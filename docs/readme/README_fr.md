# AllInOneIME

### Des commandes d'IA dans chaque champ de texte de votre Mac.

Tapez `@improve`, `@translate` ou `@question` dans n'importe quelle application, appuyez sur ⏎ et choisissez le résultat.<br>
Pas de copier-coller dans une fenêtre de chat, pas de changement d'application. Votre propre fournisseur d'IA, vos propres clés.

> [!NOTE]
> Depuis la version 0.6.3, AllInOneIME est signé avec un Developer ID et notarié par Apple : plus besoin de l'autoriser dans System Settings → Privacy & Security (Réglages Système → Confidentialité et sécurité). Après une mise à jour depuis une version antérieure, macOS demande une fois votre mot de passe de session pour chaque clé qu'AllInOneIME a enregistrée dans le trousseau : saisissez-le et cliquez sur "Always Allow" (Toujours autoriser). Téléchargez AllInOneIME uniquement depuis les [GitHub Releases](https://github.com/MicroZ-LLC/AllInOneIME/releases) ou depuis [allinoneime.com](https://allinoneime.com).

Une méthode de saisie pour macOS qui met des commandes d'IA dans chaque champ de texte. Commencez une phrase par `@` et appuyez sur ⏎ quand vous avez terminé : `@improve` peaufine ce que vous avez écrit et propose quelques reformulations, `@translate` le traduit dans les langues de votre choix, `@question` pose une question, `@agent` confie la tâche à un agent de codage (Claude Code, Gemini CLI, Kiro CLI …), et `@open` trouve des fichiers et des applications ou ouvre une adresse web. Sans `@`, vos frappes vont à l'application comme d'habitude. Elle tape aussi le chinois (pinyin, fondé sur Rime et rime-ice), le français, le coréen (hangeul) et le hindi (devanagari à partir de lettres latines), et exécute vos propres scripts comme commandes @.

La touche magique, le symbole par lequel commencent les commandes, est `@` par défaut. Dans Settings → General → Magic key, vous pouvez choisir un autre symbole : `#`, `%`, `&`, `*`, `+`, `|` ou `~` ; les commandes commencent alors par lui (par exemple `~translate`), et `@` se tape normalement. Les lettres, les chiffres, les espaces et les symboles dont la saisie a besoin (touches du pinyin comme `'` `-` `=` `[` `]` `` ` ``, et ceux que le pinyin tape en ponctuation chinoise, comme `,` `.` `?` `\`) sont refusés, et les réglages disent pourquoi. Dans le fichier de configuration : `"commandTrigger": "~"`.

## Utilisation

Sans `@`, elle se fait oublier : en anglais, les lettres sont tapées directement et ⏎ est la touche Retour ; rien ne part en ligne. Une nouvelle installation écrit en anglais ; pour taper aussi le chinois (pinyin), le français, le coréen ou le hindi, ajoutez-le dans les réglages (voir [Saisie et traduction](#saisie-et-traduction)).

| Touche | Ce qu'elle fait |
|---|---|
| Taper du pinyin, Espace / chiffres | En mode chinois : choisir les mots, comme dans toute méthode de saisie pinyin |
| `@` (en début de phrase) | Ouvre la liste des commandes : les plus utilisées récemment d'abord, 5 à la fois, défilement avec ↑↓, la molette ou le trackpad ; ou tapez des lettres pour en trouver une (d'abord le nom tapé en entier, puis les noms qui commencent par elles, puis ceux qui les contiennent). ⏎, Tab, Espace ou un chiffre la sélectionne |
| ⏎ | Exécute la commande. Fonctionne même si le pinyin n'est pas encore choisi : il est choisi d'abord, comme avec Espace |
| Espace, ⏎ / chiffres | Une fois les résultats affichés : insère celui qui est en surbrillance / numéroté ; 0 est l'original. ⏎ insère même avec une suite à moitié tapée (elle est abandonnée) |
| ⇧⏎ | Avec une suite tapée après des résultats de l'IA : l'envoie (la question suivante d'une conversation `@question`, ou un affinage). Pendant qu'une commande est tapée, ou sur des résultats de l'IA sans rien de tapé : insère ce que vous avez tapé tel quel, `@command` compris. Sur d'autres résultats (`@open`, un rappel …), insère la ligne en surbrillance, comme ⏎ |
| ⌘C | Copie le résultat en surbrillance (pour `@open`, le chemin) ; le panneau des candidats reste ouvert |
| ⌃V | Dans une commande (par ex. après `@improve `) : ajoute le texte du presse-papiers après ce que vous avez tapé au lieu de le coller dans l'application. Plusieurs lignes n'en font plus qu'une, jusqu'à 2000 caractères à la fois (`@note` conserve les retours à la ligne et en accepte jusqu'à 20000). Fonctionne dans toutes les applications ; sans commande, la touche va à l'application comme d'habitude |
| ⌘V | Comme ⌃V, mais certaines applications gèrent ⌘V elles-mêmes (des terminaux comme Ghostty, iTerm2 et Terminal, ainsi que Notes) et collent dans l'application comme d'habitude ; utilisez ⌃V dans celles-ci |
| Échap, ⌫ | Retour à la phrase pour continuer à la modifier ; taper de la ponctuation ou des chiffres après les résultats la poursuit. Après un affinage : retour aux résultats d'avant |
| Des lettres, une fois les résultats de l'IA affichés | Une suite : après `@question`, la question suivante (voir [Conversations](#conversations-avec-question-nouveau)) ; après `@improve` ou une commande d'instruction, une consigne comme `shorter` (voir [Affiner les résultats](#affiner-les-résultats-nouveau)) ; ⇧⏎ l'envoie. Après `@translate`, les lettres poursuivent la phrase, et ⏎ la traduit à nouveau |
| ⌘⏎, ⌘1–⌘9 | Dans une conversation `@question` : montre où la poursuivre (les agents de codage installés, celui auquel `@agent` confie les tâches en premier ; Claude, ChatGPT, Gemini ; ou la copier) ; ⌘1, ⌘2 … en choisissent un |
| Clic sur une ligne | Dans le panneau des candidats : la choisit, comme son chiffre le ferait (un mot, une commande de la liste, un résultat, un fichier de `@open`, un destinataire, une ligne d'extension) ; la ligne sous le pointeur est en surbrillance. Le champ de texte garde le focus |
| Appui bref sur Maj | Avec plusieurs langues de saisie : la suivante, dans leur ordre (anglais → chinois → français → …, puis retour à la première) |

## Commandes @ (bêta)

| Commande | Ce qu'elle fait |
|---|---|
| `@improve` | Peaufinage : 1–3 sont trois versions dans la langue de la phrase, à partir de 4 les styles de reformulation (ajoutés et ordonnés dans les réglages), 0 est l'original. Pas de traduction ; avec "@improve also translates" (@improve traduit aussi) activé, elle fonctionne comme `@translate @improve` |
| `@translate` | Traduit dans les langues que vous avez ajoutées (réglages → Translate, glissez pour réordonner), une ligne chacune, trois versions s'il n'y en a qu'une ; la langue de la phrase elle-même est ignorée. `@translate @improve` ensemble traduit et reformule en une seule requête |
| `@question` | Pose une question ; la réponse apparaît dans les candidats, ⏎ ou Espace l'insère, ⌘C la copie. Continuez à taper et ⇧⏎ pose une question de suivi : le panneau devient une conversation de 5 tours au plus, puis propose de la poursuivre dans Claude ou une autre IA. Sans rien tapé après, elle liste vos 5 dernières questions, les plus récentes d'abord ; taper filtre la liste (des mots n'importe où dans la question, sans tenir compte de la casse, en chinois aussi). Un chiffre, ↑↓ puis ⏎, ou un clic affiche aussitôt la réponse enregistrée d'une question, hors ligne, à insérer ou copier comme d'habitude ; ⌘R la repose alors pour obtenir une nouvelle réponse. Sans correspondance, ou si rien n'est choisi, ⏎ pose ce que vous avez tapé |
| `@reply` | Rédige trois réponses au message auquel vous répondez, dans la langue de votre interlocuteur et sur le ton de l'application (le premier style de reformulation de l'application dans Settings → Apps, sinon décontracté dans les apps de messagerie, formel dans les apps de courrier, où chaque réponse est un corps d'e-mail complet). Donnez-lui le message en le sélectionnant, en le copiant puis en appuyant sur ⌃V dans le brouillon, ou en faisant une capture d'écran (⌃⇧⌘4, ou celle de WeChat) puis en appuyant sur ⌃V ; ce que vous tapez après indique quoi répondre : `@reply politely decline`. ⌘R en rédige trois autres ; voir [Répondre](#répondre-avec-reply-nouveau) |
| `@agent` | Confie la tâche à un agent de codage sur votre Mac, choisi dans Settings → Agent : Claude Code (par défaut), Gemini CLI, Kiro CLI, ou une commande à vous (ce que vous avez tapé est ajouté comme dernier argument). Cette page indique aussi si chacun est installé et comment il démarre. Claude Code s'exécute en arrière-plan par défaut, avec une notification une fois terminé (cliquez dessus pour ouvrir la session dans Terminal et continuer), ou consultez `@tasks` ; désactivez "Runs in the background and notifies me" (s'exécute en arrière-plan et me prévient) sous Claude Code sur cette page pour l'ouvrir dans Terminal. Les autres agents s'ouvrent dans Terminal avec ce que vous avez tapé comme premier message. Chacun utilise sa propre connexion et ses propres réglages. Dans Google Chrome, elle emporte la page : l'adresse et le titre, le champ où vous avez tapé avec son formulaire ou sa section (★ marque où vous êtes), le texte sélectionné et ce qui est visible dans la fenêtre — jamais un champ de mot de passe, jamais la page entière —, si bien que `@agent why doesn't this work` dans le champ du nom d'utilisateur d'un formulaire de connexion porte sur ce champ, et `@agent why is this blocked` sur la page d'un pipeline porte sur cette page ; c'est l'agent qui en juge. Le texte de la page est transmis à l'agent tel quel, marqué comme provenant du web (et non comme des instructions de votre part). Il faut l'autorisation Accessibilité ; Chrome ne construit son arbre de la page pour elle que pendant qu'on écrit `@agent` dans Chrome, et le désactive ensuite (Settings → Agent → "@agent and @reply take the Chrome page along" (@agent et @reply emportent la page Chrome) désactive le tout). La première fois qu'elle ouvre Terminal, macOS demande si AllInOneIME peut contrôler Terminal : cliquez sur OK. (Elle s'appelait `@claude` avant la 0.6.4.) |
| `@tasks` | Liste les tâches Claude en arrière-plan (en cours / terminée / vous attend) avec leurs dernières réponses ; ⏎ en ouvre une dans Terminal, ⌘C copie la réponse |
| `@settings` | Ouvre immédiatement la fenêtre des réglages (il suffit de la choisir) |
| `@open` | Liste les fichiers, dossiers et applications correspondants pendant la frappe (Spotlight). Plusieurs mots-clés séparés par des espaces fonctionnent : chacun doit figurer dans le chemin, au moins un dans le nom (le nom d'un dossier standard vaut pour son contenu : `downloads pdf` trouve les PDF du dossier Downloads (Téléchargements)). Les applications et les dossiers standard se trouvent aussi par leur nom chinois, et une interface en chinois les affiche ainsi. Ce que vous avez ouvert avec `@open` vient en premier, puis les applications et ces dossiers, puis les fichiers récemment utilisés ou modifiés ; quand les noms trouvent deux fichiers ou moins et aucune application ni aucun de ces dossiers, les fichiers de votre dossier de départ sont aussi cherchés par contenu, ces lignes étant marquées "content" (contenu) ; quand il n'y a rien d'autre, ⏎ les liste pour que vous choisissiez au lieu d'ouvrir le premier. Avec une adresse web (`github.com`, `localhost:3000`, `https://…`), la première ligne est "open in the browser" (ouvrir dans le navigateur) et le contenu n'est pas cherché ; un fichier portant exactement ce nom (par exemple `MANIFEST.in`) vient en premier. Un texte commençant par `~/` ou `/` est un chemin : Tab le complète et entre dans les dossiers ; ⏎ ouvre, ⌘C copie le chemin |
| `@note` | Enregistre le texte dans l'app Notes, dans un dossier nommé AllInOneIME (créé s'il n'existe pas), ou là où l'indique Settings → Plugins → Notes (@note) : Notion, ou un dossier de fichiers Markdown (un coffre Obsidian ou n'importe quel dossier) ; rien n'est inséré. Le texte collé conserve ses retours à la ligne, jusqu'à 20000 caractères |
| `@reminder` | Ajoute un rappel dans l'app Rappels, dans une liste nommée AllInOneIME. Écrivez l'heure dans le texte ; elle est interprétée sur le Mac, et une ligne montre ce qui a été compris : ⏎ ou Espace l'ajoute, Échap revient à la modification. Avec une heure, il sonne à ce moment-là ; avec seulement une date, il dure toute la journée |
| `@py` | Exécute une ligne de Python (le `python3` du Mac) et insère le résultat : la valeur de la dernière expression du code, par ex. `@py 2**100`, `@py import math; math.sqrt(2)`, ou sinon ce qu'il a affiché. Non proposée sans `python3` (les outils en ligne de commande de Xcode le fournissent) |
| `@js` | Exécute une ligne de JavaScript et insère la même chose : la valeur de la dernière expression ou ce que `console.log` a affiché, par ex. `@js [1, 2, 3].map(x => x * 2)`. Elle utilise JavaScriptCore, intégré à macOS, donc rien à installer ; elle ne peut ni lire de fichiers, ni accéder au réseau, ni lancer d'autres programmes |
| `@reportissue` | Signale un problème : ouvre dans votre navigateur la page de GitHub pour un nouveau ticket (issue), avec ce que vous avez tapé après la commande comme titre, et "What happened / What you expected" (ce qui s'est passé / ce que vous attendiez) à remplir. Elle ajoute les versions de l'app et de macOS, l'architecture de votre Mac, les langues de l'interface et de saisie, les packs de langue installés, le type de fournisseur d'IA (et le modèle, s'il est public ; sinon "custom"), la touche d'action, et combien de commandes personnalisées, de plugins et d'extensions vous avez, jamais leurs noms, votre texte, vos chemins ni vos clés. ⏎ (ou votre touche d'action) affiche d'abord tout cela dans le panneau des candidats ; ⏎ à nouveau, ou un clic sur la ligne, ouvre la page, où vous le relisez et cliquez sur Submit (avec votre compte GitHub) ; Échap revient en arrière. Aussi dans le menu de saisie ("Report an Issue…") et dans Settings → About |
| `@imessage` | Envoie un iMessage : tapez un nom, un numéro de téléphone ou une adresse e-mail (un nom chinois aussi par son pinyin, complet ou par les initiales) et choisissez le destinataire dans le panneau des candidats (ceux à qui vous avez écrit récemment viennent en premier ; un numéro ou une adresse complète fonctionne aussi), puis écrivez le message (les commandes qu'il contient, comme `@stock AAPL`, s'exécutent d'abord). ⏎ affiche "Send to Alex (…): message" dans le panneau, un second ⏎ l'envoie, Échap revient à la modification ; rien n'est tapé dans le champ de texte. La première fois, macOS demande si AllInOneIME peut accéder à Contacts et contrôler Messages : cliquez sur OK pour les deux |

Exemple : `@q` ⏎, tapez `what is quantum computing`, ⏎. `@note books to read: The Three-Body Problem` ⏎ enregistre une note. `@reminder call Bob tomorrow at 3pm` ⏎, vérifiez l'heure comprise, puis ⏎ à nouveau pour l'ajouter. En mode chinois, `@open` passe momentanément aux lettres latines et revient au chinois quand vous avez fini.

Le code de `@py` et `@js` se tape en lettres latines, et la ponctuation pleine chasse (du mode chinois) devient ASCII ; écrivez-le sur une seule ligne, avec `;` entre les instructions. Il s'exécute dans un processus séparé, arrêté au bout de 10 secondes ou à tout moment avec Échap ; en cas d'erreur, la première ligne de l'erreur s'affiche, par ex. `ZeroDivisionError: division by zero`. Une sortie de plusieurs lignes est insérée telle qu'affichée ; dans un terminal, elle est insérée sur une seule ligne (un terminal exécute chaque ligne qu'on lui donne). Un terminal intégré à un éditeur (VS Code, Cursor, JetBrains) ne se distingue pas de l'éditeur lui-même, donc là, la sortie de plusieurs lignes de n'importe quelle commande est insérée telle quelle. Les deux fonctionnent aussi dans la phrase d'une autre commande : `@reply the answer is @py 2**100` ; mettez entre guillemets le code contenant des espaces : `@question explain @py "sum(x * x for x in range(10))"`. L'inverse n'est pas vrai : le code de `@py` et `@js` s'exécute toujours exactement comme vous l'avez tapé, et les `@commands` qu'il contient ne s'exécutent pas d'abord.

Quand `@` n'est pas suivi d'une commande, comme dans `@john`, le `@` est inséré comme d'habitude, donc mentionner des personnes avec @ dans les applications de messagerie fonctionne toujours. Tapé juste après une lettre, un chiffre, `.`, `_` ou `-`, comme dans `bob@example.com` ou `ssh user@host`, le `@` n'est que du texte : aucune liste ne s'ouvre, dans aucune application, terminaux compris. Quand la liste est ouverte, ← → ou une touche qui ne peut pas faire partie d'un nom de commande (`.`, `:`, `/`) la ferment et laissent ce que vous avez tapé (`@`, `@im`) tel quel ; dans un terminal, ← → ne font alors que fermer la liste. `@question`, `@improve`, `@translate` et `@reply` n'envoient à votre propre Bedrock que lorsque vous appuyez sur la touche d'action (une capture d'écran est lue sur ce Mac et seul son texte est envoyé) ; `@open` ne cherche que sur ce Mac ; `@note` et `@reminder` ne vont qu'à Notes et Rappels sur ce Mac (`@note` vers un dossier ou vers Notion à la place, si vous en avez choisi un) ; `@agent` utilise l'agent installé sur votre Mac (par défaut la commande `claude` de Claude Code) et son propre compte, et il vous demande d'abord, comme d'habitude, avant de modifier des fichiers ou d'exécuter des commandes. Sans l'agent installé, `@agent` n'est pas proposée. `@imessage` ne lit que les Contacts de ce Mac (noms, numéros de téléphone, adresses e-mail), ne passe jamais par l'IA, et c'est Messages qui envoie le message ; sans l'app Messages, elle n'est pas proposée.

### Sur le texte sélectionné (nouveau)

Sélectionnez du texte dans n'importe quelle application (une phrase dans Notes, un paragraphe dans Mail), tapez `@improve`, `@translate`, `@question` ou une autre commande qui prend du texte, et appuyez sur ⏎ : la commande travaille sur la sélection, et le résultat que vous choisissez la remplace. La sélection reste telle quelle, sélectionnée, pendant que vous tapez : la commande s'écrit dans le panneau des candidats, dont la première ligne est ce que vous tapez et la suivante "On the selection: “…” (N characters)" (sur la sélection : N caractères). Échap, ⇧⏎ ou un clic ailleurs laissent le texte tel qu'il était ; de même si vous changez la sélection entre-temps, ce qui annule la commande. Le texte tapé après la commande est une consigne pour `@improve` et `@translate` (`@translate ja`, `@improve more formal`) et la question pour `@question` (`@question what does this mean`), à propos de la sélection. `@open`, `@agent`, `@tasks`, `@settings`, `@reminder`, `@imessage`, `@reportissue`, les commandes de terminal et les extensions par script ne l'utilisent pas : elles prennent ce que vous tapez, et la sélection reste telle quelle. Jusqu'à 5000 caractères ; jamais lue pendant une saisie sécurisée ni dans un terminal. Désactivez-la sous Settings → General → "Use the selected text" (utiliser le texte sélectionné) si elle se comporte mal dans une application.

### Répondre avec @reply (nouveau)

`@reply` rédige trois réponses que vous pourriez envoyer au message auquel vous répondez. Donnez-lui le message de l'une de ces façons, puis appuyez sur ⏎ :

- **Sélectionnez-le** dans le champ, puis tapez `@reply` (la réponse que vous choisissez s'insère après lui, sur une ligne à part).
- **Copiez-le**, tapez `@reply` et appuyez sur ⌃V : le panneau affiche "Copied message · N characters" (message copié · N caractères), et le brouillon reste tel quel.
- **Faites une capture d'écran** dans le presse-papiers (⌃⇧⌘4, ou la capture d'écran de WeChat), tapez `@reply` et appuyez sur ⌃V : le panneau affiche "Screenshot · N lines (read on this Mac)" (capture d'écran · N lignes, lue sur ce Mac). La capture est lue sur ce Mac (par Vision d'Apple, un peu plus lentement la première fois) et seul son texte est envoyé ; l'image ne va nulle part et n'est pas conservée. Les lignes de gauche sont celles de votre interlocuteur et celles de droite les vôtres, comme les affichent les apps de messagerie ; les heures entre les messages sont laissées de côté. Servez-vous-en pour WeChat, dont la fenêtre ne peut pas être lue autrement.

Tapez ce que vous voulez dire après (`@reply politely decline`, `@reply 委婉拒绝`), ou rien pour une réponse appropriée. Les réponses sont dans la langue de votre interlocuteur, sauf si vous en demandez une autre, et sur le ton de l'application : le premier style de reformulation de son profil (Settings → Apps), sinon décontracté dans les apps de messagerie et formel dans les apps de courrier, où chaque réponse est un corps d'e-mail complet. Le texte autour du curseur est aussi transmis. ⌫ sans rien de tapé après `@reply` retire ce qui a été collé. ⏎ ou un chiffre insère une réponse ; ⌘R en rédige trois autres (Échap ramène les précédentes), et taper une consigne les affine comme pour tout résultat de l'IA. Dans Google Chrome, sans rien de sélectionné ni de collé, elle emporte la page comme `@agent` (Settings → Agent → "@agent and @reply take the Chrome page along"). Sans rien à quoi répondre ni rien de tapé, elle indique ce qu'il lui faut. Le masquage des informations sensibles couvre aussi le texte de la capture ; pendant une saisie sécurisée, le presse-papiers n'est pas lu et rien n'est envoyé. Une commande personnalisée que vous aviez nommée `reply` s'appelle désormais `@myreply`.

Une capture d'écran collée dans n'importe quelle autre commande fonctionne aussi : `@translate` ⌃V la traduit (à l'emplacement du curseur), `@question what does this say` ⌃V pose une question à son sujet, et les commandes sans IA reçoivent son texte comme s'il avait été copié (`@note` conserve ses lignes). Avec du texte sélectionné, `@improve` et `@translate` continuent de travailler sur la sélection, et une notification indique que la capture d'écran n'a pas été utilisée.

### Affiner les résultats (nouveau)

Pendant que les résultats de `@improve`, d'une commande d'instruction (la vôtre ou celle d'un plugin) ou de la reformulation d'une sélection sont affichés, tapez ce qu'il faut changer, comme `shorter`, `warmer`, `more formal`, `add a joke`, `in Japanese` ou `用更口语的说法` (le pinyin fonctionne, et un appui bref sur Maj change de langue), et appuyez sur ⇧⏎ : les résultats repartent vers l'IA avec votre consigne, et les nouveaux les remplacent dans le même panneau. ⏎ insère le résultat sélectionné, même avec une consigne à moitié tapée (elle est abandonnée). Affinez autant de fois que vous voulez ; la ligne du haut du panneau liste les étapes ("Refined: shorter · more formal"), et vous pouvez choisir une ligne à tout moment comme d'habitude. Une lettre commence la consigne (affichée comme "refine › …" en haut du panneau) ; tant qu'elle est vide, les chiffres, Espace et ⏎ choisissent comme avant, et ⇧⏎ insère ce que vous avez tapé tel quel. L'affinage commence une fois les résultats complets : taper pendant que les premiers résultats arrivent encore poursuit la phrase, comme avant. Pendant qu'un affinage s'exécute, vous pouvez déjà taper la consigne suivante ; l'affinage continue, et ⇧⏎ lance le suivant une fois ses résultats arrivés. Échap efface la consigne, puis revient d'une étape aux résultats d'avant le dernier affinage (pendant un affinage : l'arrête), puis à la phrase ; ⌫ sur une ligne vide revient en arrière de la même façon. Sur du texte sélectionné, le résultat choisi remplace toujours exactement la sélection, qui reste intacte jusque-là. Un affinage qui échoue (ou qui est refusé pendant une saisie sécurisée) laisse les résultats tels quels, sa consigne prête pour réessayer avec ⇧⏎. Le même affinage des mêmes résultats est servi depuis le cache. `@translate` n'a pas d'affinage : taper après ses résultats poursuit la phrase, et ⏎ la traduit à nouveau.

### Conversations avec @question (nouveau)

Une fois que `@question` a répondu, ce que vous tapez est la question suivante : ⇧⏎ la pose, avec les questions et les réponses précédentes, et le panneau devient la conversation, les tours précédents estompés sous forme de lignes Q / A, la dernière réponse en dessous. La ligne du haut indique quel tour vient ensuite ("question 2/5 › …"). Chaque réponse peut être insérée : son chiffre (1–5), ↑↓ puis ⏎, ou un clic ; la dernière est sélectionnée, et ⌘C copie celle qui est sélectionnée. ⏎ l'insère même avec une question à moitié tapée (elle est abandonnée). Échap efface ce que vous avez tapé, puis revient d'un tour ; au premier, il quitte comme avant. Le panneau s'agrandit jusqu'à environ la moitié de l'écran, puis défile, la dernière réponse en bas.

Après 5 tours (`questionRounds` dans la configuration, 2–10), la ligne de la question suivante devient "5 rounds in: continue in Claude or another AI" (5 tours : poursuivre dans Claude ou une autre IA), avec les choix numérotés ⌘1, ⌘2 … ; ⌘⏎ les affiche à n'importe quel tour (tant qu'une réponse arrive encore, il ne fait rien et n'atteint jamais l'application). Ce que vous tapez alors est le premier message envoyé là-bas ; seuls ⌘1, ⌘2 … l'envoient (⇧⏎ ne pose plus de question et n'ouvre rien). Une question sur du texte sélectionné emporte ce texte, cité dans un bloc à part. Les choix :

- **Les agents de codage installés** sur ce Mac, chacun sous son nom : celui auquel `@agent` confie les tâches en premier (⌘1), puis les autres (Claude Code, Gemini CLI, Kiro CLI, votre propre commande définie dans Settings → Agent). Chacun ouvre une session interactive dans Terminal, démarrée comme `@agent` la démarre, qui commence par la conversation et "Let's continue this discussion". Un agent qui n'est pas installé n'apparaît pas.
- **Claude** ou **ChatGPT** sur le web, la conversation déjà remplie (une longue conversation va dans le presse-papiers : collez-la).
- **Gemini** sur le web, la conversation dans le presse-papiers, à coller.
- **Copy the conversation** (copier la conversation), en Markdown (**Q:** / **A:**).

Lesquels, et dans quel ordre (le premier est celui par défaut) : Settings → General → "Continue a conversation in" (poursuivre une conversation dans ; `questionContinueIn` dans la configuration) ; au-delà de 5, ⌘6 … ⌘9 choisissent les suivants. "@agent's agent" (l'agent de @agent) y désigne l'agent choisi dans Settings → Agent, sous son nom ; un agent qui n'est pas installé pour l'instant garde sa place dans la liste quand vous la modifiez. Avec Apple Intelligence sur ce Mac, une longue conversation ne tient pas dans son petit contexte : les réponses les plus anciennes sont raccourcies, puis les tours les plus anciens laissés de côté, et le panneau indique "earlier rounds shortened" (tours précédents raccourcis). Une conversation est enregistrée sous sa première question dans les questions récentes, et la choisir affiche ses tours pour la poursuivre.

### Questions récentes (nouveau)

`@question` sans rien tapé après liste vos 5 dernières questions, les plus récentes d'abord, avec le moment où elles ont été posées ("3 hours ago"). Taper filtre la liste : chaque mot n'importe où dans la question, sans tenir compte de la casse (le chinois sans espaces aussi). Un chiffre, ↑↓ puis ⏎, ou un clic affiche aussitôt la réponse enregistrée d'une question, sans aller en ligne : Espace ou ⏎ l'insère, ⌘C la copie, ⌘R la repose pour une nouvelle réponse (pour une conversation : sa dernière question), Échap revient à la liste. Une conversation enregistrée affiche tous ses tours : tapez pour la poursuivre. Sans correspondance, ou si rien n'est choisi, ⏎ pose ce que vous avez tapé. Une nouvelle réponse à la même question, ou une conversation qui se poursuit, remplace celle enregistrée.

- Elles ne sont conservées que sur ce Mac (voir Confidentialité) : pas pendant une saisie sécurisée, et jamais pour les questions sur du texte sélectionné.
- Settings → General → "Remember recent questions" (mémoriser les questions récentes) désactive la fonction (`rememberQuestions` dans la configuration) ; désactivée à cet endroit, elle supprime aussi les questions. Désactivée depuis Settings → Assistant, elle les conserve, pour qu'une annulation remette exactement ce qui était (son aperçu l'indique) ; "Clear (N)" (effacer) les supprime.

### Notes et rappels

`@note` crée une nouvelle note ; sa première ligne en est le titre. Après avoir copié du texte, ⌃V après `@note ` (ou ⌘V, hors des terminaux) l'enregistre avec ses retours à la ligne, affichés sous forme de ↵ dans la commande. L'endroit où elle va se règle dans Settings → Plugins → Notes (@note) → Save to (enregistrer dans) :

- **Notes** (comme avant) : une nouvelle note dans le dossier AllInOneIME.
- **Folder (Obsidian or any)** (dossier, Obsidian ou autre) : un nouveau fichier Markdown par note dans le dossier que vous choisissez, nommé d'après sa première ligne (`/\:*?"<>|#^[]` deviennent `-` ; un nom déjà pris reçoit " 2", " 3"). Le fichier contient un en-tête (front matter) `created:`, puis le texte entier tel que tapé. Un fichier n'est jamais écrasé, et un dossier absent (un disque non monté, un coffre déplacé) n'est pas créé : la note revient à la place. Dans un coffre Obsidian (un dossier `.obsidian` dedans ou au-dessus), la notification indique "Saved to Obsidian" (enregistrée dans Obsidian), et le panneau de la barre des menus ouvre la note dans Obsidian.
- **Notion** : Create Integration… (créer une intégration : New integration → Internal → copiez le jeton), collez le jeton (conservé dans le trousseau), puis dans Notion ouvrez la page ou la base de données → ··· → Connections (Connexions) → ajoutez votre intégration, et collez son lien ; Test affiche "✓ “Inbox” (database)". Une page reçoit une nouvelle sous-page, une base de données une nouvelle ligne (avec la première ligne comme titre) ; le reste de la note en est le corps, en une seule requête. Hors ligne ou en cas de refus, rien n'est gardé pour un envoi ultérieur : la note revient. Pendant une saisie sécurisée, `@note` n'envoie rien à Notion.

La notification indique où la note est allée ("Saved to Notion", "Saved to “Inbox”"). Si vous quittez le champ de texte (clic ailleurs, changement d'application) ou appuyez sur ⇧⏎ (insérer tel quel) avant qu'une note contenant des retours à la ligne soit enregistrée, elle n'est pas tapée dans l'application (dans un terminal, chaque ligne s'exécuterait comme une commande) : elle va dans le presse-papiers à la place ("The note wasn't saved; its text is on the clipboard"). Une note d'une seule ligne est insérée telle quelle.

`@reminder` comprend des expressions de temps comme `tomorrow at 3pm`, `in 2 hours`, `in 3 days at 3pm`, `on the 15th`, `this weekend`, `in 1 month`, `next month` (le 1er du mois), `end of the year` (ainsi que des expressions en chinois). Le jour et l'heure peuvent être séparés (`tomorrow call Bob at 5`) ; les semaines commencent le lundi. Une heure sans am ni pm (`at 5`) désigne la prochaine occurrence, jamais entre minuit et 6 h ; une heure déjà passée aujourd'hui désigne demain, mais une partie de la journée encore en cours (`this afternoon`, `tonight`) désigne aujourd'hui, toute la journée ; une date déjà passée cette année désigne celle de l'année prochaine. Un rappel écrit pour se répéter (`standup every Monday at 9`) est ajouté une seule fois, pour la prochaine occurrence : les mots restent dans le titre et la ligne indique "once only" (une seule fois). La ligne de confirmation montre l'heure comprise, par ex. "tomorrow 3:00 PM" (selon le réglage 12/24 heures du Mac) ; si elle est fausse, Échap revient au texte. S'il ne contient ni heure ni date, le rappel n'en a pas ("no date").

`@stock` et les commandes similaires à l'intérieur de ces deux-là ne s'exécutent pas : le texte est enregistré tel qu'écrit (taper `@` à cet endroit n'ouvre pas la liste des commandes). La première fois, macOS demande si AllInOneIME peut contrôler Notes (`@note`) ou accéder à Rappels (`@reminder`) : autorisez-le. Si vous ne l'avez pas fait, autorisez AllInOneIME dans Réglages Système → Confidentialité et sécurité → Automatisation (Notes) ou → Rappels. Quand un enregistrement échoue (faute d'autorisation, par exemple), la notification en indique la raison et le texte revient dans la commande, pour le corriger et le renvoyer ; quand vous devez d'abord corriger quelque chose (une autorisation, un compte), il est aussi mis dans le presse-papiers (aller dans Réglages Système retire le focus du champ de texte). Si vous êtes passé à un autre champ de texte ou tapez autre chose, il va dans le presse-papiers à la place ("Not saved; the text is on the clipboard.").

### Vos propres commandes

Dans les réglages, sous "Custom @ Commands" (commandes @ personnalisées), cliquez sur "Add Command…" (ajouter une commande) : donnez-lui un nom et choisissez ce qu'elle fait (une instruction pour l'IA, un programme, un programme dans Terminal, une page web, ou un texte à insérer), ou partez d'un exemple. Vos commandes viennent après celles intégrées ; les noms ne contiennent que des lettres latines et ne peuvent pas reprendre le nom d'une commande intégrée ; elles fonctionnent à partir de la phrase suivante. Elles sont conservées dans `customCommands` dans le fichier de configuration (`~/.config/allinoneime/config.json`), que vous pouvez aussi modifier :

```json
"customCommands": [
  { "name": "python", "type": "run", "argv": ["python3", "-c", "{input}"], "summary": "Run Python" },
  { "name": "bc", "type": "run", "argv": ["bc", "-l"], "stdin": "{input}\n" },
  { "name": "sh", "type": "terminal", "argv": ["zsh", "-c", "{input}"] },
  { "name": "reply", "type": "prompt", "prompt": "Write a short, polite reply to the user's message." },
  { "name": "google", "type": "link", "url": "https://www.google.com/search?q={input}" },
  { "name": "sig", "type": "snippet", "summary": "Email signature", "text": "Best,\nWei\n{cursor}" }
]
```

| `type` | Ce qu'elle fait |
|---|---|
| `prompt` | Envoie à l'IA avec `prompt` comme instruction ; la réponse apparaît dans les candidats, à insérer ou copier (⌘C) |
| `run` | Exécute `argv` en arrière-plan ; ce qu'il affiche apparaît dans les candidats (plusieurs lignes sont insérées telles qu'affichées, dans un terminal sur une seule ligne). En cas d'erreur, sa dernière ligne s'affiche |
| `terminal` | Exécute `argv` dans une nouvelle fenêtre de Terminal ; rien n'est inséré |
| `link` | Place le texte dans l'adresse web `url` et l'ouvre dans le navigateur par défaut ; rien n'est inséré |
| `snippet` | Insère `text` aussitôt, ses espaces réservés remplis (voir plus bas) ; ni IA, ni programme |

- `{input}` devient ce que vous avez écrit après la commande, et reste toujours dans l'unique argument où il se trouve : aucun shell n'intervient. Pour un shell, dites-le explicitement, comme `sh` ci-dessus (`zsh -c`).
- `stdin` : ce qui est envoyé sur l'entrée standard du programme, `{input}` y étant aussi remplacé.
- L'`url` d'un `link` doit commencer par `https://`, avec `{input}` une seule fois, après le `?` ou le `#` ; le texte est encodé (une espace devient `%20`, un retour à la ligne `%0A`), 4000 caractères au plus.
- `run` et `terminal` tapent en lettres latines par défaut (comme `@open` ; en mode chinois, le chinois revient ensuite), et la ponctuation pleine chasse devient ASCII. Définissez `"ascii": false` pour garder le texte tel que tapé.
- Les programmes s'exécutent dans votre dossier de départ avec le PATH de votre shell de connexion (les installations Homebrew, pyenv et nvm sont donc trouvées). `run` arrête un programme au bout de 10 secondes (`timeoutSeconds`) ou quand il affiche trop de choses ; Échap l'arrête à tout moment.
- `summary` est la description dans la liste des commandes (facultative).
- Quand le programme indiqué dans `argv` est introuvable (par exemple, pas de `python3`), la commande n'est pas proposée et `@python …` est inséré comme du texte ; une fois le programme installé, la commande apparaît dans le champ de texte suivant.

`run` et `terminal` exécutent du code sur votre Mac : n'ajoutez que des commandes que vous avez écrites et en lesquelles vous avez confiance. Elles aussi ne s'exécutent que lorsque vous appuyez sur la touche d'action, et jamais pendant une saisie sécurisée.

#### Extraits de texte : ce que vous insérez souvent (nouveau)

Une commande `snippet` ("Insert text" dans l'éditeur, insérer du texte) insère un texte que vous avez enregistré, comme une signature, une adresse ou un lien de réunion : `@sig` ⏎ l'insère aussitôt (Tab ou Espace ne font que compléter le nom). Son `text` peut contenir des espaces réservés :

| Espace réservé | Devient |
|---|---|
| `{input}` | tout ce que vous avez écrit après le nom : `@tag foo bar` avec `#{input}` insère `#foo bar` |
| `{name?}` | un champ à remplir, rempli avec ce que vous avez écrit, séparé par des virgules (`,` ou `，`), dans l'ordre : `Dear {name?}, see you {day?}.` avec `@meet Bob, Friday`. Un champ laissé vide est nommé dans une notification, et rien n'est inséré |
| `{clipboard}` | le texte du presse-papiers (macOS peut demander d'abord) |
| `{selection}` | le texte sélectionné quand vous avez tapé `@` (il est remplacé, comme par toute commande sur la sélection) |
| `{date}`, `{time}` | la date du jour sous la forme `2026-10-17`, l'heure sous la forme `14:05` ; `{date:EEEE, MMM d}` avec un [modèle de date](https://unicode.org/reports/tr35/tr35-dates.html#Date_Field_Symbol_Table), dans la langue de l'interface |
| `{cursor}` | l'endroit où va le curseur une fois le texte inséré (une fois au plus ; pas dans un terminal) |

- `{{` écrit `{`, et le `}}` qui le ferme écrit `}` (`{{input}}` insère `{input}`) ; tout autre `}}` ou `{…}` reste tel quel, donc du JSON ou du code dans un extrait ne pose pas de problème : `{"a":{"b":1}}` est inséré tel qu'écrit.
- Sans `{input}` ni champ à remplir, ce que vous écrivez après le nom est inséré après l'extrait, précédé d'une espace.
- Écrivez `@sig` dans le texte d'une autre commande pour l'y inclure : `@question summarize this @zoom` envoie le lien lui-même. Seuls les extraits sans `{clipboard}`, `{selection}` ni champ à remplir fonctionnent là ; avec `{input}`, celui-ci est un mot ou une expression entre guillemets : `@meet「Friday 3pm」`.
- Texte brut uniquement (retours à la ligne conservés), 20 000 caractères au plus. Les extraits restent sur ce Mac, donc ils fonctionnent pendant une saisie sécurisée et dans les applications réglées sur No AI. Les bundles d'extensions peuvent aussi en fournir (`snippets` dans `extension.json`, voir [docs/extensions.md](../extensions.md)).

### Extensions par script

Ajoutez vos propres commandes @ sous forme de programmes : un script dans n'importe quel langage (bash, Python, Node, Swift, …) avec quelques lignes de métadonnées dans ses commentaires. Placez-le dans `~/.config/allinoneime/extensions`, ou dans un dossier que vous ajoutez sous Settings → Custom Commands → Script Extensions. Les Script Commands de Raycast fonctionnent telles quelles, et les dossiers qui en contiennent déjà sont trouvés avec Spotlight.

```bash
#!/bin/bash
# @allinoneime.schemaVersion 1
# @allinoneime.title Flights
# @allinoneime.argument1 {"type": "text", "placeholder": "from city"}
# @allinoneime.argument2 {"type": "text", "placeholder": "to city"}

echo "Flights from $1 to $2"
```

`flights.sh` devient `@flights`. Écrivez ses arguments après, séparés par des virgules : `@flights beijing, new york` l'exécute avec `beijing` et `new york` comme `$1` et `$2` (les virgules en trop restent dans le dernier) ; un argument obligatoire laissé vide indique ce qui manque au lieu de lancer le script. Ce qu'il affiche est utilisé selon son `output` :

| `output` | Ce qui se passe |
|---|---|
| `insert` (par défaut) | Tout, et chaque ligne, à insérer |
| `show` | Affiché dans le panneau au fil de l'exécution (progression) ; rien n'est inséré. Quittez le champ et il continue en arrière-plan (jusqu'à quatre à la fois) |
| `list` | Une liste au format JSON Script Filter d'Alfred, réexécutée pendant la frappe ; choisir une ligne insère, ouvre (une adresse web, un fichier ou un dossier ; jamais quelque chose qui s'exécuterait), copie ou lance une deuxième étape |
| `silent` | Sa dernière ligne près du curseur ; rien n'est inséré |

Une commande peut aussi ne prendre aucune entrée (`input none` : ⏎ sur son nom l'exécute), s'exécuter en arrière-plan (`background`) et vous prévenir quand elle a terminé (le panneau de la barre des menus la liste entre-temps), afficher un `status` à côté de son nom dans la liste des commandes, ou demander confirmation d'abord (`confirm`). Elle s'exécute dans son propre dossier avec le PATH de votre shell de connexion et des variables `ALLINONEIME_*` : la langue de l'interface et de saisie, l'application dans laquelle vous tapez, le texte. Un **bundle** est un dossier avec un `extension.json` qui nomme ses commandes : elles partagent du code et des préférences, que les réglages affichent (les mots de passe vont dans le trousseau). Les réglages listent chaque commande avec un interrupteur, ainsi que les scripts écartés et la raison.

Les modes de Raycast se transposent ainsi : `fullOutput` → `show`, `compact` et `silent` → `silent`, `inline` avec `refreshTime` → un statut. Le protocole complet se trouve dans [docs/extensions.md](../extensions.md) ; [Core/Examples/extensions](../../Core/Examples/extensions) en contient un de chaque sorte. Les extensions exécutent du code sur votre Mac : utilisez celles en lesquelles vous avez confiance. Elles ne s'exécutent que lorsque vous les lancez (un statut ou une liste pendant la frappe), jamais pendant une saisie sécurisée, et s'arrêtent quand la méthode de saisie se ferme.

#### Sources d'extensions (nouveau)

Un bundle peut provenir d'un dépôt Git, le vôtre ou celui de votre équipe, et rester à jour à partir de là. Settings → Custom Commands → Extension Sources → **Add from Link…** (ajouter depuis un lien) : collez l'adresse du dépôt (`git@github.com:you/my-extensions.git`, `ssh://…`, `https://…` ; éventuellement une branche, le dossier du bundle dans le dépôt, et une étiquette (tag) ou un commit auquel l'épingler). AllInOneIME le clone avec **votre propre configuration git et SSH** (clés, agent, ~/.ssh/config, assistants d'identification), si bien qu'un dépôt privé fonctionne comme dans Terminal ; l'application ne demande ni ne stocke jamais de mot de passe. Le clone va dans `~/Library/Application Support/AllInOneIME/Sources/` : d'abord dans un dossier de préparation masqué, jamais directement dans un dossier d'extensions. (Ne mettez ni nom, ni mot de passe, ni jeton dans une adresse https : l'assistant d'identification de git les conserve.)

- **D'abord l'examen.** Avant que quoi que ce soit ne se charge, vous voyez le bundle, chaque commande (nom, titre, description, sortie), les programmes qu'elles exécutent, ses préférences et le commit, sous l'avertissement "This source isn't signed: it will run programs from <address>" (cette source n'est pas signée : elle exécutera des programmes provenant de cette adresse). Seul **Enable** (activer) l'ajoute ; Cancel (annuler) supprime le clone. Vous n'examinez une source qu'une seule fois.
- **C'est vous qui appliquez les mises à jour.** Une fois par jour (et peu après le démarrage de la méthode de saisie), une source est récupérée (fetch) pour voir ce qu'il y a de nouveau : les réglages affichent "N updates" (N mises à jour) avec les commits (sujet, auteur, date) et un badge sur la page. Rien ne change tant que vous ne cliquez pas sur **Update** (mettre à jour), qui ne fait qu'une avance rapide (fast-forward) et n'exécute aucun hook. Après un push forcé, la source doit être examinée de nouveau : **Re-clone** (recloner) la montre, et seul Enable met en place l'historique réécrit (d'ici là, la version examinée continue de fonctionner). Une source épinglée à une étiquette ou à un commit n'est pas vérifiée. La vérification quotidienne se désactive source par source (`autoCheck`).
- **Les erreurs** sont les propres mots de git, avec "This uses your own git and SSH setup; check that `git ls-remote <url>` works in Terminal" (ceci utilise votre propre configuration git et SSH ; vérifiez que cette commande fonctionne dans Terminal), et en dessous votre propre rappel si vous en avez défini un (`authHint` dans la configuration).
- **Remove** (supprimer) met le clone à la corbeille ; les préférences du bundle sont conservées pour la prochaine fois.
- Depuis un terminal : `AllInOneIME --add-source <url> [--path …] [--branch …] [--pin …]` (affiche l'examen et active la source ; à refaire après un push forcé), `--update-sources` (avance rapide de chaque source examinée qui n'est pas épinglée), `--list-extensions` (sur `~/Library/Input Methods/AllInOneIME.app/Contents/MacOS/AllInOneIME`).
- Seul le code examiné se charge : un dossier de source présent dans la liste de chargement mais qui n'a pas été examiné sur ce Mac (une configuration copiée) est laissé de côté. git n'attend jamais de réponse : pas de terminal ni d'invite, donc une clé d'hôte inconnue ou une demande de mot de passe échoue aussitôt.

La configuration les conserve sous `extensionSources` ; l'organisation du dépôt est décrite dans [docs/extensions.md](../extensions.md#10-extension-sources).

### Plugins

Les plugins sont des commandes `@` prêtes à l'emploi pour des usages dont tout le monde n'a pas besoin, comme `@stock AAPL 600519 700` pour des cours de bourse. Une fois installés, ils fonctionnent comme n'importe quelle commande ; "Plugins" dans les réglages montre ce qui est installé et où chacun envoie votre texte, et permet de les supprimer. Les plugins sont du JavaScript exécuté dans un processus séparé : ils ne peuvent joindre que les sites web qu'ils déclarent (HTTPS), et ne peuvent ni lire de fichiers ni lancer d'autres programmes. "Browse Library…" (parcourir la bibliothèque) sous Plugins dans les réglages les installe depuis la [bibliothèque de plugins](https://github.com/MicroZ-LLC/AllInOneIME-plugins) : elle montre quels sites web un plugin contacte avant de l'installer ; l'index de la bibliothèque est signé et chaque fichier doit lui correspondre. Une version plus récente fait apparaître un bouton "Update" (mettre à jour) ; rien ne se met à jour tout seul. Vos propres plugins vont dans `~/.config/allinoneime/plugins/` ("Open Plugins Folder") : des plugins locaux, jamais écrasés par la bibliothèque. Les plugins de type "Link" n'exécutent aucun code : ils placent le texte dans une adresse web et l'ouvrent dans le navigateur, comme `@x nice weather today`, qui ouvre l'éditeur de publication de X avec le texte déjà rempli ; c'est à vous de publier sur la page. La bibliothèque en compte quatre (`@x`, `@threads`, `@bsky`, `@weibo`). `@xe` convertit les devises : `@xe 100 USD CNY`, `@xe 1000 JPY EUR`, sur une ligne avec la date du taux (taux fournis par ExchangeRate-API). `@calculator` est une calculatrice qui fonctionne hors ligne, `@calculator 23*17` → `391` (le `@calculate` intégré avant la 0.6.5), et `@calendar` gère les dates : `@calendar +10` → "Tue, Oct 27 · in 10 days". Pour en écrire un : [docs/plugins.md](../plugins.md).

Les commandes qui récupèrent quelque chose (plugins et programmes) fonctionnent aussi au milieu d'une phrase : `@reply tell her @stock AAPL is up today`. Les commandes intérieures s'exécutent d'abord, leur sortie prend leur place, et la commande extérieure travaille sur le résultat. L'argument est le mot qui suit la commande, plus les codes en majuscules ou les nombres qui le suivent immédiatement (`@stock AAPL TSLA`, `@stock 600519 700`) ; un mot en minuscules y met fin (`@stock SNDK is good to buy` recherche SNDK). Les guillemets le délimitent exactement : `@stock "aapl tsla"`. Le plugin `@calculator` y fonctionne aussi : `@reply the total is @calculator 23*17 dollars`. À l'intérieur de `@agent` et des commandes de terminal, elles ne s'exécutent pas : celles-ci reçoivent le texte tel qu'écrit (taper `@` à cet endroit n'ouvre pas la liste des commandes).

### Touche d'action

⏎ par défaut ; modifiez-la sous "Action key" (touche d'action) dans les réglages (`actionKey` dans la configuration) : ⏎, Tap ⌥ (appui bref sur ⌥, d'un côté ou de l'autre : appuyer et relâcher aussitôt), ⌥Espace, ou Espace (appuyez encore une fois sur Espace après avoir choisi les mots ; deux fois en mode anglais). Quelle que soit la touche d'action, les commandes @ s'exécutent aussi avec ⏎. Si ⌥Espace est déjà un raccourci pour Alfred, Raycast ou un outil similaire, ceux-ci le reçoivent en premier.

### Taper les résultats

Activez "Type results out" (taper les résultats) sous Settings → General (`typeOut` dans la configuration) et le résultat d'une commande est tapé dans l'application caractère par caractère, comme le ferait une personne, au lieu d'arriver d'un coup ; les mots choisis en pinyin arrivent toujours d'un coup. Le curseur règle le rythme, de 6 secondes par caractère à 40 par seconde (`typeOutRate`), et "Speed up and slow down (like a person)" (accélérer et ralentir, comme une personne) tape par rafales de rythme variable (`typeOutVaries`). Échap l'arrête là où il en est ; toute autre touche tape le reste d'un coup.

"Make occasional typos and fix them" (faire de temps en temps des fautes de frappe et les corriger, `typeOutMistakes`) rend l'effet encore plus humain : de temps en temps la touche voisine de la bonne, remarquée jusqu'à trois lettres plus tard, effacée et retapée ; une lettre ou une espace tapée deux fois puis effacée ; ou un mot court tapé, effacé et retapé. Quelques-unes pour 100 caractères, jamais deux rapprochées, et jamais en début de ligne. Dans du code, des adresses web et e-mail et des nombres, une faute n'est qu'une mauvaise lettre ou un mauvais chiffre, corrigé aussitôt (jamais une mauvaise parenthèse, un guillemet ou une espace, sur lesquels les éditeurs apparient ou indentent). Les mauvaises lettres sont des voisines sur votre disposition de clavier (QWERTY, AZERTY, QWERTZ…). Le chinois, le japonais et le coréen ne font qu'hésiter (deux caractères tapés, effacés et retapés), jamais avec un mauvais caractère.

Dans un champ qui accepte qu'on revienne sur une faute (les vues de texte d'Apple comme TextEdit et Notes, les navigateurs, la plupart des éditeurs) : tapé jusqu'au bout, ou avec une autre touche pressée pour taper le reste d'un coup, le texte est exactement le résultat ; Échap (ou quitter le champ) au milieu d'une faute retire d'abord la faute, si bien que le champ contient un début exact du résultat. Si le curseur bouge pendant qu'une faute est affichée (un clic), la faute est retirée là où elle était et le reste est tapé sans fautes.

Il n'y a jamais de fautes dans les terminaux, ni dans les applications qui n'indiquent pas à la méthode de saisie où se trouve le curseur. À chaque fois, la première faute est une faute simple (une mauvaise lettre, corrigée en une fois), jusqu'à ce que le champ ait montré qu'il accepte qu'on revienne sur une faute ; tant qu'une faute est affichée, la méthode de saisie vérifie avant chaque touche que le champ contient ce qu'elle a tapé. Un champ qui ignore où remplacer le texte ne peut pas revenir sur une faute : là, cette première faute reste, et le texte finit décalé d'un caractère (aussi après Échap ou une autre touche), et l'application ne reçoit plus de fautes. Settings → General liste ces applications sous l'interrupteur des fautes ; "Forget apps where typos couldn't be fixed" (oublier les applications où les fautes n'ont pas pu être corrigées) les laisse réessayer.

### Réglages par application (nouveau)

Settings → Apps donne à une application ses propres réglages, tous facultatifs ; ce qu'une application ne définit pas suit les réglages communs à toutes les applications :

| Réglage | Par exemple | Dans la configuration |
| --- | --- | --- |
| La langue de saisie dans laquelle ses champs de texte commencent | Slack en anglais, WeChat en pinyin | `inputLanguage` |
| Les styles de reformulation que `@improve` y propose | Mail formel et diplomate, Slack décontracté | `rewriteStyles` |
| Taper les résultats, ou non | activé dans une app de messagerie, désactivé dans Mail | `typeOut` |
| Pas d'IA dans cette application | `@improve`, `@translate`, `@question`, `@agent` et vos commandes d'instruction n'y envoient rien et le disent ; la frappe et les autres commandes fonctionnent | `noAI` |
| Toujours traduire en tapant | WeChat toujours en mode Traduire en tapant (voir [Traduire en tapant](#traduire-en-tapant)) | `translateAlways` |

"Add App…" (ajouter une app) liste les applications dans lesquelles vous avez tapé récemment, ou en choisit une dans /Applications. Le menu de saisie, avec "This App: <nom>", propose des interrupteurs rapides pour l'application dans laquelle vous tapez (No AI, Type Results Out, la langue de départ). Dans la configuration, ils sont sous `appProfiles`, par identifiant de bundle : `"appProfiles": {"com.tinyspeck.slackmacgap": {"inputLanguage": "en", "rewriteStyles": ["casual"], "noAI": false}}`. Les identifiants de bundle se comparent sans tenir compte de la casse (`com.apple.Mail` est le `com.apple.mail` de Mail). `@reportissue` compte les applications qui définissent quelque chose, sans jamais les nommer.

- La langue de départ fonctionne comme la langue de saisie par défaut : un champ de texte la prend quand il devient actif, et un changement avec Maj reste ensuite pour les champs de cette application jusqu'à ce que le réglage change.
- Avec No AI, les commandes d'IA restent dans la liste @ ; en lancer une affiche la notification et garde ce que vous avez écrit. Vos propres commandes de terminal (`"type": "terminal"`) exécutent des programmes, pas l'IA, et fonctionnent donc toujours là.

### Settings → Assistant (nouveau)

Les réglages s'ouvrent sur **Assistant**, une page en deux sections (avant 0.6.5, c'étaient les commandes `@config` et `@doctor`).

**Modifier les réglages en une phrase** ("Change settings in a sentence") : écrivez ce que vous voulez ("translate into Japanese and English", "candidates in a column", "use Claude") et cliquez sur Preview (ou ⌘⏎). Chaque changement s'affiche avant → après ; Apply les applique, et Undo les annule pendant 10 minutes. Cette section peut aussi activer ou désactiver la synchronisation via iCloud (ce qui est synchronisé ne se choisit que dans Settings → General). Les clés d'API, les commandes personnalisées, les plugins et tout ce qui lance des programmes n'y sont jamais modifiés ; un fournisseur sans clé ouvre son champ de clé dans Settings → AI Provider, et Test Connection s'exécute après un changement de fournisseur. Cela fonctionne avec Apple Intelligence si ce Mac l'a, sinon avec votre fournisseur.

**Vérifier les problèmes** ("Check for problems") : la méthode de saisie, le fournisseur d'IA, les autorisations, la saisie sécurisée, les packs de langue, `config.json`, les extensions, les mises à jour, la synchronisation via iCloud (activée ou non, la dernière synchronisation, la dernière erreur, iCloud Drive indisponible, des réglages d'iCloud non utilisés ici) et les erreurs récentes sont vérifiés sur ce Mac à l'ouverture de la page, les problèmes d'abord (tout va bien : "Everything looks good"). Check les vérifie à nouveau avec Test Connection ; avec une question dans "What's wrong? (optional)", l'IA explique la cause probable. Une ligne qui peut être corrigée a un bouton Fix : les changements de réglages s'affichent dans l'aperçu au-dessus, avec Apply et Undo ; les autres agissent tout de suite.

### Synchronisation via iCloud (nouveau)

Settings → General → **Sync through iCloud** (synchroniser via iCloud ; désactivé par défaut) garde vos réglages, votre liste de jargon, vos commandes personnalisées et les mots appris par le pinyin identiques sur tous vos Mac, grâce à votre propre iCloud Drive : aucun autre compte où se connecter, rien ne passe par nos serveurs. Il faut iCloud Drive (Réglages Système → Compte Apple → iCloud) ; sans lui, l'interrupteur reste désactivé et le signale, avec un bouton qui ouvre ce panneau.

| Interrupteur | Ce qui est synchronisé | Par défaut |
| --- | --- | --- |
| Settings (réglages) | les réglages de `config.json` : langues, styles de reformulation, touche d'action, frappe des résultats, réglages par application, masquage des informations sensibles (ses interrupteurs), fournisseur d'IA et modèle (jamais une clé) … | activé |
| Jargon and custom commands (jargon et commandes personnalisées) | votre liste de jargon et `customCommands` | activé |
| Learned words (mots appris) | ce que le pinyin a appris de vos choix (le dictionnaire utilisateur de Rime, via la synchronisation des dictionnaires utilisateur de librime ; vos propres fichiers Rime, comme les expressions personnalisées, restent sur le Mac) | activé |
| Hidden words (mots masqués) | les mots que vous cachez à l'IA ("iCloud Drive is end-to-end encrypted only with Advanced Data Protection" : iCloud Drive n'est chiffré de bout en bout qu'avec la protection avancée des données) | désactivé |
| Recent questions (questions récentes) | les questions récentes de `@question` et leurs réponses (tant que "Remember recent questions" est activé) | désactivé |
| API keys and passwords (clés d'API et mots de passe) | vos clés d'API et les mots de passe des extensions, via le trousseau iCloud, toujours chiffré de bout en bout (il faut activer Mots de passe et trousseau dans Réglages Système → Compte Apple → iCloud) | désactivé |

`iCloud Drive/AllInOneIME/settings.json` contient chaque réglage avec le moment où il a changé et sur quel Mac (un identifiant aléatoire), et pour chaque réglage, la modification la plus récente l'emporte : une liste (vos commandes personnalisées, les styles de reformulation) compte comme une seule valeur, les réglages par application vont application par application, et supprimer les réglages d'une application est aussi une modification. La synchronisation a lieu au démarrage de la méthode de saisie, environ 5 s après une modification, quand iCloud apporte une modification d'un autre Mac (et toutes les 5 minutes), et avec **Sync Now** (synchroniser maintenant) ; pour les mots appris, au démarrage de la méthode de saisie, toutes les 30 minutes (après une pause dans la frappe) et avec Sync Now. La ligne d'état indique "Last synced 2 min ago" (dernière synchronisation il y a 2 min), "Waiting for iCloud…" (en attente d'iCloud…) ou l'erreur.

- À l'activation, un Mac prend les réglages déjà présents dans iCloud ; les siens ne complètent que ce qui n'y est pas encore. Ses collections sont en revanche fusionnées : questions récentes (les deux listes, les plus récentes d'abord, chaque question une seule fois), mots masqués, commandes personnalisées (par nom ; celle d'iCloud en cas de conflit) et lignes de la liste de jargon. De même quand un interrupteur en dessous est activé pour la première fois. Ce que vous retirez ensuite sur un autre Mac (une commande personnalisée ou un mot masqué supprimés) reste retiré. Il revient une fois, et le supprimer à nouveau est définitif, quand il venait du premier Mac à avoir activé la synchronisation et que ce Mac était en veille pendant qu'un autre Mac y fusionnait sa liste, quand il a été supprimé sur un Mac encore en 0.6.4, ou quand un Mac encore en 0.6.4 le remet. Un réglage enregistré dans les réglages pendant qu'un Mac active la synchronisation est conservé, et part vers les autres Mac.
- Réactivée après une désactivation : ce qu'iCloud a modifié entre-temps arrive (même là où ce Mac l'a aussi modifié), ce que seul ce Mac a modifié est envoyé, et une collection à laquelle il a ajouté quelque chose entre-temps est fusionnée, jamais abandonnée.
- Les questions récentes de deux Mac sont fusionnées ; "Clear" sur un Mac efface aussi sur les autres toutes les questions posées avant. Désactiver "Remember recent questions" les supprime sur ce Mac seulement, et une fois l'option réactivée, les questions des autres Mac y reviennent. Un Clear fait pendant qu'un Mac ne synchronise pas les questions récentes (ou ne les mémorise pas) ne concerne que ce Mac.
- Désactiver Hidden words ou Recent questions laisse dans iCloud ce qui a été synchronisé : **Remove from iCloud…** (retirer d'iCloud) sous chaque interrupteur (après confirmation) les retire ; les autres Mac gardent les leurs, et un Mac qui les synchronise encore y remet les siens.
- Une valeur venue d'un autre Mac que celui-ci ne peut pas utiliser (un fournisseur sans clé ici, un profil AWS qu'il n'a pas, une valeur hors limites) n'est pas appliquée : la ligne d'état et la vérification des problèmes de Settings → Assistant indiquent laquelle.
- Un fichier qu'iCloud n'a pas encore téléchargé est attendu, jamais considéré comme vide ; un `settings.json` illisible est mis de côté sous le nom `settings (unreadable …).json`, jamais écrasé. Les réglages d'une version plus récente sont conservés tels quels.
- Les clés d'API et les mots de passe passent par le trousseau iCloud, pas par iCloud Drive : avec "API keys and passwords" activé (et la synchronisation activée), une clé enregistrée ou remplacée sur un Mac se retrouve sur les autres. C'est désactivé par défaut : activer la synchronisation seule ne déplace aucune clé, et rien ne bouge tant que vous n'activez pas cette ligne. L'activer déplace les clés de ce Mac du trousseau de session vers le trousseau iCloud (macOS ne demande alors plus votre mot de passe de session pour elles après une mise à jour) ; la désactiver les recopie dans le trousseau de session et les laisse dans le trousseau iCloud pour vos autres Mac. Les clés non synchronisées restent dans le trousseau de session, comme avant, tout comme la connexion à AllInOneIME Cloud, qui n'est jamais synchronisée : chaque Mac se connecte lui-même. Quand deux Mac ont des clés différentes, la dernière enregistrée l'emporte (d'après sa date d'enregistrement, que chaque copie conserve). L'autre n'est pas supprimée : elle est gardée dans le trousseau de session de son Mac comme copie remplacée (sous "AllInOneIME replaced API key", avec un nom qui se termine par "(replaced)"), jamais utilisée. Une clé qui passe dans le trousseau iCloud en garde une aussi, au cas où la clé différente d'un autre Mac arriverait par-dessus. Il y a une copie remplacée par clé sur chaque Mac : une plus récente la remplace. Supprimer une clé synchronisée la supprime sur tous les Mac qui synchronisent les clés (la question dit "all your Macs" : tous vos Mac), ainsi que la copie remplacée de ce Mac ; un Mac où "API keys and passwords" est désactivé, ou encore en 0.6.4, garde sa propre copie, et la remet si la synchronisation des clés y est activée plus tard (la question le dit aussi). Sur un Mac où elle est désactivée, Remove… (supprimer) retire la clé et sa copie remplacée de ce Mac seulement (la question dit "this Mac" : ce Mac), et la copie du trousseau iCloud reste pour vos autres Mac. Une clé que macOS ne laissait pas AllInOneIME lire sans votre mot de passe de session au moment de la déplacer reste dans le trousseau de session jusqu'à sa prochaine utilisation : si macOS le demande alors et que vous l'autorisez, elle est de nouveau utilisée, même si elle a été supprimée sur un autre Mac. Chaque clé n'est toujours envoyée qu'à l'hôte pour lequel elle a été enregistrée. Tant que les clés sont synchronisées, `allinoneime-cli` et les versions antérieures à 0.6.5 ne les voient pas dans le trousseau. Un build sans le profil de provisionnement (un build de développement) garde les clés dans le trousseau de session et ne peut pas les synchroniser : la ligne l'indique.
- Jamais synchronisés : la connexion à AllInOneIME Cloud, les identifiants AWS (dans `~/.aws`), les sources d'extensions (elles exécutent du code : chaque Mac décide), les dossiers d'extensions et les plugins (des chemins propres à chaque Mac), les applications sans fautes de frappe et les applications récentes, l'état des fenêtres, et les interrupteurs de synchronisation eux-mêmes (propres à chaque Mac).
- La désactiver arrête la synchronisation et laisse tout tel quel, sur ce Mac et dans iCloud ; **Remove from iCloud…** (après confirmation) met le dossier à la corbeille et désactive la synchronisation sur ce Mac.
- Settings → Assistant ("sync through iCloud") l'active ou la désactive ; les mots masqués et les questions récentes ne se choisissent que dans Settings → General. Dans la configuration : `iCloudSync` (`enabled`, `settings`, `jargon`, `learnedWords`, `hiddenWords`, `recentQuestions`, `keys`).

## Panneau de la barre des menus

<img src="../en/panel-swipe.png" width="520" alt="Le panneau de la barre des menus : verre dépoli, avec les notes, les rappels et les tâches Claude sur des cartes ; une ligne balayée vers la gauche affiche son bouton Remove">

Cliquez sur l'icône d'AllInOneIME dans la barre des menus (le symbole ∞ avec un curseur, sans cadre ; celui avec un cadre est la source de saisie) et le panneau se déroule en dessous ; un clic ailleurs le ferme :

- Notes : les notes enregistrées avec `@note`, les 5 plus récentes ; cliquez sur l'une d'elles pour l'ouvrir là où elle est allée : dans Notes, dans Obsidian ou l'application propre au fichier, ou la page Notion. Un fichier qui n'existe plus n'est plus listé.
- Reminders (rappels) : les rappels non terminés de la liste AllInOneIME de Rappels (`@reminder` ajoute à cette liste), les plus proches d'abord, 8 affichés ; cliquez sur le cercle pour en cocher un, ou sur le titre pour ouvrir Rappels.
- Claude Tasks (tâches Claude) : comme `@tasks`, les tâches Claude en arrière-plan (ce que `@agent` délègue à Claude Code), jusqu'à 30, 5 affichées à la fois : faites défiler pour en voir plus, ou cherchez dans leurs titres et réponses avec le champ de recherche ; avec leur progression et la première ligne de la dernière réponse ; cliquez sur l'une d'elles pour l'ouvrir dans Terminal et continuer.

Balayez une ligne (une note, un rappel ou une tâche) vers la gauche avec deux doigts pour afficher son bouton Remove (supprimer), ou jusqu'au bout pour la supprimer d'un coup ; avec une souris, faites un clic droit dessus. La suppression la retire seulement du panneau : la note reste dans Notes, le rappel dans Rappels (non terminé), la tâche dans Claude Code.

L'en-tête affiche les compteurs (comme "2 reminders · 1 task running" ; les tâches qui vous attendent sont comptées à part, comme "1 waiting for you") et un bouton d'actualisation. Il ne prend jamais le focus à l'application dans laquelle vous tapez : cocher un rappel ou actualiser laisse cette application au premier plan ; seul le champ de recherche des tâches Claude, une fois cliqué, prend le clavier. L'icône est affichée par défaut ; désactivez-la sous "Menu Bar Panel" dans les réglages.

Ce qu'il lit, et quand :

- Notes : la liste est le registre propre du panneau (conservé même quand il est fermé), et Notes n'est jamais lancée : c'est seulement quand Notes est déjà ouverte, et qu'AllInOneIME a été autorisé auparavant à la contrôler, que le panneau y vérifie les titres modifiés et les notes supprimées.
- Rappels : la liste AllInOneIME est lue quand le panneau se déroule, toutes les 60 secondes et quand les rappels changent. Le panneau ne fait jamais demander l'accès par macOS de lui-même : si macOS ne vous l'a pas encore demandé, il affiche "Allow Access to Reminders" (autoriser l'accès à Rappels), et seul ce bouton le demande ; si vous avez refusé, il affiche "Open System Settings" (ouvrir Réglages Système).
- Tâches Claude : le panneau n'exécute `claude agents` que lorsqu'il est déroulé : une fois à l'ouverture, lors d'une actualisation, et quand `@agent` délègue une tâche ; et toutes les 15 secondes tant qu'une tâche n'est pas terminée, plus du tout une fois qu'elles le sont toutes. Les dernières réponses sont lues à la fin des transcriptions de Claude Code sur ce Mac (`~/.claude/projects`), et seulement quand une transcription a changé.
- Quand il est fermé, rien de tout cela ne s'exécute ; il se contente de garder un registre des notes que `@note` enregistre.

## Saisie et traduction

Dans les réglages :

- **Langues de saisie** : de une à cinq parmi l'anglais, le chinois (pinyin), le français, le coréen et le hindi, ajoutées avec + (toujours présent ; grisé à cinq). Une nouvelle installation commence avec l'anglais seulement. Les nouveaux champs de texte commencent dans la première ; un appui bref sur Maj passe à la suivante, dans leur ordre ; avec une seule, Maj ne change rien.
  - **Le français** se tape avec sa propre disposition de clavier : AZERTY, sauf si vous en choisissez une autre sur sa carte. Ses touches mortes (^, ¨, `, ´, ~) composent aussi à partir de celle-ci.
  - **Le coréen** se tape en hangeul avec la disposition 2-set (Dubeolsik), chaque syllabe étant assemblée au fil de la frappe (g k s → 한) ; Maj donne ㄲ ㄸ ㅃ ㅆ ㅉ et ㅒ ㅖ.
  - **Le hindi** : tapez les mots tels qu'ils se prononcent en lettres latines et obtenez du devanagari (namaste → नमस्ते). Les mots courants sont orthographiés comme on les écrit en hindi ; sinon Espace insère la première graphie, un chiffre une autre, ⏎ les lettres telles que tapées, et "." le danda (।).
  - Le nom d'une commande, le texte de `@open` et le code (`@py`, `@js`) se tapent en lettres latines quelle que soit la langue ; celle-ci revient après la commande.
  - `@improve` garde une phrase coréenne, hindie ou française dans sa propre langue, et `@translate` la traduit dans vos langues (le français est distingué de l'anglais lorsqu'il fait partie de vos langues de saisie).
- **Packs de langue** : l'application est fournie avec l'anglais (et le français, qui n'a besoin que de la disposition de macOS). Le chinois, le coréen et le hindi sont des packs que vous téléchargez en les ajoutant : ajouter le chinois (pinyin) télécharge ses dictionnaires (environ 34 Mo, 125 Mo une fois décompressés) avec une barre de progression, et le pinyin fonctionne dès que c'est terminé, sans redémarrage ; le pack du coréen (sa table de touches et la façon dont les jamo forment des syllabes) et celui du hindi (ses lettres et ses mots courants) pèsent quelques kilo-octets. Un pack ne contient que des données (dictionnaires, tables et schémas, jamais de code), il est listé dans un index signé et vérifié par rapport à son SHA-256 avant d'être utilisé, comme les plugins. La carte de chaque langue affiche son pack (version, taille, provenance) avec Delete… (supprimer), et retirer la langue propose de supprimer son pack. Une mise à jour depuis la version 0.6.1 ou antérieure conserve le chinois sans téléchargement : l'installeur garde les dictionnaires fournis avec l'ancienne version.
- **Disposition des candidats** : pour choisir les mots, les candidats pinyin et hindi sont côte à côte par défaut (Horizontal), comme dans les méthodes de saisie du système : ← → choisissent et ↑↓ (ou - =) changent de page. Choisissez Vertical sur la page Input, sous les langues de saisie, pour les avoir les uns sous les autres (↑↓ choisissent). La liste des commandes @ et les résultats sont toujours verticaux.
- **Pinyin approximatif** (avec la saisie du chinois) : des sons que vous ne distinguez pas, tapés d'une façon ou de l'autre, par ex. z ↔ zh, n ↔ l, in ↔ ing. Sur la page Input, choisissez Chinese (pinyin) dans la barre des langues de saisie, activez "Fuzzy pinyin" et choisissez les paires ; les dictionnaires sont redéployés en une seconde ou deux. Cela écrit `rime_ice.custom.yaml` dans le dossier utilisateur de Rime, et jamais par-dessus un fichier à vous qui s'y trouverait.
- **Personal Dictionaries** (dictionnaires personnels, avec la saisie du chinois) : Settings → Input → Chinese (pinyin) → Personal Dictionaries → **Import or Update…** ajoute un vocabulaire Rime en UTF-8 (`.dict.yaml`) à côté de rime-ice (le pack de langue chinois doit être installé). La liste montre le `name` Rime, le nom du fichier et le nombre d'entrées de chacun ; importer à nouveau le même `name` remplace sa copie enregistrée (modifier seulement le fichier source ne la met pas à jour). Chaque import, mise à jour ou suppression recompile le dictionnaire pinyin (tous les mots de rime-ice avec les vôtres), ce qui peut prendre une minute environ ; la saisie du chinois est suspendue jusque-là, et la page affiche la progression ou une erreur. Les copies restent sur ce Mac, hors de la synchronisation iCloud et des requêtes à l'IA ; mais un mot que vous y choisissez est appris comme les autres, dans le dictionnaire utilisateur de Rime, qui se synchronise avec les mots appris si c'est activé et reste après la suppression du dictionnaire. Si vous avez votre propre `rime_ice.custom.yaml`, l'import est refusé avant toute modification de fichier.
- **Traduction (@translate)** : ajoutez les langues vers lesquelles traduire (espagnol, français, allemand, japonais, coréen, chinois, hindi, bengali, tamoul et les autres grandes langues de l'Inde…) et faites-les glisser pour les ordonner. Le hindi tapé en lettres latines ("aap kaise ho") revient en devanagari. `@translate` écrit une ligne dans chacune, dans cet ordre (trois versions s'il n'y en a qu'une) ; la langue de la phrase elle-même est ignorée. Une nouvelle installation traduit vers la première langue des langues préférées de votre Mac qui n'est pas l'anglais ; avec l'anglais seul, `@translate` indique qu'il n'y a encore aucune langue cible, et ⏎ sur cet avis ouvre cette page avec "Add…" (ajouter…) encadré (la phrase est insérée telle que tapée). Traduire en tapant ne s'active pas alors, et indique où en ajouter une.
- **Dispositions de clavier** : le français se tape avec la disposition choisie sur sa carte (`keyboardLayouts` dans la configuration). Pour les autres langues, sous la méthode de saisie, macOS conserve votre dernière disposition latine (AZERTY, QWERTZ, espagnol, U.S. International…), vous tapez donc comme d'habitude, `@` compris là où votre disposition le place, et les touches mortes composent aussi dans le texte d'une commande (⌥E puis E → é, ^ puis e → ê). Les dispositions sans lettres latines (russe, hindi InScript) ne peuvent pas être utilisées sous une méthode de saisie : passez-y avec ⌃Espace, ou collez (⌃V) du texte dans une commande.
- `@improve` peaufine et reformule sans traduire ; `@translate @improve` ensemble traduit et reformule en une seule requête. Activez "@improve also translates" dans les réglages pour que `@improve` fasse toujours cela.

Un dictionnaire personnel ressemble à ceci (les champs d'une entrée sont séparés par des **tabulations**) :

```yaml
---
name: my_vocabulary
version: "1"
columns: [text, code, weight]
...
星河项目	xing he xiang mu	100
蓝杉团队	lan shan tuan dui	200
```

Écrivez le pinyin en minuscules latines, avec des espaces entre les syllabes et `v` pour `ü` ; le poids est facultatif (un nombre positif ou nul). Sans `columns`, l'ordre est `text`, `code`, `weight`. `name` peut contenir des lettres latines, des chiffres, `-`, `_` et `.` ; un fichier fait au plus 32 Mio. Les fichiers qui dépendent de `import_tables` ou n'ont pas de codes pinyin sont refusés, sans rien modifier.

## Styles de reformulation

Après les lignes 1–3 viennent les reformulations, **dans la langue que vous avez tapée** : des reformulations en anglais pour l'anglais, en chinois pour le chinois. Choisissez celles que vous voulez dans les réglages :

- Polish (peaufiner) : même ton, plus naturel
- Concise (concis)
- Formal (formel) : pour les managers et les clients
- Casual (décontracté)
- Tactful (diplomate)
- Jargon : le jargon d'Amazon en anglais (bandwidth, circle back…), le jargon des grandes entreprises tech en chinois. Les mauvaises nouvelles sont minimisées, par ex. "this is a blocker bug" → "Oh! Looks like your team has the bandwidth to fix this minor issue!"

Les reformulations qui ne changent que la ponctuation ou répètent une autre ligne ne sont pas affichées.

### Liste de jargon (vos propres termes)

Jargon n'a pas de liste de termes intégrée. Vous pouvez préparer la vôtre (par exemple, les expressions qu'utilise votre équipe), et le modèle privilégie ses termes. Dans les candidats, la ligne Jargon précise le sens des termes qu'elle a utilisés.

La liste est un fichier texte avec un terme par ligne, éventuellement suivi de sa signification, séparée par "=", deux-points ou une tabulation (vous pouvez copier deux colonnes d'un tableur et les coller). Les lignes commençant par `#` sont des commentaires :

```
PRFAQ = a new-feature proposal: the press release and FAQ, written first
COE = an incident review
two-way door = a decision you can undo at any time
```

Sous "Rewrite Styles → Jargon list" dans les réglages, cliquez sur "New" (nouveau) pour créer une liste vide à l'emplacement `~/.config/allinoneime/jargon.txt` et l'ouvrir ; si vous avez déjà un fichier de liste, cliquez sur "Choose File…" (choisir un fichier) pour l'utiliser là où il se trouve (`jargonFile` dans la configuration). Les modifications s'appliquent immédiatement. Seuls les 150 premiers termes sont lus. Avec "Jargon" coché, la liste est envoyée à Bedrock avec chaque requête.

## Traduire en tapant

Un prototype, à essayer. Maintenez Maj seule pendant 1 seconde pour activer (ou désactiver) la traduction en tapant ; un appui bref sur Maj change toujours de langue de saisie. À 0,5 s, une indication près du curseur affiche "Keep holding → Translate as You Type" (continuez à maintenir → traduire en tapant), et à 1 s, "Translate as You Type on: Chinese → English · hold Shift again to turn off" (traduction en tapant activée : chinois → anglais · maintenez de nouveau Maj pour la désactiver ; elle nomme la langue vers laquelle elle traduit) le confirme pendant environ 1,5 s (pour la désactiver : "Keep holding → Translate as You Type off", puis "Translate as You Type off") ; relâchez avant et rien ne change. Maj avec une lettre (une majuscule) ou avec une autre touche ne l'active jamais. Tant qu'elle est active, l'icône de la barre des menus porte un petit point. Il n'y a pas de commande pour elle.

Tant qu'elle est active, ce que vous tapez s'accumule dans un brouillon, avec les langues sur la pastille à côté ("ZH → EN" ; 「中 → 英」 dans l'interface chinoise). Elle traduit vers la langue choisie en dernier sur sa pastille (voir plus bas), dans toutes les applications et après un redémarrage ; tant que vous n'en avez pas choisi, vers votre première langue de traduction dans les réglages (et de nouveau vers celle-ci quand la langue choisie n'en fait plus partie). Si vous ne tapez qu'une langue, celle-ci est sautée : en tapant l'anglais seul, avec l'anglais puis le français comme langues de traduction, c'est le français. La langue que vous tapez au moment de l'activation n'y change rien. ⏎ traduit le brouillon et la traduction est insérée aussitôt, sans candidats à choisir : le brouillon indique "Translating…" (traduction en cours…) pendant ce temps, et rien n'est envoyé (le ⏎ suivant est celui de l'application). ⇧⏎ insère le brouillon tel que tapé ; Échap pendant la traduction l'arrête et garde le brouillon (⌫ l'arrête aussi, et efface un caractère comme sur le brouillon) ; en cas d'échec (le réseau, un refus, la saisie sécurisée), le brouillon reste avec une notification d'une ligne et ⏎ réessaie. Le texte tapé dans la langue vers laquelle elle traduit (appui bref sur Maj pour passer à l'anglais) est inséré tel que tapé.

Tant qu'elle est active, une petite pastille "ZH → EN" (「中 → 英」 dans l'interface chinoise) s'affiche sous la ligne où vous tapez, dans le panneau propre à la méthode de saisie (le panneau des candidats : au-dessus des candidats pendant que vous tapez du pinyin), si bien qu'elle ne prend jamais le focus à l'application. Cliquez sur "ZH" pour changer de langue de saisie, comme avec un appui bref sur Maj. Cliquez sur "EN" pour une courte liste de vos langues de traduction, la langue actuelle cochée, et cliquez sur l'une d'elles : c'est vers elle qu'elle traduit, aussitôt (la pastille et la traduction suivante suivent) et désormais. Les touches fonctionnent comme avant ; n'importe laquelle ferme la liste.

- **Ton** : il suit l'application : le premier style de reformulation de l'application dans Settings → Apps, sinon décontracté dans les apps de messagerie (WeChat, Slack, Messages, Telegram, Discord, Teams), formel dans les apps de courrier (Mail, Outlook, Spark), naturel ailleurs.
- **Applications** : passer à une autre application (même une sans champ de texte) la désactive, sans notification, et revenir la laisse désactivée, sauf si cette application a "Always Translate as You Type" (toujours traduire en tapant ; 「总是边打边译」) dans Settings → Apps (`translateAlways` dans son profil) : là, elle s'active d'elle-même. Dans une application réglée sur No AI, elle ne fait rien : le texte est inséré tel que tapé, avec une notification ; de même pour ce que vous tapez pendant une saisie sécurisée (un champ de mot de passe).
- **Confidentialité** : comme pour `@translate` : envoyé seulement quand vous appuyez sur ⏎, à votre propre fournisseur d'IA, avec les informations sensibles masquées si cette option est activée.

## Installation

Il faut macOS 14 ou une version ultérieure pour l'utiliser. L'installeur est universel : il fonctionne sur les Mac à puce Apple et Intel. Pour l'instant, il n'a été testé que sur macOS 27 sur puce Apple (la version Intel seulement par son autotest sous Rosetta).

1. Téléchargez `AllInOneIME-<version>.dmg` depuis les [Releases](https://github.com/MicroZ-LLC/AllInOneIME/releases/latest) (uniquement depuis là) et ouvrez-le.
2. Double-cliquez sur "Install AllInOneIME" qu'il contient et cliquez sur Install. La méthode de saisie va dans `~/Library/Input Methods` et "AllInOneIME Settings" dans `~/Applications`. Pour cet utilisateur seulement ; aucun mot de passe administrateur n'est nécessaire.
3. L'installeur est signé avec un Developer ID et notarié par Apple, donc la première fois macOS demande seulement s'il faut ouvrir une application téléchargée sur Internet : cliquez sur Ouvrir. (Les versions antérieures à 0.6.3 n'étaient pas notariées : chacune devait être autorisée une fois dans Réglages Système → Confidentialité et sécurité → Ouvrir quand même.)

Ensuite, AllInOneIME est activé et figure dans vos sources de saisie ; passez-y avec Ctrl+Espace (la touche 🌐 ne change de source que si "Appuyer sur la touche 🌐 pour" est réglé sur "Changer de source de saisie" dans Réglages Système → Clavier). Si l'installeur vous dit de l'ajouter à la main, ce Mac ne permet pas aux programmes de l'activer ; ajoutez-le donc vous-même une fois : Réglages Système → Clavier → Saisie de texte → Sources de saisie → Modifier… → + (en bas à gauche) → Anglais → AllInOneIME (il tape aussi le pinyin une fois que vous avez ajouté le chinois sous Input dans ses réglages).

Si Ctrl+Espace ne vous amène pas à AllInOneIME, ou s'il revient à U.S. au bout d'un moment, relancez l'installeur : il rajoute AllInOneIME à vos sources de saisie.

Mise à jour : Settings → About → Check for Updates (rechercher des mises à jour). Quand une nouvelle version existe, About l'indique (ainsi qu'une ligne dans le panneau de la barre des menus), avec les nouveautés ; "Update to <version>" (mettre à jour vers <version>) la télécharge, la vérifie par rapport aux informations de mise à jour signées avec la clé de publication d'AllInOneIME, l'installe et redémarre la méthode de saisie. Vos réglages, packs de langue, mots appris et extensions sont conservés, et si quelque chose se passe mal, la version que vous aviez est remise en place. AllInOneIME vérifie une fois par jour de lui-même, en arrière-plan (désactivez-le avec "Check for updates automatically" sous About) ; rien n'est installé tant que vous ne cliquez pas. Cela fonctionne à partir de 0.6.3 ; pour mettre à jour une version plus ancienne, ou si vous préférez, installez l'image disque de la nouvelle version par-dessus, sans désinstaller d'abord. Avant de mettre à niveau, lisez le [journal des modifications](../../CHANGELOG.md) : il contient les changements de chaque version et les notes de mise à niveau.

Mise à jour vers 0.6.3 depuis une version antérieure : 0.6.3 est la première version signée avec un Developer ID, donc le trousseau ne la reconnaît pas encore comme l'application qui a enregistré vos clés. La première fois qu'elle a besoin de chaque clé enregistrée (une clé d'API, la connexion à AllInOneIME Cloud, le mot de passe d'une extension), macOS demande votre mot de passe de session : saisissez-le et cliquez sur "Always Allow" (Toujours autoriser). Il ne le redemande plus, y compris après les mises à jour suivantes. Les clés d'Amazon Bedrock se trouvent dans `~/.aws/credentials`, qui n'est pas concerné. L'accessibilité (Réglages Système → Confidentialité et sécurité → Accessibilité), dont se servent le collage dans les terminaux et la lecture de la sélection, demande aussi une étape : si AllInOneIME figure dans la liste, retirez-le, puis réactivez-le quand on vous le demande.

Si vous aviez installé AIPinyin (l'ancien nom d'AllInOneIME), installez simplement : l'ancienne AIPinyin.app et son lanceur de réglages sont supprimés, et l'entrée de vos sources de saisie prend le nouveau nom, sans qu'il faille la rajouter. Les réglages, la liste de jargon et les mots appris sont déplacés vers les nouveaux dossiers (`~/.config/allinoneime` et autres) au premier lancement, et chaque ancien dossier est remplacé par un lien vers le nouveau.

Pour désinstaller, ouvrez "Install AllInOneIME" et cliquez sur Uninstall…. Les réglages et les mots appris sont conservés.

### Compiler depuis les sources

La compilation nécessite Xcode 26 ou une version ultérieure (le SDK de macOS 26).

```sh
git clone https://github.com/MicroZ-LLC/AllInOneIME.git
cd AllInOneIME
make install
```

`make install` télécharge librime et les dictionnaires rime-ice et les vérifie, compile, puis installe aux mêmes emplacements, en l'ajoutant à vos sources de saisie de la même façon. L'application installée ainsi n'a pas de dictionnaires chinois (ils constituent le pack de langue chinois) : une installation qui les avait les garde comme pack ; sinon `make install-pack` installe le pack à partir des dictionnaires du dépôt local, sans téléchargement. `make status` affiche la version installée (`version:`) et indique si elle figure dans vos sources de saisie (`listed:`). Pour désinstaller : `make uninstall`.

## Configurer l'IA

Les traductions et reformulations vont au fournisseur d'IA choisi dans Settings → AI Provider. Une nouvelle installation démarre sur AllInOneIME Cloud : connectez-vous, et vous disposez de 20 requêtes gratuites par jour. Sur un Mac doté d'Apple Intelligence, tout peut aussi s'exécuter sur ce Mac, sans compte (voir "Apple Intelligence sur ce Mac" ci-dessous). Ou utilisez votre propre fournisseur, les coûts étant imputés à votre compte : Amazon Bedrock dans votre compte AWS, l'API Claude, Gemini ou un service compatible OpenAI (voir "Autres fournisseurs d'IA" ci-dessous).

### Amazon Bedrock

1. Activez Bedrock dans la console AWS et assurez-vous de pouvoir utiliser le modèle choisi. Le modèle par défaut est Claude Haiku 4.5 ; la première fois que vous utilisez un modèle Anthropic, vous remplissez une fois un formulaire de cas d'usage.
2. Utilisez un profil AWS autorisé à `bedrock:InvokeModelWithResponseStream` : des clés statiques dans `~/.aws/credentials`, ou un profil qui obtient des identifiants temporaires (`credential_process`, un rôle, SSO ; voir "Profils AWS" ci-dessous).
3. Ouvrez "AllInOneIME Settings" : vous le trouverez dans Spotlight ou dans Applications, ou ouvrez-le depuis l'icône de la méthode de saisie dans la barre des menus → Settings…. Choisissez le profil, la région et le modèle, puis cliquez sur "Test Connection" (tester la connexion). L'interface est disponible en English, 简体中文 (chinois simplifié), 繁體中文 (chinois traditionnel), 日本語, 한국어, Deutsch, Français, Español et Português (Brasil). Par défaut ("Follow the system" (suivre le système) dans Settings → General → "Interface language" (langue de l'interface)), elle suit les langues préférées du système (Réglages Système → Général → Langue et région) : la première d'entre elles que l'application propose, une variante régionale donnant sa langue (Deutsch pour de-AT, Español pour es-MX, Français pour fr-CA), le chinois traditionnel pour zh-Hant, zh-TW et zh-HK, le chinois simplifié pour les autres variantes du chinois, le portugais du Brésil aussi pour celui du Portugal (il s'y lit mieux que l'anglais), l'anglais quand aucune ne convient. Vous pouvez aussi en choisir une à cet endroit, chacune étant listée dans sa propre langue. La fenêtre des réglages, les indications du panneau des candidats et le menu de saisie suivent tous cette langue. Les réglages s'ouvrent sur la page Assistant : modifier les réglages en les décrivant et vérifier les problèmes, avec un bouton Fix pour chacun (voir [Settings → Assistant](#settings--assistant-nouveau)).

#### Profils AWS

Tout profil que l'AWS CLI peut utiliser sans rien vous demander fonctionne, depuis `~/.aws/config` et `~/.aws/credentials` (ou les fichiers que nomment `AWS_CONFIG_FILE` et `AWS_SHARED_CREDENTIALS_FILE` dans votre shell). Dans un profil, c'est la première de ces sources qu'il contient qui est utilisée, dans l'ordre de l'AWS CLI (un profil qui a à la fois `role_arn` et des clés est un rôle) :

| Type | Dans le profil | Renouvellement |
| --- | --- | --- |
| Rôle | `role_arn` avec `source_profile` (de n'importe quel type ici, chaînes comprises ; un profil qui se nomme lui-même utilise ses propres clés) ou `credential_source = Environment` ; `role_session_name`, `external_id`, `duration_seconds` | de nouveau par STS `AssumeRole` (dans la `region` du profil, sinon us-east-1) 5 minutes avant leur expiration |
| SSO | `sso_account_id`, `sso_role_name` avec `sso_session` et sa section `[sso-session …]` (ou les anciens `sso_start_url`, `sso_region`) | récupérés de nouveau avec votre connexion en cache 5 minutes avant leur expiration |
| Clés statiques | `aws_access_key_id`, `aws_secret_access_key` (et `aws_session_token`) dans `~/.aws/credentials` | relues à chaque requête |
| `credential_process` | `credential_process = /usr/local/bin/my-creds --profile dev` (découpé comme une commande shell, exécuté sans shell, avec le PATH de votre shell de connexion, dans votre dossier de départ, 60 s au plus) | réexécuté 5 minutes avant son `Expiration` ; s'il n'y en a pas, quand AWS refuse les identifiants |
| Clés statiques | les mêmes clés dans `~/.aws/config` | relues à chaque requête |

Avec le profil "default" (ou si aucun n'est choisi), les clés de votre shell passent en premier, comme les prend l'AWS CLI : `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` et `AWS_SESSION_TOKEN`. Un profil que vous nommez n'est jamais mélangé avec elles. `AWS_REGION` (ou `AWS_DEFAULT_REGION`) dans votre shell l'emporte sur la `region` d'un profil, comme dans l'AWS CLI ; le champ Region des réglages l'emporte sur les deux.

- **Automatique :** les identifiants qui expirent sont gardés en mémoire (jamais écrits sur le disque) et récupérés de nouveau 5 minutes avant leur expiration ; quand il reste moins de 10 minutes, une requête les utilise et en récupère de nouveaux en arrière-plan, pour que la frappe n'attende pas. Les requêtes simultanées attendent une seule récupération. Quand Bedrock répond que les identifiants ont expiré (`ExpiredTokenException` …), ils sont récupérés de nouveau et la requête est renvoyée, une seule fois.
- **SSO :** AllInOneIME utilise la connexion que l'AWS CLI conserve dans `~/.aws/sso/cache` (il ne fait que la lire) et ne peut pas se connecter à votre place, car il faut un navigateur. Quand la connexion expire, le panneau des candidats indique "SSO sign-in expired: run aws sso login --profile X" (connexion SSO expirée : exécutez aws sso login --profile X) : exécutez cette commande dans Terminal (les réglages proposent Copy Command et Open in Terminal ; Settings → Assistant propose la commande à copier), et AllInOneIME reprend tout seul la nouvelle connexion.
- **Non pris en charge :** `mfa_serial` (une méthode de saisie ne peut pas vous demander de code MFA : utilisez `credential_process` ou SSO, ou laissez votre CLI mettre les identifiants en cache), `credential_source = Ec2InstanceMetadata` ou `EcsContainer` (pas sur un Mac), et web identity.
- **Limites connues :** seuls le PATH et les variables des fichiers AWS (`AWS_CONFIG_FILE`, `AWS_SHARED_CREDENTIALS_FILE`) viennent de votre shell de connexion, pour `credential_process` aussi (pas le reste de son environnement). AllInOneIME ne renouvelle pas les jetons `sso_session` (le jeton d'actualisation de la CLI n'est pas utilisé : le cache SSO est seulement lu), donc quand le jeton en cache expire, exécutez `aws sso login` (l'AWS CLI le renouvelle aussi chaque fois que vous l'utilisez).
- **Settings → AI Provider** liste chaque profil avec son type ("dev — Role via base") et indique, pour celui qui est choisi, quand ses identifiants expirent ("Role via base: credentials expire at 15:30", "SSO (signed in until 18:00)") ou ce qu'il faut faire. Test Connection récupère des identifiants neufs par toute la chaîne ; Settings → Assistant rapporte la même chose.
- Des programmes ne s'exécutent et AWS n'est sollicité pour des identifiants (`sts.<region>.amazonaws.com`, `portal.sso.<region>.amazonaws.com`) que lorsqu'une requête ou Test Connection en a besoin : jamais pour lister les profils, jamais pour Settings → Assistant.

### Autres fournisseurs d'IA : API Claude, Gemini, services compatibles OpenAI

Vous n'avez pas besoin d'AWS : choisissez-en un sous "AI Provider" (fournisseur d'IA) dans les réglages, collez une clé d'API, cliquez sur "Save" (enregistrer), puis sur "Test Connection".

| Fournisseur | Modèle par défaut | Clé d'API |
|---|---|---|
| API Claude | `claude-haiku-5-5` (le plus rapide et le moins cher ; Sonnet 5.5 et Opus 5.5 sont plus soigneux mais plus lents et plus chers) | [Claude Console](https://platform.claude.com) |
| API Gemini | `gemini-3.8-flash` | Google AI Studio |
| Compatible OpenAI | `gpt-6-luna` d'OpenAI (ou `gpt-5.4-mini`) ; "Common Services…" (services courants) propose DeepSeek, Qwen, Kimi, Zhipu GLM, SiliconFlow, OpenRouter et Ollama sur ce Mac : en choisir un remplit son URL de base, puis saisissez son modèle | La clé du service ; réglez la Base URL sur son adresse, par ex. `https://api.deepseek.com/v1`, ou `http://localhost:11434/v1` pour Ollama sur ce Mac |

- Les clés d'API sont conservées dans le trousseau de session, jamais dans le fichier de configuration ; si vous activez "API keys and passwords" sous Sync through iCloud, elles le sont plutôt dans le trousseau iCloud, où `allinoneime-cli` et les versions antérieures à 0.6.5 ne les voient pas. S'il n'y en a pas, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` (ou `GOOGLE_API_KEY`) et `OPENAI_API_KEY` de votre shell sont utilisées.
- La ligne de la clé d'API indique si une clé est définie : "✓ Saved · ends in a1b2" (enregistrée · se termine par a1b2 : ses 4 derniers caractères, conservés avec elle pour ne pas avoir à lire la clé pour les afficher) avec Replace… (remplacer) et Remove… (supprimer), "✓ From $OPENAI_API_KEY" (depuis $OPENAI_API_KEY) pour une clé de votre shell, ou "No API key yet" (pas encore de clé d'API) avec le champ pour la coller.
- "Thinking" (réflexion) est réglé sur bas par défaut : la méthode de saisie attend à chaque phrase, et moins de réflexion va plus vite. Choisissez "Not set" (non défini) pour les modèles qui ne le prennent pas en charge.
- Avec Claude Opus 5.5 ou Sonnet 5.5, les requêtes incluent le repli en cas de refus de l'API Claude (`fallbacks: "default"`) : quand un classificateur de sécurité refuse, le serveur réessaie avec un autre modèle.
- Dans le fichier de configuration : `provider` (`"bedrock"`, `"anthropic"`, `"gemini"`, `"openai"`), et `model`, `baseURL`, `effort` et `temperature` sous `anthropic`, `gemini` et `openai` (ceux qui ne sont pas définis prennent les valeurs par défaut).

### Apple Intelligence sur ce Mac (macOS 26)

Sur un Mac doté d'Apple Intelligence (puce Apple, macOS 26 ou ultérieur, activée dans Réglages Système → Apple Intelligence et Siri), choisissez "Apple Intelligence (on this Mac)" sous "AI Provider" : pas de clé, pas de coût, et rien de ce que vous tapez ne quitte le Mac. Elle utilise le modèle intégré à macOS (le framework Foundation Models), avec les mêmes instructions et le même format de réponse que les autres fournisseurs, mais uniquement les exemples écrits dans la langue de la phrase (un petit modèle copie trop facilement la langue d'un exemple).

- C'est un petit modèle : son contexte est d'environ 4K tokens (8K sur macOS 27), donc un long paragraphe peut être trop long pour lui, et il parle moins de langues (anglais, chinois, japonais, coréen, français, allemand, espagnol et quelques autres ; pas le hindi). Dans les deux cas, il le dit. Ses résultats sont en dessous de ceux des modèles dans le cloud, et ses réponses de `@question` sur des faits et du code sont souvent fausses.
- Là où il ne peut pas être utilisé, il est listé en grisé avec la raison (non pris en charge sur ce Mac, désactivé, modèle pas prêt), et les réglages renvoient vers Réglages Système → Apple Intelligence et Siri. Avant macOS 26, il n'est pas listé.
- "Output tokens", la température et le délai d'expiration sous "Model Settings" s'y appliquent. Dans le fichier de configuration : `"provider": "apple"`.

## Confidentialité

- La frappe (anglais et pinyin) et les calculs du plugin `@calculator` sont entièrement locaux. Ce n'est que lorsque vous appuyez sur la touche d'action avec `@improve`, `@translate` ou `@question` que la phrase est envoyée au fournisseur d'IA que vous avez choisi (votre propre Bedrock, ou le service dont vous avez ajouté la clé). Avec "Jargon" coché et une liste de jargon définie, la liste est envoyée avec elle. Affiner les résultats (une consigne tapée après eux, puis ⇧⏎) renvoie la même requête avec les résultats affichés et votre consigne ; une question de suivi (⇧⏎) envoie avec elle la conversation jusque-là.
- Settings → Assistant n'envoie du texte à un modèle que lorsque vous cliquez sur Preview, ou sur Check avec une question : à Apple Intelligence sur ce Mac dès qu'elle est disponible (rien ne quitte le Mac), sinon à votre fournisseur. Une demande envoie votre phrase (une clé tapée dedans est retirée d'abord) avec les valeurs actuelles des réglages qu'elle peut modifier : jamais une clé, ni les mots que vous cachez à l'IA (seulement leur nombre), et les noms de vos profils AWS seulement quand la phrase parle d'AWS ou de Bedrock. Une question est envoyée avec les résultats des vérifications, masqués : pas de chemins au-delà de `~`, pas de clés, les lignes de journal sous forme de phrases fixes. Le masquage des informations sensibles s'applique aux deux. Les vérifications seules n'envoient rien ; Check envoie en plus la requête de Test Connection, et seulement si le fournisseur a une clé ou des identifiants à tester.
- Poursuivre ailleurs une conversation `@question` (⌘1 … après le dernier tour, ou ⌘⏎) l'envoie, avec ce que vous avez tapé, au service que vous choisissez : un agent de codage sur ce Mac (Claude Code, Gemini CLI, Kiro CLI ou le vôtre, chacun avec son propre compte et son propre service), claude.ai, chatgpt.com ou gemini.google.com, dans l'adresse web ou via le presse-papiers. Elle part telle que vous l'avez vue : les valeurs masquées dans les requêtes à l'IA (voir ci-dessous) y figurent telles quelles, puisque c'est vous qui choisissez de l'envoyer là. Rien ne part tant que vous n'en avez pas choisi un ; "Copy the conversation" ne fait que la mettre dans le presse-papiers.
- Avec AllInOneIME Cloud, la phrase passe par le serveur du développeur vers un fournisseur de modèles (actuellement via OpenRouter) : le serveur ne conserve que des compteurs, jamais le texte. La connexion ne conserve que votre adresse e-mail.
- Masquer les informations sensibles (Settings → AI Provider → Privacy, désactivé par défaut) : avant l'envoi de toute requête (`@improve`, `@translate`, `@question`, vos commandes d'instruction et plugins d'instruction, avec tous les fournisseurs, y compris AllInOneIME Cloud), les adresses e-mail, numéros de téléphone, numéros de carte de paiement (vérifiés par Luhn), clés d'API et jetons (`sk-`, `sk-ant-`, `AKIA…`, `ghp_`, `xox…` et longues chaînes aléatoires), adresses IP et vos propres mots (un nom de code, un nom) sont remplacés sur le Mac par des espaces réservés comme `[EMAIL_1]`, `[PHONE_1]`, `[ITEM_1]` ; la même valeur reçoit le même espace réservé. Les résultats du modèle récupèrent les vraies valeurs avant d'être affichés ou insérés, et le panneau indique "2 items hidden from the AI". Un résultat dont le modèle a modifié l'espace réservé au point de le rendre méconnaissable est affiché tel qu'écrit, marqué "⚠ placeholder changed". Les entrées de la liste de jargon contenant une valeur masquée ne sont pas envoyées. Chaque type peut être désactivé. Les formes pleine chasse (`zhang＠example.com`, `１３８…`) sont trouvées aussi, et une valeur ou une expression peut être coupée par un retour à la ligne. Il reconnaît les valeurs formatées comme les e-mails, les numéros et les clés ; il ne peut reconnaître ni les noms ni les adresses (ajoutez-les comme vos propres mots), ni les lettres semblables d'autres alphabets. S'applique aux requêtes vers votre service d'IA ; `@agent` (avec la page Chrome qu'elle emporte), les plugins qui récupèrent des données sur un site web (`@stock`) ou en ouvrent un (`@x`) et les extensions par script envoient le texte tel que tapé. Dans la configuration : `redaction` (`enabled`, `emails`, `phones`, `cards`, `keys`, `ips`, `customWords`).
- La méthode de saisie lit le texte du presse-papiers, une fois, uniquement lorsque vous appuyez sur ⌃V ou ⌘V dans une commande ; le contenu que les gestionnaires de mots de passe marquent comme masqué n'est pas lu. Le texte est d'abord affiché dans la commande et, là encore, n'est envoyé que lorsque vous appuyez sur la touche d'action. Les versions récentes de macOS demandent si AllInOneIME peut lire le presse-papiers : autorisez-le. Pour ne plus avoir à répondre à chaque fois, réglez l'autorisation de collage d'AllInOneIME sur toujours autoriser dans Réglages Système → Confidentialité et sécurité.
- Dans les champs de mot de passe, macOS passe à son propre clavier (U.S. ou ABC) et revient quand vous les quittez. Chaque fois que l'application dans laquelle vous tapez active la saisie sécurisée, AllInOneIME ne compose pas de texte : les touches passent telles quelles. Et tant que le système est en saisie sécurisée (champs de mot de passe, Entrée clavier sécurisée de Terminal, etc.), rien n'est envoyé à l'IA.
- `@note` et `@reminder` ne passent pas par l'IA : AllInOneIME ne remet le texte qu'à Notes et Rappels sur ce Mac, et interprète aussi l'heure du rappel sur le Mac (que ces applications le synchronisent avec vos autres appareils dépend de leurs comptes, comme iCloud). Elles fonctionnent donc aussi pendant une saisie sécurisée. `@note` vers un dossier écrit un fichier sur ce Mac (il est synchronisé si le dossier l'est, comme le serait un dossier iCloud Drive ou Obsidian Sync). `@note` vers Notion envoie la note à Notion (api.notion.com, avec le jeton de votre intégration, conservé dans le trousseau), et seulement à ce moment-là : pas pendant une saisie sécurisée.

Rien n'arrive sur GitHub tant que vous ne cliquez pas sur Submit là-bas.
- `@open` ne cherche que sur ce Mac. Elle mémorise ce que vous avez ouvert avec elle (les 200 derniers éléments), dans les préférences propres à la méthode de saisie (pas dans config.json), pour les lister en premier.
- Pour "Add App…" dans Settings → Apps, la méthode de saisie conserve les identifiants de bundle des 12 dernières applications dans lesquelles vous avez tapé, dans ses propres préférences ; rien d'autre à leur sujet.
- `@question` mémorise vos 5 dernières questions avec leurs réponses et le moment où elles ont été posées, uniquement sur ce Mac (sauf si vous choisissez de les synchroniser via iCloud, voir plus haut), dans `~/Library/Application Support/AllInOneIME/recent-questions.json` (lisible uniquement par votre compte utilisateur), pour les lister sous `@question` ; une réponse enregistrée est affichée depuis ce fichier sans aller en ligne. Rien n'est conservé pendant une saisie sécurisée, et les questions posées sur du texte sélectionné ne sont pas conservées du tout (leur réponse porte sur la sélection, qui se retrouverait sur le disque). Désactiver "Remember recent questions" dans Settings → General les supprime aussi ; la désactiver depuis Settings → Assistant (`rememberQuestions` dans la configuration) les conserve, pour que cela puisse être annulé exactement. "Clear" les supprime.
- Pour lister vos notes, le panneau de la barre des menus conserve l'identifiant (celui de la note dans Notes, le chemin du fichier ou l'adresse de la page Notion) et la première ligne (jusqu'à 80 caractères) des 30 dernières notes enregistrées avec `@note`, dans les préférences propres à la méthode de saisie, y compris quand le panneau est désactivé. Ouvrir le panneau n'interroge jamais Notion.
- `@py` et `@js` ne s'exécutent que lorsque vous appuyez sur la touche d'action, et uniquement sur du code que vous avez tapé ou collé vous-même : les réponses de l'IA et la sortie des autres commandes ne sont jamais exécutées comme du code. `@py` utilise le `python3` de votre Mac, qui peut lire et écrire des fichiers et accéder à Internet comme il le fait dans Terminal ; `@js` s'exécute dans un processus séparé qui ne peut ni lire de fichiers, ni accéder au réseau, ni lancer d'autres programmes. Aucune des deux ne s'exécute pendant une saisie sécurisée.
- Vérification des mises à jour : une fois par jour (sauf si "Check for updates automatically" est désactivé), AllInOneIME télécharge https://allinoneime.com/update.json et sa signature ; la requête ne contient aucun identifiant ni rien de ce que vous avez tapé. Une mise à jour n'est téléchargée, depuis la release GitHub, que lorsque vous cliquez sur Update.
- Sources d'extensions : git s'exécute sur votre Mac, sous votre compte, uniquement pour les sources que vous avez ajoutées : une récupération (fetch) par jour pour celles qui se vérifient d'elles-mêmes (aucune pour une source épinglée), et quand vous cliquez sur Check Now, Update ou Re-clone. Il ne communique qu'avec l'hôte du dépôt, authentifié par votre propre configuration git et SSH ; rien de ce que vous tapez ne l'accompagne.

## Développement

```sh
make test         # unit tests, plus tests that run the real Rime engine (and make strings-check)
make strings      # adds new interface text to Resources/Localizable.xcstrings, marks what's unused stale
make pack         # the Chinese language pack: build/packs/zh-pinyin-<version>.tar.xz, its sha256, its packs.json entry
make packs        # all the language packs: Chinese, and Korean and Hindi from Core/LanguagePacks/ (ko-hangul, hi-phonetic)
make selftest     # drives the input method through a simulated text field: real Bedrock calls
make realtest     # types into a real app's text field (needs the screen unlocked; takes over the foreground for about 1 minute)
make screenshots  # regenerates the screenshots in docs/
make cli && .build/release/allinoneime-cli --styles concise,jargon "this is a blocker bug your team need fix it asap"   # try polishing and rewrites in the terminal
make icon         # regenerates the app icon and the menu bar icon from Resources/AppIcon.png
make dmg          # the release installer, build/AllInOneIME-<version>.dmg (universal; needs the Developer ID certificate it's signed with and DIST_PROFILE, the provisioning profile; optionally notarized), and the in-app update, build/AllInOneIME-<version>-update.zip
make app PROFILE=<profile> SIGN_IDENTITY=<a certificate it lists>   # a build with the keychain entitlements: it can sync keys through iCloud Keychain
make update-test  # the in-app updater end to end: a temporary install, a test server on 127.0.0.1, a test key (never the installed app)
```

`make selftest` et `make realtest` ne dépendent pas de vos réglages. L'autotest utilise sa propre configuration (Amazon Bedrock avec le profil AWS et la région tirés de la vôtre, tout le reste par défaut) ; le test dans une vraie application règle le fournisseur sur Bedrock pendant qu'il s'exécute, puis remet le vôtre. Ce qu'ils ne peuvent pas vérifier sur le moment est ignoré, pas compté comme un échec : les vérifications Bedrock en direct sans identifiants pour ce profil, et tout ce qui se tape pendant que la saisie sécurisée est active (écran verrouillé, champ de mot de passe). La dernière ligne compte les vérifications réussies, échouées et ignorées ; seuls les échecs font échouer l'exécution, et une exécution avec des vérifications ignorées se termine par INCOMPLETE, ou par SKIPPED quand rien de ce qui tape ne s'est exécuté (BLOCKED : le test dans une vraie application a démarré sur un écran verrouillé), jamais par PASSED.

Les textes de l'interface s'écrivent `tr("中文", "English")` : le chinois simplifié et l'anglais viennent du code, les autres langues des String Catalogs, `Core/Resources/Localizable.xcstrings` pour les textes du core et `Resources/Localizable.xcstrings` pour ceux de l'application (fusionnés et compilés dans chaque application par le Makefile avec `xcstringstool` de Xcode), indexés par le texte anglais avec `%@` pour chaque interpolation. Après avoir ajouté ou modifié du texte, exécutez `make strings` (`make test` échoue d'ici là ; les textes des autotests, dans `*SelfTest.swift`, ne sont pas destinés aux traducteurs). Quand un même texte anglais a deux sens (`make strings` les signale, et `make strings-check` échoue dessus), donnez à l'un une clé à lui, un nom court à points qui dit où ou comment il est utilisé : `tr("删除", "Remove", key: "remove.delete")` ; son anglais est la valeur anglaise de la clé dans le catalogue. Ajouter une langue, c'est ajouter sa colonne au catalogue : les traductions relues, un fichier JSON par langue (`"core\t<key>"` ou `"app\t<key>"` → sa traduction), y entrent avec `Scripts/import-translations.py <folder>`, qui ne touche jamais à l'anglais et refuse une traduction dont les espaces réservés ne sont pas ceux de sa clé. Les textes propres au core prennent le code de la langue de l'interface et se cherchent de la même façon (`InterfaceText.lookup`, que chaque application définit : ses bundles `.lproj` sur macOS ; ailleurs, `StringCatalog` lit les tables du catalogue).

Organisation du code : la racine est l'application macOS ; `Core/` est le core que partagent toutes les plateformes, un package Swift à part entière (il se compile et se teste seul, sur macOS, Linux et Windows) ; `Windows/` est le début de l'application Windows.

- `Core/Sources/AllInOneIMECore` : client Bedrock, SigV4, prompts, la machine à états de saisie à deux niveaux (y compris les commandes @) ; aucune dépendance à AppKit
- `Core/Sources/AllInOneIMEText` : les textes de l'interface et leur langue (`UIString`, `InterfaceText`, `InterfaceLanguage`, et `StringCatalog`, qui lit le catalogue là où il n'y a pas de bundles `.lproj`) ; tous les liens qui ouvrent des réglages (`AllInOneIMECore` le réexporte)
- `Core/Sources/AllInOneIMEQuickJS` : QuickJS-ng (ses sources C dans `Core/Sources/CQuickJS`), le JavaScript des plugins et de `@js` là où il n'y a pas JavaScriptCore (Windows, Linux, Android)
- `Core/Sources/AllInOneIMERime` : enveloppe de librime
- `Core/Sources/AllInOneIMECLI` : la ligne de commande, `allinoneime-cli` (`make cli`), lancée par le `main` propre à chaque plateforme
- `Sources/AllInOneIMEMac` : ce que seul le Mac possède (dispositions de clavier, signature du code, Spotlight, AppleScript, l'installation des mises à jour), et `Platform.mac`
- `Sources/AllInOneIME` : la méthode de saisie InputMethodKit, le panneau des candidats, la fenêtre des réglages
- `Sources/AllInOneIMESettings` : le lanceur "AllInOneIME Settings"
- `Sources/AllInOneIMEInstaller` : "Install AllInOneIME" sur l'image disque : installe, met à jour et désinstalle

Les packs de langue ont leur propre bibliothèque, distincte de celle des plugins : le dépôt [MicroZ-LLC/AllInOneIME-languages](https://github.com/MicroZ-LLC/AllInOneIME-languages), servi à l'adresse https://languages.allinoneime.com/, signé avec sa propre clé. `make pack` construit l'archive ; elle y est publiée comme fichier de release (release `zh-pinyin-<version>`, `ko-hangul-<version>`, `hi-phonetic-<version>`), et `swift Scripts/build-packs-index.swift <languages repo> build/packs/*.tar.xz.json` y écrit `packs.json` et le signe dans `packs.json.sig` avec la clé des packs de langue tirée du trousseau (`allinoneime-languages-signing`). L'application lit https://languages.allinoneime.com/packs.json, vérifie la signature, puis la taille et le SHA-256 de l'archive. Pour essayer un pack depuis un serveur local : `--test-key` signe avec une clé de test, puis `AllInOneIME --install-pack zh-pinyin --library http://127.0.0.1:8765/ --key <its public key> --packs-dir <folder>`.

Publier une version (le système de mise à jour intégré lit https://allinoneime.com/update.json, signé avec la clé propre aux publications) :

1. Augmentez le numéro de version (`AppVersion.swift` et les trois Info.plist ; `AppVersionTests` vérifie qu'ils concordent) et mettez à jour les journaux des modifications.
2. `make dmg NOTARY_PROFILE=<profile>` : `build/AllInOneIME-<version>.dmg` avec son `.sha256`, et `build/AllInOneIME-<version>-update.zip` (les deux applications, telles que l'installeur de l'image disque les contient). Les applications et l'image sont signées avec le certificat Developer ID Application du trousseau, et l'image est notariée avec ce profil de trousseau `xcrun notarytool`, puis agrafée (stapled). La méthode de saisie porte le profil de provisionnement Developer ID (`Resources/Signing/AllInOneIME-DeveloperID.provisionprofile`, `DIST_PROFILE`), qui lui accorde ses droits d'accès au trousseau (entitlements) ; le build s'arrête si le profil ne liste pas le certificat de signature, ne couvre pas tous les appareils ou expire dans moins de 30 jours (`Scripts/profile-entitlements.sh`), ou si la signature n'a pas ces droits, et il lance une fois la méthode de saisie signée (macOS tue celle dont le profil ne convient pas). Un `DIST_PROFILE` vide l'arrête aussi : une version publiée sans ces droits ne verrait plus aucune des clés passées dans le trousseau iCloud. Le profil ne liste que les deux certificats Developer ID G1 : avant de signer avec un autre (G2), créez dans le portail des développeurs (à la main : la signature de l'App ID n'est pas laissée à Xcode) un nouveau profil qui le liste, et validez-le (commit).
3. Envoyez les deux dans la release GitHub `v<version>` et publiez-la.
4. `make update-manifest UPDATE_SUMMARY_EN="…" UPDATE_SUMMARY_ZH="…"` (une phrase ou deux chacun) : écrit `site/public/update.json` (la version, le build et la version minimale de macOS lus dans les applications, l'adresse, la taille et le SHA-256 du fichier, l'adresse des notes de version et le résumé) et le signe dans `update.json.sig` avec la clé du trousseau de session (`allinoneime-releases-signing` ; macOS peut demander d'autoriser l'accès). Validez (commit) les deux.
5. Déployez le site (`cd site && npx wrangler@4 deploy`), seulement une fois que les fichiers de la release se téléchargent : les applications vérifient une fois par jour, et `AllInOneIME --check-update` montre ce qu'elles voient.

L'application vérifie la signature du manifeste avec la clé publique qu'elle contient avant de le lire, n'installe jamais une version qui n'est pas plus récente, ne télécharge qu'en https depuis allinoneime.com ou les fichiers des releases GitHub du dépôt, et n'installe l'archive qu'une fois que sa taille et son SHA-256 correspondent au manifeste, que les identifiants de bundle, les versions et les signatures de code des deux applications sont corrects et que la nouvelle méthode de saisie démarre. La méthode de saisie passe ensuite la main à son propre exécutable comme assistant (`--apply-update`), qui attend qu'elle se ferme, échange les applications comme le fait l'installeur (les anciennes mises de côté, remises en place si quelque chose échoue) et enregistre la nouvelle. Pour essayer avec un serveur local : `make update-test`, ou `--test-key` avec `Scripts/build-update-manifest.swift` et `AllInOneIME --install-update --manifest-url http://127.0.0.1:<port>/update.json --key <its public key> --target-dir <folder>`.

L'identifiant de bundle est toujours `com.aipinyin.inputmethod.AIPinyin` : macOS s'en sert pour mémoriser la source de saisie ajoutée et les autorisations qui lui ont été accordées, donc le changer obligerait à rajouter la méthode de saisie et à les accorder de nouveau.
