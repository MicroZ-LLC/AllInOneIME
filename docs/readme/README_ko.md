# AllInOneIME

### Mac의 모든 텍스트 필드에서 AI 명령어를.

어떤 앱에서든 `@improve`, `@translate`, `@question`을 입력하고 ⏎를 누른 뒤 결과를 고르세요.<br>
채팅 창에 복사할 필요도, 앱을 전환할 필요도 없습니다. AI 제공업체도 키도 모두 여러분의 것을 씁니다.

AllInOneIME는 [GitHub Releases](https://github.com/MicroZ-LLC/AllInOneIME/releases) 또는 [allinoneime.com](https://allinoneime.com)에서만 내려받으세요.

모든 텍스트 필드에서 AI 명령어를 쓸 수 있는 macOS 입력기입니다. 문장을 `@`로 시작하고, 다 쓰면 ⏎를 누르세요. `@improve`는 쓴 글을 다듬고 몇 가지 다시 쓰기를 제안하고, `@translate`는 고른 언어로 번역하고, `@question`은 질문을 하고, `@agent`는 코딩 에이전트(Claude Code, Gemini CLI, Kiro CLI …)에 넘기고, `@open`은 파일과 앱을 찾거나 웹 주소를 엽니다. 오른쪽 ⌥를 누른 채 말할 수도 있습니다. `@`가 없으면 키 입력은 평소처럼 앱으로 갑니다. 중국어(병음, Rime과 rime-ice 기반), 프랑스어, 한국어(한글), 힌디어(라틴 문자로 데바나가리 입력)도 입력할 수 있고, 직접 만든 스크립트를 @ 명령어로 실행할 수도 있습니다.

![@improve와 다듬지 않은 문장을 입력하고 ⏎: 다듬은 버전과 다시 쓰기](../en/improve.png)

자세한 내용(모든 명령어와 설정, 설치 문제 해결, 개인정보 보호)은 [Wiki](https://github.com/MicroZ-LLC/AllInOneIME/wiki)를 참고하세요. MicroZ LLC의 [Weijian Zhang](https://weijianz.com)이 만들었습니다.

## 사용 방법

`@`가 없으면 방해하지 않습니다. 영어에서는 글자가 그대로 입력되고 ⏎는 Return입니다. 아무것도 온라인으로 전송되지 않습니다. 새로 설치하면 영어만 입력합니다. 중국어(병음), 프랑스어, 한국어, 힌디어도 입력하려면 설정에서 추가하세요([입력과 번역](#입력과-번역) 참고).

| 키 | 동작 |
|---|---|
| 병음 입력, Space / 숫자 | 중국어 모드: 일반 병음 입력기처럼 단어를 고릅니다 |
| `@`(문장 맨 앞에서) | 명령어 목록을 엽니다. 최근에 많이 쓴 것이 먼저 나오고, 한 번에 5개씩, ↑↓, 스크롤 휠, 트랙패드로 스크롤합니다. 글자를 입력해 찾을 수도 있습니다(전부 입력한 이름이 먼저, 그다음 그 글자로 시작하는 이름, 그다음 그 글자를 포함하는 이름). ⏎, Tab, Space, 숫자 키로 선택합니다 |
| ⏎ | 명령어를 실행합니다. 병음을 아직 고르지 않았어도 됩니다. Space를 누를 때처럼 먼저 골라집니다 |
| Space, ⏎ / 숫자 | 결과가 나타나면: 강조된 결과 / 해당 번호의 결과를 삽입합니다. 0은 원문입니다. 후속 입력을 쓰다 말았어도 ⏎는 삽입합니다(쓰던 내용은 버려집니다) |
| ⇧⏎ | AI 결과 뒤에 후속 입력을 했을 때: 그것을 보냅니다(`@question` 대화의 다음 질문, 또는 다듬기). 명령어를 입력하는 중이거나, AI 결과에서 아무것도 입력하지 않았을 때: 입력한 그대로, `@command`까지 포함해 삽입합니다. 다른 결과(`@open`, 미리 알림 …)에서는 ⏎처럼 강조된 행을 삽입합니다 |
| ⌘C | 강조된 결과를 복사합니다(`@open`에서는 경로). 후보 패널은 열린 채로 있습니다 |
| ⌃V | 명령어 안에서(예: `@improve ` 뒤): 클립보드 텍스트를 앱에 붙여 넣는 대신, 입력한 내용 뒤에 덧붙입니다. 여러 줄은 한 줄로 합쳐지며, 한 번에 최대 2000자입니다(`@note`는 줄바꿈을 유지하며 최대 20000자). 어떤 앱에서든 작동하며, 명령어가 없으면 키는 평소처럼 앱으로 갑니다 |
| ⌘V | ⌃V와 같지만, ⌘V를 직접 처리하는 앱(Ghostty, iTerm2, Terminal 같은 터미널과 Notes)에서는 평소처럼 앱에 붙여 넣습니다. 그런 앱에서는 ⌃V를 쓰세요 |
| Esc, ⌫ | 문장으로 돌아가 계속 편집합니다. 결과가 나온 뒤 문장 부호나 숫자를 입력하면 문장을 이어 씁니다. 다듬은 뒤에는: 그 전의 결과로 돌아갑니다 |
| AI 결과가 나온 뒤 입력하는 글자 | 후속 입력입니다. `@question` 뒤에서는 다음 질문([대화](#question으로-대화하기-신규) 참고), `@improve`나 프롬프트 명령어 뒤에서는 `shorter` 같은 지시([결과 다듬기](#결과-다듬기-신규) 참고)이며, ⇧⏎로 보냅니다. `@translate` 뒤에서는 글자가 문장을 이어 쓰고, ⏎를 누르면 다시 번역합니다 |
| ⌘⏎, ⌘1–⌘9 | `@question` 대화에서: 이어서 할 수 있는 곳(설치된 코딩 에이전트, `@agent`가 넘기는 에이전트가 먼저; Claude, ChatGPT, Gemini; 또는 복사)을 보여 줍니다. ⌘1, ⌘2 …로 하나를 고릅니다 |
| 행 클릭 | 후보 패널에서: 그 행의 숫자 키를 누른 것처럼 선택합니다(단어, 목록의 명령어, 결과, `@open` 파일, 받는 사람, 확장의 행). 포인터 아래의 행이 강조됩니다. 텍스트 필드는 포커스를 유지합니다 |
| Shift 가볍게 누르기 | 입력 언어가 둘 이상일 때: 순서대로 다음 언어로 바꿉니다(영어 → 중국어 → 프랑스어 → …, 그다음 다시 처음으로) |
| 오른쪽 ⌥ 누르고 있기 | 말하고, 떼면 멈춥니다. 입력 중인 언어(영어, 중국어, 프랑스어, 한국어, 힌디어)로 인식합니다. 명령어 안에서는 텍스트가 그 뒤에 들어가고, 그렇지 않으면 바로 삽입됩니다 |

## @ 명령어 (베타)

| 명령어 | 동작 |
|---|---|
| `@improve` | 다듬기: 1–3은 문장 원래 언어로 된 세 가지 버전, 4부터는 다시 쓰기 스타일(설정에서 추가하고 순서를 정함), 0은 원문입니다. 번역은 하지 않습니다. "@improve also translates"(@improve에서도 번역)를 켜면 `@translate @improve`처럼 작동합니다 |
| `@translate` | 추가한 언어로 번역합니다(설정 → "Translate", 드래그로 순서 변경). 언어마다 한 줄이며, 언어가 하나뿐이면 세 가지 버전입니다. 문장 원래 언어는 건너뜁니다. `@translate @improve`를 함께 쓰면 한 번의 요청으로 번역과 다시 쓰기를 합니다 |
| `@question` | 질문합니다. 답은 후보에 나타나며, ⏎ 또는 Space로 삽입하고 ⌘C로 복사합니다. 계속 입력하고 ⇧⏎를 누르면 후속 질문을 합니다. 패널이 최대 5회차의 대화가 되고, 그다음에는 Claude나 다른 AI에서 이어 가자고 제안합니다. 뒤에 아무것도 입력하지 않으면 최근 질문 5개를 최신순으로 보여 줍니다. 입력하면 범위가 좁혀집니다(질문 안 어디에 있는 단어든, 대소문자 구분 없이, 중국어도). 숫자 키, ↑↓ 후 ⏎, 또는 클릭하면 그 질문의 저장된 답을 오프라인으로 바로 보여 주며, 평소처럼 삽입하거나 복사할 수 있습니다. 거기서 ⌘R을 누르면 다시 질문해 새 답을 받습니다. 일치하는 것이 없거나 아무것도 고르지 않으면 ⏎는 입력한 내용을 질문합니다 |
| `@reply` | 답장하려는 메시지에 대한 답장을 세 가지 씁니다. 상대방의 언어로, 앱에 맞는 어조로 씁니다(Settings → Apps에서 그 앱의 첫 번째 다시 쓰기 스타일, 없으면 채팅 앱에서는 편하게, 메일에서는 격식 있게 쓰며, 메일에서는 답장마다 이메일 본문 전체가 됩니다). 메시지는 선택하거나, 복사한 뒤 작성 중인 칸에서 ⌃V를 누르거나, 스크린샷을 찍고(⌃⇧⌘4 또는 WeChat 자체 스크린샷) ⌃V를 눌러 건넵니다. 뒤에 입력한 내용은 어떻게 답할지를 정합니다: `@reply politely decline`. ⌘R은 세 개를 더 씁니다. [@reply로 답장하기](#reply로-답장하기-신규) 참고 |
| `@agent` | 작업을 Mac의 코딩 에이전트에 넘깁니다. 에이전트는 Settings → Agent에서 고릅니다: Claude Code(기본값), Gemini CLI, Kiro CLI, 또는 직접 만든 명령(입력한 내용이 마지막 인수로 붙습니다). 이 페이지에는 각 에이전트가 설치되어 있는지, 어떻게 시작하는지도 표시됩니다. Claude Code는 기본적으로 백그라운드에서 실행되며 끝나면 알림을 보내고(알림을 클릭하면 Terminal에서 세션을 열어 이어 갈 수 있음), `@tasks`에서도 볼 수 있습니다. 그 페이지의 Claude Code 아래에 있는 "Runs in the background and notifies me"(백그라운드에서 실행하고 끝나면 알림)를 끄면 Terminal에서 엽니다. 다른 에이전트는 Terminal에서 열리며, 입력한 내용이 첫 메시지가 됩니다. 각 에이전트는 자체 로그인과 설정을 씁니다. Google Chrome에서는 페이지를 함께 가져갑니다. 주소와 제목, 입력한 필드와 그 필드가 속한 양식이나 섹션(★가 현재 위치를 표시), 선택한 텍스트, 창에 보이는 내용이며, 암호 필드나 페이지 전체는 절대 가져가지 않습니다. 그래서 로그인 양식의 사용자 이름 필드에서 `@agent why doesn't this work`라고 하면 그 필드에 관한 것이 되고, 파이프라인 페이지에서 `@agent why is this blocked`라고 하면 그 페이지에 관한 것이 됩니다. 어느 쪽인지는 에이전트가 판단합니다. 페이지의 텍스트는 읽은 그대로, 웹에서 온 것으로 표시되어(사용자의 지시가 아니라) 에이전트에 전달됩니다. 손쉬운 사용 권한이 필요합니다. Chrome은 그곳에서 `@agent`를 쓰는 동안에만 이를 위한 페이지 트리를 만들고 끝나면 다시 끕니다(Settings → Agent → "@agent and @reply take the Chrome page along"(@agent와 @reply가 Chrome 페이지를 함께 가져감)으로 모두 끌 수 있습니다). 처음 Terminal을 열 때 macOS가 AllInOneIME가 Terminal을 제어해도 되는지 묻습니다. "확인"을 클릭하세요. (0.6.4 이전에는 `@claude`였습니다.) |
| `@tasks` | 백그라운드 Claude 작업(진행 중 / 완료 / 응답 대기)과 각각의 마지막 답장을 나열합니다. ⏎는 Terminal에서 열고, ⌘C는 답장을 복사합니다 |
| `@settings` | 설정 창을 바로 엽니다(고르기만 하면 됩니다) |
| `@open` | 입력하는 대로 일치하는 파일, 폴더, 앱을 나열합니다(Spotlight). 공백으로 구분해 여러 키워드를 쓸 수 있습니다. 각 키워드는 경로에 있어야 하고, 적어도 하나는 이름에 있어야 합니다(표준 폴더의 이름은 그 안의 항목에도 적용됩니다. `downloads pdf`는 Downloads(다운로드) 안의 PDF를 찾습니다). 앱과 표준 폴더는 중국어 이름으로도 찾을 수 있고, 중국어 인터페이스에서는 그 이름으로 표시됩니다. `@open`으로 연 항목이 먼저 나오고, 그다음 앱과 그 폴더들, 그다음 최근에 사용하거나 변경한 파일이 나옵니다. 이름으로 찾은 파일이 두 개 이하이고 해당하는 앱이나 그 폴더가 없으면, 홈 폴더의 파일을 내용으로도 검색하며 그 행에는 "content"(내용)라고 표시됩니다. 그 밖에 아무것도 없으면, ⏎는 첫 항목을 여는 대신 그것들을 나열해 고를 수 있게 합니다. 웹 주소(`github.com`, `localhost:3000`, `https://…`)를 입력하면 첫 행은 "open in the browser"(브라우저에서 열기)이고 내용은 검색하지 않습니다. 정확히 그 이름의 파일(예: `MANIFEST.in`)이 있으면 그것이 먼저 나옵니다. `~/`나 `/`로 시작하는 텍스트는 경로입니다. Tab은 경로를 완성하며 폴더 안으로 들어가고, ⏎는 열고, ⌘C는 경로를 복사합니다 |
| `@note` | 텍스트를 Notes 앱의 AllInOneIME라는 폴더(없으면 만듦)에 저장하거나, Settings → Plugins → Notes (@note)에서 정한 곳에 저장합니다: Notion, 또는 Markdown 파일 폴더(Obsidian 보관소나 아무 폴더). 아무것도 삽입되지 않습니다. 붙여 넣은 텍스트는 줄바꿈을 유지하며 최대 20000자입니다 |

`@john`처럼 `@` 뒤에 명령어가 오지 않으면 `@`가 평소처럼 입력되므로, 채팅 앱에서 사람을 @멘션하는 것도 그대로 됩니다. 글자, 숫자, `.`, `_`, `-` 바로 뒤에 입력한 `@`는(`bob@example.com`이나 `ssh user@host`처럼) 그냥 텍스트입니다. 목록이 열리지 않으며, 터미널을 포함해 모든 앱에서 그렇습니다. 목록이 열려 있을 때 ← →나 명령어 이름에 들어갈 수 없는 키(`.`, `:`, `/`)를 누르면 목록이 닫히고 입력한 내용(`@`, `@im`)은 그대로 남습니다. 터미널에서는 이때 ← →가 목록만 닫습니다. `@question`, `@improve`, `@translate`, `@reply`는 실행 키를 눌렀을 때만 여러분의 Bedrock으로 보냅니다(스크린샷은 이 Mac에서 읽고 그 텍스트만 보냅니다). `@open`은 이 Mac에서만 검색합니다. `@note`와 `@reminder`는 이 Mac의 Notes와 Reminders로만 갑니다(`@note`는 폴더나 Notion을 골랐다면 그곳으로 갑니다). `@agent`는 Mac에 설치된 에이전트(기본값은 Claude Code의 `claude` 명령어)와 그 계정을 사용하며, 파일을 바꾸거나 명령어를 실행하기 전에 평소처럼 먼저 묻습니다. 그 에이전트가 설치되어 있지 않으면 `@agent`는 제공되지 않습니다. `@imessage`는 이 Mac의 Contacts(이름, 전화번호, 이메일)만 읽으며, AI를 거치지 않고, 메시지는 Messages가 보냅니다. Messages 앱이 없으면 제공되지 않습니다.

### 선택한 텍스트에서 (신규)

아무 앱에서나 텍스트를 선택하고(메모의 한 문장, Mail의 한 단락), `@improve`, `@translate`, `@question` 또는 텍스트를 받는 다른 명령어를 입력한 뒤 ⏎를 누르세요. 명령어가 선택 영역을 대상으로 동작하고, 고른 결과가 선택 영역을 대체합니다. 입력하는 동안 선택 영역은 그대로, 선택된 채로 남습니다. 명령어는 후보 패널에 적히며, 첫 줄은 입력하는 내용이고 다음 줄은 "On the selection: “…” (N characters)"(선택 영역에 대해: N자)입니다. Esc, ⇧⏎, 다른 곳 클릭은 텍스트를 원래대로 둡니다. 그사이 선택 영역을 바꿔도 마찬가지이며, 명령어는 취소됩니다. 명령어 뒤에 입력한 텍스트는 `@improve`와 `@translate`에서는 지시(`@translate ja`, `@improve more formal`), `@question`에서는 선택 영역에 대한 질문(`@question what does this mean`)이 됩니다. `@open`, `@agent`, `@tasks`, `@settings`, `@reminder`, `@imessage`, `@reportissue`, 터미널 명령어, 스크립트 확장은 선택 영역을 쓰지 않습니다. 이들은 입력한 내용만 받고, 선택 영역은 그대로 남습니다. 최대 5000자이며, 보안 입력 중이거나 터미널에서는 절대 읽지 않습니다. 어떤 앱에서 제대로 동작하지 않으면 Settings → General → "Use the selected text"(선택한 텍스트 사용)에서 끄세요.

### @reply로 답장하기 (신규)

`@reply`는 답장하려는 메시지에 보낼 만한 답장을 세 가지 씁니다. 다음 중 한 가지 방법으로 메시지를 건넨 뒤 ⏎를 누르세요:

- 필드에서 메시지를 **선택**하고 `@reply`를 입력합니다(고른 답장은 그 뒤에 별도의 줄로 들어갑니다).
- 메시지를 **복사**하고 `@reply`를 입력한 뒤 ⌃V를 누릅니다. 패널에 "Copied message · N characters"(복사한 메시지 · N자)가 표시되고, 작성 중인 글은 그대로 남습니다.
- 클립보드로 **스크린샷을 찍고**(⌃⇧⌘4 또는 WeChat 자체 스크린샷) `@reply`를 입력한 뒤 ⌃V를 누릅니다. 패널에 "Screenshot · N lines (read on this Mac)"(스크린샷 · N줄, 이 Mac에서 읽음)이 표시됩니다. 스크린샷은 이 Mac에서 읽고(Apple의 Vision. 처음에는 조금 느림) 그 텍스트만 보냅니다. 이미지는 어디로도 가지 않고 보관되지도 않습니다. 채팅 앱에서 보이는 대로 왼쪽 줄은 상대방의 메시지, 오른쪽 줄은 내 메시지로 보며, 메시지 사이의 시각은 뺍니다. 다른 방법으로는 창을 읽을 수 없는 WeChat에서 쓰세요.

하고 싶은 말을 뒤에 쓰거나(`@reply politely decline`, `@reply 委婉拒绝`), 아무것도 쓰지 않으면 적절한 답장을 씁니다. 답장은 다른 언어를 요청하지 않는 한 상대방의 언어로, 앱에 맞는 어조로 씁니다. 그 앱 프로필의 첫 번째 다시 쓰기 스타일(Settings → Apps), 없으면 채팅 앱에서는 편하게, 메일 앱에서는 격식 있게 쓰며, 메일에서는 답장마다 이메일 본문 전체가 됩니다. 커서 주변의 텍스트도 함께 갑니다. `@reply` 뒤에 아무것도 입력하지 않은 상태에서 ⌫를 누르면 붙여 넣은 것이 지워집니다. ⏎나 숫자 키로 답장을 삽입하고, ⌘R은 세 개를 더 씁니다(Esc를 누르면 앞의 답장이 다시 나옵니다). 지시를 입력하면 다른 AI 결과처럼 다듬을 수 있습니다. Google Chrome에서 아무것도 선택하거나 붙여 넣지 않았으면 `@agent`처럼 페이지를 함께 가져갑니다(Settings → Agent → "@agent and @reply take the Chrome page along"). 답장할 대상도 없고 입력한 것도 없으면 무엇이 필요한지 알려 줍니다. 민감한 정보 숨기기는 스크린샷의 텍스트에도 적용됩니다. 보안 입력 중에는 클립보드를 읽지 않고 아무것도 보내지 않습니다. `reply`라는 이름으로 만들어 둔 사용자 지정 명령어는 이제 `@myreply`입니다.

스크린샷은 다른 명령어에 붙여 넣어도 됩니다. `@translate` 뒤에서 ⌃V를 누르면 번역해 커서 위치에 넣고, `@question what does this say` 뒤에서 ⌃V를 누르면 그 내용에 대해 질문하며, AI를 쓰지 않는 명령어는 텍스트를 복사한 것처럼 받습니다(`@note`는 줄을 유지합니다). 텍스트를 선택한 상태에서는 `@improve`와 `@translate`가 계속 선택 영역을 대상으로 동작하고, 스크린샷을 쓰지 않았다고 알려 줍니다.

### 결과 다듬기 (신규)

`@improve`, 프롬프트 명령어(직접 만든 것 또는 플러그인의 것), 또는 선택 영역 다시 쓰기의 결과가 나와 있는 동안 바꿀 점을 입력하세요. 예를 들어 `shorter`, `warmer`, `more formal`, `add a joke`, `in Japanese`, `用更口语的说法` 같은 것입니다(병음도 되고, Shift를 가볍게 누르면 언어가 바뀝니다). ⇧⏎를 누르면 결과가 지시와 함께 다시 AI로 가고, 새 결과가 같은 패널에서 기존 결과를 대체합니다. ⏎는 선택된 결과를 삽입하며, 지시를 쓰다 말았어도 마찬가지입니다(쓰던 지시는 버려집니다). 원하는 만큼 다시 다듬을 수 있습니다. 패널 맨 위 줄에 단계가 나열되고("Refined: shorter · more formal"), 언제든 평소처럼 행을 고를 수 있습니다. 글자를 입력하면 지시가 시작됩니다(패널 위쪽에 "refine › …"로 표시). 지시가 비어 있는 동안에는 숫자 키, Space, ⏎가 전처럼 선택에 쓰이고, ⇧⏎는 입력한 그대로 삽입합니다. 다듬기는 결과가 모두 나온 뒤에 시작됩니다. 첫 결과가 아직 들어오는 동안 입력하면 전처럼 문장을 이어 씁니다. 다듬기가 진행되는 동안에도 다음 지시를 미리 입력할 수 있습니다. 다듬기는 계속 진행되고, 그 결과가 들어오면 ⇧⏎로 다음 다듬기를 실행합니다. Esc는 지시를 지우고, 그다음 마지막 다듬기 전의 결과로 한 단계 돌아가며(다듬기 중이면 멈추고), 그다음 문장으로 돌아갑니다. 빈 줄에서 ⌫를 눌러도 같은 방식으로 돌아갑니다. 선택한 텍스트에서는 고른 결과가 여전히 정확히 선택 영역만 대체하며, 그때까지 선택 영역은 건드리지 않습니다. 실패한(또는 보안 입력 중에 거부된) 다듬기는 결과를 그대로 두고, 그 지시는 ⇧⏎로 다시 시도할 수 있게 남겨 둡니다. 같은 결과에 대한 같은 다듬기는 캐시에서 답합니다. `@translate`에는 다듬기가 없습니다. 결과 뒤에 입력하면 문장을 이어 쓰고, ⏎를 누르면 다시 번역합니다.

### @question으로 대화하기 (신규)

`@question`이 답한 뒤에 입력하는 내용은 다음 질문이 됩니다. ⇧⏎를 누르면 지금까지의 질문과 답을 함께 붙여 질문하고, 패널은 대화 형태로 커집니다. 이전 회차는 흐리게 Q / A 행으로, 최신 답은 그 아래에 표시됩니다. 맨 위 줄은 다음이 몇 번째 회차인지 알려 줍니다("question 2/5 › …"). 어느 답이든 삽입할 수 있습니다. 해당 숫자(1–5), ↑↓ 후 ⏎, 또는 클릭입니다. 최신 답이 선택되어 있고, ⌘C는 선택된 답을 복사합니다. 질문을 쓰다 말았어도 ⏎는 답을 삽입합니다(쓰던 질문은 버려집니다). Esc는 입력한 내용을 지우고, 그다음 한 회차 돌아갑니다. 첫 회차에서는 전처럼 빠져나갑니다. 패널은 화면의 절반쯤까지 커진 뒤 스크롤되며, 최신 내용이 맨 아래에 옵니다.

5회차가 지나면(설정 파일의 `questionRounds`, 2–10) 다음 질문 줄이 "5 rounds in: continue in Claude or another AI"(5회차 진행: Claude나 다른 AI에서 이어 가기)로 바뀌고, 선택지에 ⌘1, ⌘2 … 번호가 붙습니다. ⌘⏎를 누르면 어느 회차에서든 선택지를 볼 수 있습니다(답이 아직 들어오는 중이면 아무것도 하지 않으며, 앱으로 전달되지도 않습니다). 이때 입력하는 내용은 그곳에서의 첫 메시지가 되며, ⌘1, ⌘2 …만 그것을 보냅니다(⇧⏎는 더 이상 질문하지 않고 아무것도 열지 않습니다). 선택한 텍스트에 대한 질문은 그 텍스트를 별도의 인용 블록으로 함께 가져갑니다. 선택지:

- 이 Mac에 **설치된 코딩 에이전트**, 각각 그 이름으로 표시됨: `@agent`가 넘기는 에이전트가 먼저(⌘1), 그다음 나머지(Claude Code, Gemini CLI, Kiro CLI, Settings → Agent에서 정한 직접 만든 명령). 각각 Terminal에서 대화형 세션을 열고, `@agent`가 시작하는 방식대로 시작해 대화 내용과 "Let's continue this discussion"으로 시작합니다. 설치되지 않은 것은 표시되지 않습니다.
- 웹의 **Claude** 또는 **ChatGPT**, 대화가 채워진 상태로 열립니다(긴 대화는 클립보드로 가니 붙여 넣으세요).
- 웹의 **Gemini**, 대화는 클립보드에 있으니 붙여 넣습니다.
- **Copy the conversation**(대화 복사), Markdown 형식(**Q:** / **A:**)입니다.

어떤 것을 어떤 순서로 보여 줄지(첫 번째가 기본값): Settings → General → "Continue a conversation in"(대화를 이어 갈 곳, 설정 파일의 `questionContinueIn`). 5개를 넘으면 나머지는 ⌘6 … ⌘9로 고릅니다. 거기의 "@agent's agent"(@agent의 에이전트)는 Settings → Agent에서 고른 에이전트이며, 그 이름으로 표시됩니다. 지금 설치되어 있지 않은 에이전트도 목록을 편집할 때 제자리를 유지합니다. 이 Mac의 Apple Intelligence를 쓰면 긴 대화는 작은 컨텍스트에 다 들어가지 않습니다. 가장 오래된 답부터 줄이고, 그다음 가장 오래된 회차를 빼며, 패널에 "earlier rounds shortened"(이전 회차 줄임)라고 표시합니다. 대화는 첫 질문으로 최근 질문에 저장되며, 고르면 이어 갈 수 있도록 각 회차가 표시됩니다.

### 최근 질문 (신규)

뒤에 아무것도 입력하지 않은 `@question`은 최근 질문 5개를 최신순으로, 질문한 시각("3 hours ago")과 함께 보여 줍니다. 입력하면 범위가 좁혀집니다. 각 단어가 질문 안 어디에 있든, 대소문자 구분 없이 찾습니다(띄어쓰기 없는 중국어도). 숫자 키, ↑↓ 후 ⏎, 또는 클릭하면 그 질문의 저장된 답을 온라인에 접속하지 않고 바로 보여 줍니다. Space 또는 ⏎로 삽입, ⌘C로 복사, ⌘R로 다시 질문해 새 답 받기(대화라면 마지막 질문), Esc로 목록으로 돌아갑니다. 저장된 대화는 모든 회차를 보여 주며, 입력하면 이어서 대화할 수 있습니다. 일치하는 것이 없거나 아무것도 고르지 않으면 ⏎는 입력한 내용을 질문합니다. 같은 질문에 대한 새 답이나 이어진 대화는 저장된 것을 대체합니다.

- 질문은 이 Mac에만 보관됩니다(개인정보 보호 참고). 보안 입력 중에는 보관하지 않고, 선택한 텍스트에 대한 질문은 절대 보관하지 않습니다.
- Settings → General → "Remember recent questions"(최근 질문 기억)로 끌 수 있습니다(설정 파일의 `rememberQuestions`). 거기서 끄면 질문도 삭제됩니다. Settings → Assistant로 끄면 질문이 남아 있어서, 되돌리면 정확히 이전 상태로 돌아갑니다(미리 보기에도 그렇게 표시됩니다). "Clear (N)"(지우기)는 질문을 삭제합니다.

### 메모와 미리 알림

`@note`는 새 메모를 만들며, 첫 줄이 제목이 됩니다. 텍스트를 복사한 뒤 `@note ` 다음에 ⌃V(터미널 밖에서는 ⌘V도 가능)를 누르면 줄바꿈까지 함께 저장되며, 줄바꿈은 명령어 안에서 ↵로 표시됩니다. 저장 위치는 Settings → Plugins → Notes (@note) → "Save to"(저장 위치)에서 정합니다:

- **Notes**(이전과 같음): AllInOneIME 폴더에 새 메모를 만듭니다.
- **Folder (Obsidian or any)**(폴더, Obsidian 또는 아무 폴더): 고른 폴더에 메모마다 새 Markdown 파일을 만들며, 파일 이름은 첫 줄을 따릅니다(`/\:*?"<>|#^[]`는 `-`가 되고, 이미 있는 이름에는 " 2", " 3"이 붙습니다). 파일에는 `created:` 머리말(front matter)과 입력한 텍스트 전체가 들어갑니다. 기존 파일을 덮어쓰는 일은 없고, 없는 폴더(마운트되지 않은 드라이브, 옮긴 보관소)는 만들지 않으며 대신 메모가 명령어로 돌아옵니다. Obsidian 보관소(그 안이나 상위에 `.obsidian` 폴더가 있는 곳)에서는 알림에 "Saved to Obsidian"이 표시되고, 메뉴 막대 패널이 그 메모를 Obsidian에서 엽니다.
- **Notion**: "Create Integration…"(통합 만들기…)을 클릭해(New integration → Internal → 토큰 복사) 토큰을 붙여 넣고(키체인에 보관), Notion에서 페이지나 데이터베이스를 열어 ··· → Connections(연결) → 내 통합을 추가한 다음, 그 링크를 붙여 넣습니다. Test를 누르면 "✓ “Inbox” (database)"가 표시됩니다. 페이지에는 새 하위 페이지가, 데이터베이스에는 새 행이 생기며(첫 줄이 제목), 메모의 나머지는 본문이 되어 한 번의 요청으로 갑니다. 오프라인이거나 거부되면 나중에 보내려고 보관하지 않고, 메모가 명령어로 돌아옵니다. 보안 입력 중에는 `@note`가 Notion으로 보내지 않습니다.

알림에 메모가 어디로 갔는지 표시됩니다("Saved to Notion", "Saved to “Inbox”"). 줄바꿈이 있는 메모를 저장하기 전에 텍스트 필드를 떠나거나(다른 곳을 클릭, 앱 전환) ⇧⏎(입력한 그대로 삽입)를 누르면, 그 텍스트는 앱에 입력되지 않고(터미널에서는 각 줄이 명령어로 실행될 것이므로) 대신 클립보드에 들어갑니다("The note wasn't saved; its text is on the clipboard"). 한 줄짜리 메모는 입력한 그대로 삽입됩니다.

`@reminder`는 `tomorrow at 3pm`, `in 2 hours`, `in 3 days at 3pm`, `on the 15th`, `this weekend`, `in 1 month`, `next month`(그달 1일), `end of the year` 같은 시간을 해석합니다(중국어 시간 표현도 됩니다). 날짜와 시간은 떨어져 있어도 됩니다(`tomorrow call Bob at 5`). 한 주는 월요일에 시작합니다. 오전/오후가 없는 시간(`at 5`)은 다음에 오는 그 시간이며, 자정부터 오전 6시 사이가 되는 일은 없습니다. 오늘 이미 지난 시간은 내일이 되지만, 아직 진행 중인 하루의 시간대(`this afternoon`, `tonight`)는 오늘의 종일 일정이 됩니다. 올해 이미 지난 날짜는 내년이 됩니다. 반복되도록 쓴 것(`standup every Monday at 9`)은 다음 한 번만 추가됩니다. 그 단어들은 제목에 남고, 행에는 "once only"(한 번만)라고 표시됩니다. 확인용 행에는 해석한 시간이 표시됩니다(예: "tomorrow 3:00 PM", Mac의 12/24시간제 설정을 따름). 틀렸다면 Esc로 텍스트로 돌아갑니다. 시간이나 날짜가 없으면 시간 없이 추가됩니다("no date").

이 두 명령어 안에서는 `@stock` 같은 명령어가 실행되지 않습니다. 텍스트는 쓴 그대로 저장됩니다(그 안에서 `@`를 입력해도 명령어 목록이 열리지 않습니다). 처음에 macOS가 AllInOneIME가 Notes를 제어(`@note`)하거나 Reminders에 접근(`@reminder`)하도록 허용할지 묻습니다. 허용하세요. 허용하지 않았다면 System Settings → Privacy & Security → Automation(시스템 설정 → 개인정보 보호 및 보안 → 자동화)(Notes) 또는 → Reminders에서 AllInOneIME를 허용하세요. 저장에 실패하면(예: 권한 없음) 알림에 이유가 표시되고, 텍스트가 명령어로 돌아와 고쳐서 다시 보낼 수 있습니다. 먼저 무언가를 고쳐야 할 때(권한, 계정)는 텍스트가 클립보드에도 들어갑니다(System Settings로 가면 텍스트 필드의 포커스가 사라지기 때문입니다). 이미 다른 텍스트 필드로 옮겼거나 다른 내용을 입력하고 있다면, 대신 클립보드에 들어갑니다("Not saved; the text is on the clipboard.").

### 나만의 명령어

설정의 "Custom @ Commands"(사용자 지정 @ 명령어)에서 "Add Command…"(명령어 추가…)를 클릭하세요. 이름을 정하고 동작(AI 지시문, 프로그램, Terminal에서 실행하는 프로그램, 웹 페이지, 삽입할 텍스트)을 고르거나, 예제에서 시작합니다. 나만의 명령어는 내장 명령어 뒤에 나옵니다. 이름은 영문자만 쓸 수 있고 내장 명령어와 같을 수 없으며, 다음 문장부터 작동합니다. 명령어는 설정 파일(`~/.config/allinoneime/config.json`)의 `customCommands`에 저장되며, 직접 편집할 수도 있습니다:

```json
"customCommands": [
  { "name": "python", "type": "run", "argv": ["python3", "-c", "{input}"], "summary": "Run Python" },
  { "name": "bc", "type": "run", "argv": ["bc", "-l"], "stdin": "{input}\n" },
  { "name": "sh", "type": "terminal", "argv": ["zsh", "-c", "{input}"] },
  { "name": "reply", "type": "prompt", "prompt": "Write a short, polite reply to the user's message." },
  { "name": "google", "type": "link", "url": "https://www.google.com/search?q={input}" },
  { "name": "sig", "type": "snippet", "summary": "Email signature", "text": "Best,\nWei\n{cursor}" }
]
```

| `type` | 동작 |
|---|---|
| `prompt` | `prompt`를 지시문으로 삼아 AI에 보냅니다. 답은 후보에 나타나며 삽입하거나 복사(⌘C)할 수 있습니다 |
| `run` | `argv`를 백그라운드에서 실행합니다. 출력은 후보에 나타납니다(여러 줄은 출력된 그대로, 터미널에서는 한 줄로 삽입). 오류가 나면 마지막 줄이 표시됩니다 |
| `terminal` | `argv`를 새 Terminal 창에서 실행합니다. 아무것도 삽입되지 않습니다 |
| `link` | 텍스트를 웹 주소 `url`에 넣어 기본 브라우저에서 엽니다. 아무것도 삽입되지 않습니다 |
| `snippet` | `text`를 바로 삽입하며, 그 안의 자리 표시자(아래 참고)를 채웁니다. AI도 프로그램도 쓰지 않습니다 |

- `{input}`은 명령어 뒤에 쓴 내용으로 바뀌며, 항상 그것이 들어 있는 하나의 인수 안에 머뭅니다. 셸은 관여하지 않습니다. 셸이 필요하면 위의 `sh`(`zsh -c`)처럼 명시하세요.
- `stdin`: 프로그램의 표준 입력으로 보낼 내용이며, 여기서도 `{input}`이 바뀝니다.
- `link`의 `url`은 `https://`여야 하며, `{input}`은 한 번, `?` 또는 `#` 뒤에 있어야 합니다. 텍스트는 인코딩되며(공백은 `%20`, 줄바꿈은 `%0A`) 최대 4000자입니다.
- `run`과 `terminal`은 기본적으로 영문자를 입력합니다(`@open`처럼. 중국어 모드에서는 끝나면 중국어로 돌아옵니다). 전각 문장 부호는 ASCII로 바뀝니다. 입력한 그대로 두려면 `"ascii": false`를 설정하세요.
- 프로그램은 홈 폴더에서 로그인 셸의 PATH로 실행됩니다(그래서 Homebrew, pyenv, nvm으로 설치한 것도 찾습니다). `run`은 10초 후(`timeoutSeconds`) 또는 출력이 너무 많을 때 프로그램을 멈추며, Esc로 언제든 멈출 수 있습니다.
- `summary`는 명령어 목록에 표시되는 설명입니다(선택 사항).
- `argv`의 프로그램을 찾을 수 없으면(예: `python3` 없음) 그 명령어는 제공되지 않고 `@python …`이 텍스트로 입력됩니다. 프로그램을 설치하면 다음 텍스트 필드부터 명령어가 나타납니다.

`run`과 `terminal`은 Mac에서 코드를 실행합니다. 직접 작성했고 신뢰하는 명령어만 추가하세요. 이 명령어들도 실행 키를 눌렀을 때만 실행되며, 보안 입력 중에는 절대 실행되지 않습니다.

#### 스니펫: 자주 넣는 텍스트 (신규)

`snippet` 명령어(편집기에서는 "Insert text", 텍스트 삽입)는 서명, 주소, 회의 링크처럼 저장해 둔 텍스트를 삽입합니다. `@sig` ⏎를 누르면 바로 들어갑니다(Tab이나 Space는 이름만 완성합니다). `text`에는 자리 표시자를 넣을 수 있습니다:

| 자리 표시자 | 바뀌는 내용 |
|---|---|
| `{input}` | 이름 뒤에 쓴 내용 전체: `#{input}`이면 `@tag foo bar`가 `#foo bar`를 삽입합니다 |
| `{name?}` | 빈칸. 쓴 내용을 쉼표(`,` 또는 `，`)로 나누어 순서대로 채웁니다: `Dear {name?}, see you {day?}.`에 `@meet Bob, Friday`. 비어 있는 빈칸이 있으면 알림에 그 이름이 나오고 아무것도 삽입되지 않습니다 |
| `{clipboard}` | 클립보드의 텍스트(macOS가 먼저 물어볼 수 있음) |
| `{selection}` | `@`를 입력할 때 선택되어 있던 텍스트(선택 영역에 대한 다른 명령어처럼 그 텍스트를 대체합니다) |
| `{date}`, `{time}` | 오늘 날짜 `2026-10-17`, 시각 `14:05`. [날짜 패턴](https://unicode.org/reports/tr35/tr35-dates.html#Date_Field_Symbol_Table)을 쓴 `{date:EEEE, MMM d}`는 인터페이스 언어로 표시됩니다 |
| `{cursor}` | 삽입한 뒤 커서가 갈 위치(최대 한 번. 터미널에서는 안 됨) |

- `{{`는 `{`가 되고, 그것을 닫는 `}}`는 `}`가 됩니다(`{{input}}`은 `{input}`을 삽입). 그 밖의 `}}`나 `{…}`는 그대로 남으므로 스니펫에 JSON이나 코드를 넣어도 됩니다: `{"a":{"b":1}}`은 쓴 그대로 들어갑니다.
- `{input}`도 빈칸도 없으면, 이름 뒤에 쓴 내용은 스니펫 뒤에 공백 하나를 두고 들어갑니다.
- 다른 명령어의 텍스트 안에 `@sig`를 쓰면 그 스니펫이 들어갑니다: `@question summarize this @zoom`은 링크 자체를 보냅니다. 그 안에서는 `{clipboard}`, `{selection}`, 빈칸이 없는 스니펫만 작동하며, `{input}`이 있으면 한 단어나 따옴표로 묶은 구절을 받습니다: `@meet「Friday 3pm」`.
- 일반 텍스트만 되며(줄바꿈 유지) 최대 20,000자입니다. 스니펫은 이 Mac에만 있으므로 보안 입력 중에도, No AI로 설정한 앱에서도 작동합니다. 확장 번들도 스니펫을 담을 수 있습니다(`extension.json`의 `snippets`, [docs/extensions.md](../extensions.md) 참고).

### 스크립트 확장

나만의 @ 명령어를 프로그램으로 추가할 수 있습니다. 어떤 언어로 된 스크립트든(bash, Python, Node, Swift 등) 주석에 몇 줄의 메타데이터를 넣으면 됩니다. `~/.config/allinoneime/extensions`에 두거나, "Settings → Custom Commands → Script Extensions"(설정 → 사용자 지정 명령어 → 스크립트 확장)에서 추가한 폴더에 두세요. Raycast Script Commands는 그대로 작동하며, 이미 그것들이 들어 있는 폴더는 Spotlight로 찾아냅니다.

```bash
#!/bin/bash
# @allinoneime.schemaVersion 1
# @allinoneime.title Flights
# @allinoneime.argument1 {"type": "text", "placeholder": "from city"}
# @allinoneime.argument2 {"type": "text", "placeholder": "to city"}

echo "Flights from $1 to $2"
```

`flights.sh`는 `@flights`가 됩니다. 인수는 그 뒤에 쉼표로 구분해 씁니다. `@flights beijing, new york`은 `beijing`과 `new york`을 `$1`과 `$2`로 하여 실행합니다(그 이상의 쉼표는 마지막 인수에 남습니다). 필수 인수가 비어 있으면 실행하지 않고 무엇이 빠졌는지 알려 줍니다. 출력은 `output` 설정에 따라 사용됩니다:

| `output` | 동작 |
|---|---|
| `insert`(기본값) | 출력 전체와 각 줄을 삽입할 수 있습니다 |
| `show` | 출력되는 대로 패널에 표시됩니다(진행 상황). 아무것도 삽입되지 않습니다. 필드를 떠나면 백그라운드에서 계속됩니다(동시에 최대 4개) |
| `list` | Alfred의 Script Filter JSON 형식 목록으로, 입력할 때마다 다시 실행됩니다. 행을 고르면 삽입, 열기(웹 주소, 파일, 폴더. 실행될 수 있는 것은 절대 열지 않음), 복사, 또는 두 번째 단계 실행을 합니다 |
| `silent` | 마지막 줄을 커서 근처에 표시합니다. 아무것도 삽입되지 않습니다 |

명령어는 입력을 받지 않을 수도 있고(`input none`: 이름에서 ⏎를 누르면 실행), 백그라운드(`background`)에서 실행되다가 끝나면 알려 줄 수도 있으며(그동안 메뉴 막대 패널에 표시됨), 명령어 목록에서 이름 옆에 상태(`status`)를 표시하거나, 먼저 확인(`confirm`)을 받을 수도 있습니다. 명령어는 자기 폴더에서 로그인 셸의 PATH와 `ALLINONEIME_*` 변수(인터페이스 언어와 입력 언어, 입력 중인 앱, 텍스트)로 실행됩니다. **번들**은 명령어를 나열한 `extension.json`이 있는 폴더입니다. 번들의 명령어들은 코드와 환경설정을 공유하며, 환경설정은 설정에 표시됩니다(비밀번호는 키체인에 저장). 설정에는 모든 명령어가 스위치와 함께 나열되고, 제외된 스크립트도 그 이유와 함께 나열됩니다.

Raycast의 모드는 다음과 같이 대응됩니다: `fullOutput` → `show`, `compact`와 `silent` → `silent`, `refreshTime`이 있는 `inline` → 상태. 전체 프로토콜은 [docs/extensions.md](../extensions.md)에 있으며, [Core/Examples/extensions](../../Core/Examples/extensions)에는 종류별 예제가 하나씩 있습니다. 확장 기능은 Mac에서 코드를 실행합니다. 신뢰하는 것만 쓰세요. 확장 기능은 실행할 때만 동작하고(상태나 목록은 입력하는 동안), 보안 입력 중에는 절대 동작하지 않으며, 입력기가 종료되면 멈춥니다.

#### 확장 소스 (신규)

번들은 내 Git 저장소나 팀의 Git 저장소에서 가져와 그곳에서 계속 최신 상태로 유지할 수 있습니다. "Settings → Custom Commands → Extension Sources → **Add from Link…**"(설정 → 사용자 지정 명령어 → 확장 소스 → 링크로 추가…)에서 저장소 주소를 붙여 넣으세요(`git@github.com:you/my-extensions.git`, `ssh://…`, `https://…`. 필요하면 브랜치, 저장소 안의 번들 폴더, 고정할 태그나 커밋도 지정합니다). AllInOneIME는 **사용자 자신의 git과 SSH 설정**(키, 에이전트, ~/.ssh/config, 자격 증명 도우미)으로 클론하므로, 비공개 저장소도 Terminal에서처럼 동작합니다. 앱은 암호를 묻거나 저장하지 않습니다. 클론은 `~/Library/Application Support/AllInOneIME/Sources/`에 들어갑니다. 먼저 숨겨진 준비 폴더에 들어가며, 확장 폴더로 바로 들어가는 일은 없습니다. (https 주소에 사용자 이름, 암호, 토큰을 넣지 마세요. 그런 것은 git의 자격 증명 도우미가 보관합니다.)

- **먼저 검토합니다.** 무엇이든 불러오기 전에 번들, 각 명령어(이름, 제목, 설명, 출력), 명령어가 실행하는 프로그램, 번들의 환경설정, 커밋을 "This source isn't signed: it will run programs from <address>"(이 소스는 서명되지 않았습니다: 그 주소의 프로그램을 실행합니다)라는 경고 아래에서 보게 됩니다. **Enable**(활성화)을 눌러야만 추가되며, Cancel(취소)은 클론을 삭제합니다. 소스 검토는 한 번만 합니다.
- **업데이트 적용은 사용자가 결정합니다.** 하루에 한 번(그리고 입력기가 시작된 직후) 소스를 가져와(fetch) 새로운 것이 있는지 확인합니다. 설정에 "N updates"(업데이트 N개)와 그 커밋(제목, 작성자, 날짜), 페이지의 배지가 표시됩니다. **Update**(업데이트)를 클릭하기 전까지는 아무것도 바뀌지 않으며, Update는 fast-forward만 하고 훅은 실행하지 않습니다. 강제 푸시가 있으면 소스를 다시 검토해야 합니다. **Re-clone**(다시 클론)이 검토 화면을 보여 주고, Enable을 눌러야만 다시 쓰인 기록으로 바뀝니다(그때까지는 검토한 버전이 계속 동작합니다). 태그나 커밋에 고정한 소스는 확인하지 않습니다. 매일 확인은 소스마다 끌 수 있습니다(`autoCheck`).
- **오류**는 git의 메시지 그대로이며, "This uses your own git and SSH setup; check that `git ls-remote <url>` works in Terminal"(사용자 자신의 git과 SSH 설정을 사용합니다. Terminal에서 이 명령이 동작하는지 확인하세요)과, 설정했다면 그 아래에 사용자 자신의 안내 문구(설정 파일의 `authHint`)가 붙습니다.
- **Remove**(제거)는 클론을 휴지통으로 옮깁니다. 번들의 환경설정은 다음을 위해 남겨 둡니다.
- 터미널에서: `AllInOneIME --add-source <url> [--path …] [--branch …] [--pin …]`(검토 내용을 출력하고 활성화합니다. 강제 푸시 뒤에도 다시 실행), `--update-sources`(고정되지 않은 검토된 소스를 모두 fast-forward), `--list-extensions`(실행 파일은 `~/Library/Input Methods/AllInOneIME.app/Contents/MacOS/AllInOneIME`).
- 검토된 코드만 불러옵니다. 불러오기 목록에 있어도 이 Mac에서 검토하지 않은 소스 폴더(복사해 온 설정 파일 등)는 제외됩니다. git은 응답을 기다리지 않습니다. 터미널도 프롬프트도 없으므로, 알 수 없는 호스트 키나 암호 요청은 바로 실패합니다.

설정 파일에는 `extensionSources`로 저장됩니다. 저장소 구성은 [docs/extensions.md](../extensions.md#10-extension-sources)에 있습니다.

### 플러그인

플러그인은 모든 사람에게 필요하지는 않은 기능을 위한 기성 `@` 명령어입니다. 예를 들어 `@stock AAPL 600519 700`은 주가를 보여 줍니다. 설치하면 다른 명령어처럼 작동합니다. 설정의 "Plugins"(플러그인)에서 설치된 플러그인과 각 플러그인이 텍스트를 어디로 보내는지 확인하고, 제거할 수 있습니다. 플러그인은 별도 프로세스에서 실행되는 JavaScript로, 선언한 웹사이트(HTTPS)에만 접속할 수 있고 파일을 읽거나 다른 프로그램을 실행할 수 없습니다. 설정의 "Plugins"에 있는 "Browse Library…"(라이브러리 둘러보기…)로 [플러그인 라이브러리](https://github.com/MicroZ-LLC/AllInOneIME-plugins)에서 설치합니다. 설치 전에 플러그인이 접속하는 웹사이트를 보여 주며, 라이브러리의 색인은 서명되어 있고 모든 파일이 색인과 일치해야 합니다. 새 버전이 있으면 "Update"(업데이트) 버튼이 나타나며, 저절로 업데이트되는 것은 없습니다. 직접 만든 플러그인은 `~/.config/allinoneime/plugins/`("Open Plugins Folder", 플러그인 폴더 열기)에 둡니다. 이것은 로컬 플러그인이며 라이브러리가 덮어쓰지 않습니다. "Link"(링크) 플러그인은 코드를 실행하지 않습니다. 텍스트를 웹 주소에 넣어 브라우저에서 열 뿐입니다. 예를 들어 `@x nice weather today`는 텍스트가 채워진 X의 작성 화면을 엽니다. 게시할지는 페이지에서 여러분이 정합니다. 라이브러리에는 네 개가 있습니다(`@x`, `@threads`, `@bsky`, `@weibo`). `@xe`는 통화를 환산합니다: `@xe 100 USD CNY`, `@xe 1000 JPY EUR`. 결과는 환율 날짜와 함께 한 줄로 나옵니다(환율 제공: ExchangeRate-API). `@calculator`는 오프라인에서 작동하는 계산기입니다: `@calculator 23*17` → `391`(0.6.5 이전에는 내장 명령어 `@calculate`). `@calendar`는 날짜를 계산합니다: `@calendar +10` → "Tue, Oct 27 · in 10 days". 플러그인 작성법: [docs/plugins.md](../plugins.md).

무언가를 가져오는 명령어(플러그인과 프로그램)는 문장 안에서도 작동합니다: `@reply tell her @stock AAPL is up today`. 안쪽 명령어가 먼저 실행되어 그 출력이 자리를 대신하고, 바깥 명령어가 그 결과를 처리합니다. 인수는 명령어 뒤의 단어와, 그 바로 뒤에 오는 대문자 코드나 숫자입니다(`@stock AAPL TSLA`, `@stock 600519 700`). 소문자 단어가 나오면 끝납니다(`@stock SNDK is good to buy`는 SNDK를 조회합니다). 따옴표로 정확히 지정할 수 있습니다: `@stock "aapl tsla"`. `@calculator` 플러그인도 문장 안에서 작동합니다: `@reply the total is @calculator 23*17 dollars`. `@agent`와 터미널 명령어 안에서는 실행되지 않습니다. 그런 명령어는 쓴 그대로의 텍스트를 받습니다(그 안에서 `@`를 입력해도 명령어 목록이 열리지 않습니다).

### 실행 키

기본값은 ⏎입니다. 설정의 "Action key"(실행 키)에서 바꿀 수 있습니다(설정 파일의 `actionKey`): ⏎, "Tap ⌥"(⌥ 가볍게 누르기. 양쪽 모두 가능하며, 눌렀다가 바로 뗍니다. 오른쪽 ⌥를 누르고 있는 것은 여전히 말하기용입니다), ⌥Space, 또는 Space(단어를 고른 뒤 Space를 한 번 더. 영어 모드에서는 두 번). 실행 키가 무엇이든 @ 명령어는 ⏎로도 실행됩니다. ⌥Space가 이미 Alfred, Raycast 같은 앱의 단축키라면 그 앱이 먼저 받습니다.

### 결과를 타이핑해 넣기

Settings → General에서 "Type results out"(결과를 타이핑해 넣기)을 켜면(설정 파일의 `typeOut`), 명령어의 결과가 한 번에 들어가는 대신 사람이 타이핑하듯 한 글자씩 앱에 입력됩니다. 병음으로 고른 단어는 여전히 한 번에 들어갑니다. 슬라이더로 속도를 글자당 6초부터 초당 40글자까지 정하고(`typeOutRate`), "Speed up and slow down (like a person)"(사람처럼 빨라졌다 느려졌다)은 속도가 바뀌는 짧은 연타로 입력합니다(`typeOutVaries`). Esc는 그 자리에서 멈추고, 다른 키는 나머지를 한 번에 입력합니다.

"Make occasional typos and fix them"(가끔 오타를 내고 고치기, `typeOutMistakes`)은 훨씬 더 사람처럼 보이게 합니다. 가끔 올바른 키 옆의 키를 누르고 늦어도 세 글자 뒤에 알아채 지운 뒤 다시 입력하거나, 글자나 공백을 두 번 입력했다가 지우거나, 짧은 단어를 입력했다가 지우고 다시 입력합니다. 100글자에 몇 번 정도이며, 두 개가 붙어서 나오지 않고 줄 맨 앞에서는 절대 일어나지 않습니다. 코드, 웹 주소와 이메일 주소, 숫자 안에서는 오타가 틀린 글자나 숫자 하나뿐이고 바로 고칩니다(편집기가 짝을 맞추거나 들여쓰기하는 괄호, 따옴표, 공백은 절대 틀리지 않습니다). 틀린 글자는 사용하는 키보드 배열(QWERTY, AZERTY, QWERTZ…)에서 이웃한 키입니다. 중국어, 일본어, 한국어는 머뭇거리기만 하고(두 글자를 입력했다가 지우고 다시 입력), 틀린 글자는 절대 넣지 않습니다.

오타를 되돌릴 수 있는 필드(TextEdit과 메모 같은 Apple의 텍스트 뷰, 브라우저, 대부분의 편집기)에서는, 끝까지 입력하거나 다른 키를 눌러 나머지를 한 번에 입력하면 텍스트가 결과와 정확히 같습니다. 오타 도중에 Esc를 누르면(또는 필드를 떠나면) 먼저 오타를 빼므로, 필드에는 결과의 앞부분이 정확히 남습니다. 오타가 보이는 동안 커서가 움직이면(클릭 등) 오타는 원래 자리에서 빠지고, 나머지는 오타 없이 입력됩니다.

터미널이나 커서 위치를 입력기에 알려 주지 않는 앱에서는 절대 오타를 내지 않습니다. 매번 첫 오타는 단순한 것(틀린 글자 하나, 한 번에 수정)이며, 필드가 오타를 되돌릴 수 있음을 보여 줄 때까지 그렇습니다. 오타가 보이는 동안 입력기는 키를 누를 때마다 그 전에 필드에 자신이 입력한 내용이 그대로 있는지 확인합니다. 바꿀 위치를 무시하는 필드는 오타를 되돌릴 수 없어서, 그곳에는 첫 오타가 남고 텍스트는 한 글자 어긋난 채로 끝나며(Esc나 다른 키 뒤에도 마찬가지), 그 앱에서는 다시 오타를 내지 않습니다. Settings → General의 오타 스위치 아래에 그런 앱이 나열되며, "Forget apps where typos couldn't be fixed"(오타를 고치지 못한 앱 잊기)로 다시 시도하게 할 수 있습니다.

### 앱별 설정 (신규)

Settings → Apps에서 앱마다 자체 설정을 줄 수 있으며, 모두 선택 사항입니다. 앱이 정하지 않은 항목은 모든 앱에 공통인 설정을 따릅니다.

| 설정 | 예 | 설정 파일 |
| --- | --- | --- |
| 그 앱의 텍스트 필드가 시작하는 입력 언어 | Slack은 영어, WeChat은 병음 | `inputLanguage` |
| 그곳에서 `@improve`가 제공하는 다시 쓰기 스타일 | Mail은 격식 있고 정중하게, Slack은 편하게 | `rewriteStyles` |
| 결과를 타이핑해 넣을지 여부 | 채팅 앱에서는 켜고, Mail에서는 끄기 | `typeOut` |
| 이 앱에서는 AI 사용 안 함 | `@improve`, `@translate`, `@question`, `@agent`와 사용자의 프롬프트 명령어는 그곳에서 아무것도 보내지 않고 그렇다고 알립니다. 입력과 다른 명령어는 동작합니다 | `noAI` |
| 항상 입력하며 번역 | WeChat에서는 항상 입력하며 번역([입력하며 번역하기](#입력하며-번역하기) 참고) | `translateAlways` |

"Add App…"(앱 추가)은 최근 입력한 앱을 보여 주거나 /Applications에서 하나를 고릅니다. 입력 메뉴의 "This App: <이름>"에는 입력 중인 앱을 위한 빠른 스위치가 있습니다(No AI, Type Results Out, 시작 언어). 설정 파일에서는 번들 ID별로 `appProfiles` 아래에 있습니다: `"appProfiles": {"com.tinyspeck.slackmacgap": {"inputLanguage": "en", "rewriteStyles": ["casual"], "noAI": false}}`. 번들 ID는 대소문자를 구분하지 않고 맞춥니다(`com.apple.Mail`은 Mail의 `com.apple.mail`입니다). `@reportissue`는 무언가를 설정한 앱의 수만 세고, 이름은 절대 밝히지 않습니다.

- 시작 언어는 기본 입력 언어처럼 동작합니다. 텍스트 필드가 활성화될 때 그 언어로 시작하고, 이후 Shift로 바꾼 언어는 설정이 바뀔 때까지 그 앱의 필드에서 유지됩니다.
- No AI에서도 AI 명령어는 @ 목록에 남아 있습니다. 실행하면 알림이 나오고, 쓴 내용은 그대로 남습니다. 사용자의 터미널 명령어(`"type": "terminal"`)는 AI가 아니라 프로그램을 실행하므로 그곳에서도 계속 동작합니다.

### Settings → Assistant (신규)

설정 창은 두 부분으로 된 **Assistant** 페이지로 열립니다(0.6.5 이전에는 `@config`와 `@doctor` 명령어였습니다).

**한 문장으로 설정 바꾸기**("Change settings in a sentence"): 원하는 것을 쓰고("translate into Japanese and English", "candidates in a column", "use Claude") Preview(또는 ⌘⏎)를 누르세요. 변경마다 이전 → 이후로 표시되고, Apply로 적용하며, Undo로 10분 안에 되돌릴 수 있습니다(그사이 다시 바꾼 설정은 그대로 두고 알려 줍니다). iCloud 동기화도 켜고 끌 수 있습니다(무엇을 동기화할지는 Settings에서만 고릅니다). API 키, 직접 만든 명령어, 플러그인, 프로그램을 실행하는 것은 여기서 절대 바뀌지 않습니다. 키가 없는 제공자는 Settings → AI Provider에서 키 입력란을 열고, 제공자를 바꾼 뒤에는 Test Connection이 실행됩니다. 이 Mac에 Apple Intelligence가 있으면 그것으로, 없으면 선택한 제공자로 동작합니다.

**문제 점검하기**("Check for problems"): 입력기, AI 제공자, 권한, 보안 입력, 언어 팩, `config.json`, 확장 프로그램, 업데이트, iCloud 동기화(켜짐 여부, 마지막 동기화 시각, 마지막 오류, iCloud Drive를 쓸 수 없음, 이 Mac에서 쓰지 않은 iCloud의 설정), 최근 오류를 페이지가 열릴 때(그리고 창이 다시 앞으로 올 때) 이 Mac에서 점검하고, 문제를 먼저 보여 줍니다(모두 정상이면 "Everything looks good"). Check는 Test Connection과 함께 다시 점검하며, "What's wrong? (optional)"에 질문을 쓰면 AI가 가능한 원인을 설명합니다. 고칠 수 있는 행에는 Fix 버튼이 있습니다. 설정 변경은 위의 미리 보기에 Apply와 Undo와 함께 표시되고, 나머지는 바로 실행됩니다.

### iCloud로 동기화 (신규)

Settings → General → **Sync through iCloud**(iCloud로 동기화, 기본값은 끔)를 켜면 설정, Jargon 목록, 사용자 지정 명령어, 병음이 학습한 단어가 여러분 자신의 iCloud Drive를 통해 모든 Mac에서 똑같이 유지됩니다. 따로 로그인할 것도 없고, 저희 서버를 거치지도 않습니다. iCloud Drive가 필요하며(시스템 설정 → Apple 계정 → iCloud), 없으면 스위치가 꺼진 채로 그 이유를 알려 주고 그 패널을 여는 버튼을 보여 줍니다.

| 스위치 | 동기화하는 것 | 기본값 |
| --- | --- | --- |
| Settings(설정) | `config.json`의 설정: 언어, 다시 쓰기 스타일, 실행 키, 결과를 타이핑해 넣기, 앱별 설정, 민감한 정보 숨기기(스위치들), AI 제공업체와 모델(키는 절대 아님) … | 켬 |
| Jargon and custom commands(Jargon과 사용자 지정 명령어) | Jargon 목록과 `customCommands` | 켬 |
| Learned words(학습한 단어) | 병음이 사용자의 선택에서 학습한 것(Rime의 사용자 사전. librime의 사용자 사전 동기화를 씀. 사용자 정의 문구 같은 여러분 자신의 Rime 파일은 Mac에 남음) | 켬 |
| Hidden words(숨긴 단어) | AI에게 숨기는 단어("iCloud Drive is end-to-end encrypted only with Advanced Data Protection": iCloud Drive는 고급 데이터 보호를 켠 경우에만 종단 간 암호화됨) | 끔 |
| Recent questions(최근 질문) | `@question`의 최근 질문과 답("Remember recent questions"가 켜져 있는 동안) | 끔 |
| API keys and passwords(API 키와 암호) | API 키와 확장의 암호. 항상 종단 간 암호화되는 iCloud 키체인을 통해 동기화(시스템 설정 → Apple 계정 → iCloud에서 암호 및 키체인이 켜져 있어야 함) | 끔 |

`iCloud Drive/AllInOneIME/settings.json`에는 설정마다 언제, 어느 Mac(무작위 ID)에서 바뀌었는지가 기록되며, 설정별로 가장 최근의 변경이 이깁니다. 목록(사용자 지정 명령어, 다시 쓰기 스타일)은 하나의 값으로 취급하고, 앱별 설정은 앱 단위로 처리하며, 앱의 설정을 지우는 것도 변경입니다. 동기화는 입력기가 시작될 때, 무언가를 바꾸고 약 5초 뒤, iCloud가 다른 Mac의 변경을 가져올 때(그리고 5분마다), **Sync Now**(지금 동기화)를 누를 때 일어납니다. 학습한 단어는 입력기가 시작될 때, 30분마다(타이핑이 잠시 멈췄을 때), Sync Now를 누를 때 동기화됩니다. 상태 줄에는 "Last synced 2 min ago"(2분 전에 동기화함), "Waiting for iCloud…"(iCloud 기다리는 중…) 또는 오류가 표시됩니다.

- 켜면 그 Mac은 iCloud에 이미 있는 설정을 받아들이고, 자신의 설정으로는 아직 없는 것만 채웁니다. 모음은 대신 병합됩니다: 최근 질문(두 목록을 최신순으로, 같은 질문은 한 번만), 숨긴 단어, 사용자 지정 명령어(이름 기준. 겹치면 iCloud 쪽), Jargon 목록의 줄. 그 아래의 스위치를 처음 켤 때도 같습니다. 그 뒤 다른 Mac에서 뺀 것(지운 사용자 지정 명령어나 숨긴 단어)은 계속 빠져 있습니다. 다만 다음 경우에는 한 번 다시 나타나며, 다시 지우면 그대로 지워집니다: 처음 동기화를 켠 Mac에서 온 것인데 다른 Mac이 자기 목록을 병합하는 동안 그 Mac이 잠자기 상태였을 때, 아직 0.6.4인 Mac에서 지웠을 때, 아직 0.6.4인 Mac이 그것을 되살렸을 때. Mac이 동기화를 켜는 도중에 Settings에서 저장한 설정은 유지되어 다른 Mac으로 갑니다.
- 껐다가 다시 켜면: 그사이 iCloud에서 바뀐 것이 들어오고(이 Mac에서도 바꾼 것이라도), 이 Mac에서만 바뀐 것은 올라가며, 그사이 이 Mac에서 항목을 추가한 모음은 병합되고 버려지지 않습니다.
- 두 Mac의 최근 질문은 병합됩니다. 한 Mac에서 "Clear"를 누르면 다른 Mac에서도 그 전에 한 질문이 모두 지워집니다. "Remember recent questions"를 끄면 그 Mac에서만 지워지고, 다시 켜면 다른 Mac의 질문이 돌아옵니다. 최근 질문을 동기화하지 않는(또는 기억하지 않는) 동안 누른 Clear는 그 Mac에만 적용됩니다.
- Hidden words나 Recent questions를 꺼도 이미 동기화된 것은 iCloud에 남습니다. 각 스위치 아래의 **Remove from iCloud…**(iCloud에서 제거…, 먼저 확인)로 지울 수 있습니다. 다른 Mac은 자기 것을 유지하며, 아직 그것을 동기화하는 Mac은 자기 것을 다시 올립니다.
- 다른 Mac에서 온 값을 이 Mac에서 쓸 수 없으면(여기에 키가 없는 제공업체, 이 Mac에 없는 AWS 프로필, 범위를 벗어난 값) 적용하지 않으며, 상태 줄과 Settings → Assistant의 문제 점검이 어느 것인지 알려 줍니다.
- iCloud가 아직 내려받지 않은 파일은 기다리며, 비어 있는 것으로 취급하지 않습니다. 읽을 수 없는 `settings.json`은 `settings (unreadable …).json`으로 옆에 치워 두며, 덮어쓰지 않습니다. 더 새 버전이 저장한 설정은 그대로 둡니다.
- API 키와 암호는 iCloud Drive가 아니라 iCloud 키체인을 통해 동기화됩니다. (동기화가 켜진 상태에서) "API keys and passwords"를 켜면, 한 Mac에서 저장하거나 교체한 키가 다른 Mac에도 생깁니다. 기본값은 끔입니다. 동기화를 켜는 것만으로는 어떤 키도 옮겨지지 않으며, 이 행을 켜기 전까지는 아무것도 옮겨지지 않습니다. 켜면 이 Mac의 키가 로그인 키체인에서 iCloud 키체인으로 옮겨지고(그 뒤로는 업데이트 후에도 macOS가 그 키들에 대해 로그인 암호를 묻지 않습니다), 끄면 키를 로그인 키체인으로 다시 복사하고 다른 Mac을 위해 iCloud 키체인에도 남겨 둡니다. 동기화하지 않는 키는 전처럼 로그인 키체인에 남으며, AllInOneIME Cloud 로그인도 그렇습니다. 이 로그인은 절대 동기화되지 않으므로 Mac마다 직접 로그인합니다. 두 Mac의 키가 서로 다르면 마지막에 저장한 키가 이깁니다(모든 사본에 함께 보관되는 저장 시각 기준). 다른 쪽은 지워지지 않고 그 Mac의 로그인 키체인에 교체된 사본으로 보관되며("AllInOneIME replaced API key" 아래, 이름이 "(replaced)"로 끝남), 절대 사용되지 않습니다. iCloud 키체인으로 옮겨지는 키도 다른 Mac의 다른 키가 그 위에 덮일 때를 대비해 사본을 하나 남깁니다. 교체된 사본은 Mac마다 키당 하나이며, 나중 것이 이전 것을 대신합니다. 동기화 중에 키를 제거하면 키를 동기화하는 모든 Mac에서 제거되고(확인 창에 "all your Macs"라고 표시됨) 이 Mac의 교체된 사본도 제거됩니다. "API keys and passwords"를 끈 Mac이나 아직 0.6.4인 Mac은 자기 사본을 유지하며, 나중에 그 Mac에서 키 동기화를 켜면 그 키를 다시 올립니다(확인 창에서도 그렇게 알려 줌). 이 행을 끈 Mac에서 Remove…는 키와 그 교체된 사본을 그 Mac에서만 제거하며(확인 창에 "this Mac"이라고 표시됨), iCloud 키체인의 사본은 다른 Mac을 위해 남습니다. 옮길 때 macOS가 로그인 암호 없이는 AllInOneIME에게 읽기를 허락하지 않은 키는 다음에 쓰일 때까지 로그인 키체인에 남습니다. 그때 macOS가 묻고 허용하면, 다른 Mac에서 제거된 키라도 다시 사용됩니다. 각 키는 여전히 저장할 때 정한 호스트로만 전송됩니다. 키를 동기화하는 동안에는 `allinoneime-cli`와 0.6.5 이전 버전이 키체인에서 키를 보지 못합니다. 프로비저닝 프로파일이 없는 빌드(개발 빌드)는 키를 로그인 키체인에 두며 동기화할 수 없고, 그 행에 그렇게 표시됩니다.
- 절대 동기화하지 않는 것: AllInOneIME Cloud 로그인, AWS 자격 증명(`~/.aws`에 있음), 확장 소스(코드를 실행하므로 Mac마다 결정), 확장 폴더와 플러그인(Mac마다 다른 경로), 오타를 내지 않는 앱과 최근 앱, 창 상태, 동기화 스위치 자체(Mac마다 따로).
- 끄면 동기화를 멈추고, 이 Mac과 iCloud의 모든 것을 그대로 둡니다. **Remove from iCloud…**(먼저 확인)는 폴더를 휴지통으로 옮기고 이 Mac의 동기화를 끕니다.
- Settings → Assistant("sync through iCloud")로도 켜고 끌 수 있습니다. 숨긴 단어와 최근 질문은 Settings → General에서만 고릅니다. 설정 파일에서는 `iCloudSync`(`enabled`, `settings`, `jargon`, `learnedWords`, `hiddenWords`, `recentQuestions`, `keys`)입니다.

## 메뉴 막대 패널

<img src="../en/panel-swipe.png" width="520" alt="메뉴 막대 패널: 반투명 유리 질감에 메모, 미리 알림, Claude 작업이 카드로 표시됨. 왼쪽으로 쓸어 넘긴 행에 Remove 버튼이 보임">

메뉴 막대의 AllInOneIME 아이콘(테두리 없는 ∞와 커서 모양. 테두리가 있는 것은 입력 소스입니다)을 클릭하면 그 아래로 패널이 열립니다. 다른 곳을 클릭하면 닫힙니다:

- Notes(메모): `@note`로 저장한 메모 중 최신 5개. 클릭하면 저장된 곳에서 엽니다: Notes, Obsidian 또는 그 파일을 여는 앱, 또는 Notion 페이지. 없어진 파일은 더 이상 나열되지 않습니다.
- Reminders(미리 알림): Reminders의 AllInOneIME 목록에 있는 아직 완료하지 않은 미리 알림(`@reminder`가 이 목록에 추가합니다). 마감이 가까운 순으로 8개를 표시합니다. 동그라미를 클릭하면 완료 처리하고, 제목을 클릭하면 Reminders를 엽니다.
- Claude Tasks(Claude 작업): `@tasks`처럼 백그라운드 Claude 작업(`@agent`가 Claude Code에 넘긴 것)을 최대 30개, 한 번에 5개씩 표시합니다. 스크롤하면 더 볼 수 있고, 검색 상자에서 제목과 답장을 검색할 수도 있습니다. 진행 상황과 마지막 답장의 첫 줄도 함께 보입니다. 클릭하면 Terminal에서 열어 이어서 할 수 있습니다.

행(메모, 미리 알림, 작업)을 두 손가락으로 왼쪽으로 쓸어 넘기면 "Remove"(제거) 버튼이 나타나고, 끝까지 쓸어 넘기면 바로 제거됩니다. 마우스에서는 오른쪽 클릭하세요. 제거는 패널에서 빼는 것일 뿐입니다. 메모는 Notes에, 미리 알림은 Reminders에(완료되지 않은 채로), 작업은 Claude Code에 그대로 남습니다.

헤더에는 개수("2 reminders · 1 task running" 등. 응답을 기다리는 작업은 "1 waiting for you"처럼 따로 셉니다)와 새로 고침 버튼이 있습니다. 입력 중인 앱의 포커스를 절대 빼앗지 않습니다. 미리 알림을 완료하거나 새로 고침해도 그 앱이 앞에 그대로 있습니다. 키보드 입력을 받는 것은 클릭한 뒤의 Claude 작업 검색 상자뿐입니다. 아이콘은 기본적으로 표시되며, 설정의 "Menu Bar Panel"(메뉴 막대 패널)에서 끌 수 있습니다.

무엇을, 언제 읽는지:

- Notes: 목록은 패널 자체의 기록이며(패널이 닫혀 있을 때도 유지), Notes를 실행시키는 일은 없습니다. Notes가 이미 실행 중이고 AllInOneIME가 이전에 Notes 제어를 허용받은 경우에만, 패널이 바뀐 제목과 삭제된 메모를 확인합니다.
- Reminders: 패널이 열릴 때, 60초마다, 그리고 미리 알림이 바뀔 때 AllInOneIME 목록을 읽습니다. 패널이 스스로 macOS에 접근 권한을 묻게 하는 일은 없습니다. macOS가 아직 묻지 않았다면 "Allow Access to Reminders"(미리 알림 접근 허용)를 표시하며, 그 버튼만 권한을 요청합니다. 거부했다면 "Open System Settings"(시스템 설정 열기)를 표시합니다.
- Claude 작업: 패널은 열려 있는 동안에만 `claude agents`를 실행합니다. 열릴 때 한 번, 새로 고침할 때, `@agent`가 작업을 넘길 때, 그리고 아직 끝나지 않은 작업이 있는 동안 15초마다 실행하며, 모두 끝나면 더 이상 실행하지 않습니다. 마지막 답장은 이 Mac에 있는 Claude Code 대화 기록(`~/.claude/projects`)의 끝부분에서, 기록이 바뀌었을 때만 읽습니다.
- 패널이 닫혀 있는 동안에는 이 중 아무것도 실행되지 않습니다. `@note`가 저장한 메모의 기록만 남깁니다.

## 입력과 번역

설정에서:

- **Input languages**(입력 언어): 영어, 중국어(병음), 프랑스어, 한국어, 힌디어 중 한 개에서 다섯 개까지 +로 추가합니다(+는 항상 있으며, 다섯 개가 되면 흐리게 표시됨). 새로 설치하면 영어만으로 시작합니다. 새 텍스트 필드는 첫 번째 언어로 시작하며, Shift를 가볍게 누르면 순서대로 다음 언어로 바뀝니다. 언어가 하나면 Shift로 바뀌지 않습니다.
  - **프랑스어**는 전용 키보드 레이아웃으로 입력합니다. 카드에서 다른 것을 고르지 않으면 AZERTY입니다. 데드 키(^, ¨, `, ´, ~)도 그 레이아웃으로 조합됩니다.
  - **한국어**는 두벌식 자판으로 한글을 입력하며, 입력하는 대로 음절을 조합합니다(g k s → 한). Shift로 ㄲ ㄸ ㅃ ㅆ ㅉ와 ㅒ ㅖ를 입력합니다.
  - **힌디어**: 단어를 소리 나는 대로 라틴 문자로 입력하면 데바나가리가 됩니다(namaste → नमस्ते). 흔한 단어는 힌디어 표기대로 적힙니다. 그 밖에는 Space가 첫 번째 표기를, 숫자가 다른 표기를, ⏎가 입력한 그대로의 글자를 삽입하고, "."은 단다(।)를 삽입합니다.
  - 명령어 이름, `@open`의 텍스트, 코드(`@py`, `@js`)는 언어와 상관없이 영문자로 입력하며, 명령어가 끝나면 원래 언어로 돌아옵니다.
  - `@improve`는 한국어, 힌디어, 프랑스어 문장을 그 언어 그대로 다루고, `@translate`는 그것을 여러분의 언어로 번역합니다(프랑스어가 입력 언어 중 하나이면 프랑스어와 영어를 구분합니다).
- **Language packs**(언어 팩): 앱에는 영어(그리고 macOS의 레이아웃만 있으면 되는 프랑스어)가 들어 있습니다. 중국어, 한국어, 힌디어는 추가할 때 다운로드하는 팩입니다. 중국어(병음)를 추가하면 사전(약 34 MB, 압축 해제 시 125 MB)이 진행 막대와 함께 다운로드되며, 다 되면 재시작 없이 바로 병음을 쓸 수 있습니다. 한국어 팩(키 배열표와 자모로 음절을 만드는 방법)과 힌디어 팩(문자와 흔한 단어)은 몇 KB입니다. 팩은 데이터만 담으며(사전, 표, 스키마. 코드는 절대 없음), 서명된 색인에 올라 있고 사용 전에 SHA-256을 확인합니다. 플러그인과 같습니다. 각 언어의 카드에는 그 팩(버전, 크기, 출처)이 "Delete…"(삭제…)와 함께 표시되며, 언어를 제거하면 팩도 삭제할지 묻습니다. 0.6.1 이하에서 업데이트하면 중국어는 다운로드 없이 유지됩니다. 설치 프로그램이 이전 버전에 들어 있던 사전을 남겨 둡니다.
- **후보 배열**: 단어를 고를 때 병음과 힌디어 후보는 기본적으로 가로로 나란히 놓입니다(Horizontal). 시스템 기본 입력기처럼 ← →로 고르고 ↑↓(또는 - =)로 페이지를 넘깁니다. 위아래로 놓으려면(↑↓로 선택) Input 페이지의 입력 언어 아래에서 Vertical을 고르세요. @ 명령어 목록과 결과는 항상 세로입니다.
- **Fuzzy pinyin**(퍼지 병음, 중국어 입력 시): 구분하지 않는 소리를 어느 쪽으로 입력해도 됩니다(예: z ↔ zh, n ↔ l, in ↔ ing). "Input"(입력) 페이지의 입력 언어 막대에서 중국어(병음)를 고르고, "Fuzzy pinyin"을 켠 다음 쌍을 고르세요. 사전이 1~2초 안에 다시 배포됩니다. Rime 사용자 폴더에 `rime_ice.custom.yaml`을 쓰며, 그곳에 있는 여러분 자신의 파일을 덮어쓰지는 않습니다.
- **Translate (@translate)**(번역): 번역할 언어(스페인어, 프랑스어, 독일어, 일본어, 한국어, 중국어, 힌디어, 벵골어, 타밀어 및 기타 주요 인도 언어…)를 추가하고 드래그해 순서를 정합니다. 라틴 문자로 입력한 힌디어("aap kaise ho")는 데바나가리로 돌아옵니다. `@translate`는 이 순서대로 언어마다 한 줄씩 씁니다(언어가 하나면 세 가지 버전). 문장 원래 언어는 건너뜁니다. 새로 설치하면 Mac의 선호하는 언어 중 영어가 아닌 첫 번째 언어로 번역합니다. 영어만 있으면 `@translate`가 아직 번역할 언어가 없다고 알리고, 그 알림에서 ⏎를 누르면 이 페이지가 열리며 "Add…"(추가…)에 테두리가 표시됩니다(문장은 입력한 그대로 들어갑니다). 이때 입력하며 번역하기도 켜지지 않고, 언어를 추가할 곳을 알려 줍니다.
- **Keyboard layouts**(키보드 레이아웃): 프랑스어는 카드에서 고른 레이아웃으로 입력합니다(설정 파일의 `keyboardLayouts`). 다른 언어에서는 입력기 아래에서 macOS가 마지막으로 쓴 라틴 레이아웃(AZERTY, QWERTZ, 스페인어, US International…)을 유지하므로 평소처럼 입력할 수 있고, `@`도 레이아웃상 원래 자리에 있으며, 데드 키도 명령어의 텍스트 안에서 조합됩니다(⌥E 다음 E → é, ^ 다음 e → ê). 라틴 문자가 없는 레이아웃(러시아어, 힌디어 InScript)은 입력기 아래에서 쓸 수 없습니다. ⌃Space로 그 레이아웃으로 전환하거나, 텍스트를 명령어에 붙여 넣거나(⌃V) 받아쓰기로 입력하세요.
- `@improve`는 번역하지 않고 다듬고 다시 씁니다. `@translate @improve`를 함께 쓰면 한 번의 요청으로 번역과 다시 쓰기를 합니다. 설정에서 "@improve also translates"를 켜면 `@improve`가 항상 그렇게 합니다.

## 다시 쓰기 스타일

1–3번 줄 다음에 다시 쓰기가 나오며, **입력한 언어로** 작성됩니다. 영어는 영어로, 중국어는 중국어로 다시 씁니다. 설정에서 원하는 것을 고르세요:

- Polish(다듬기): 같은 어조로, 더 자연스럽게
- Concise(간결하게)
- Formal(격식 있게): 상사와 고객용
- Casual(편하게)
- Tactful(완곡하게)
- Jargon(업계 용어): 영어에서는 Amazon식 말투(bandwidth, circle back…), 중국어에서는 대형 IT 기업의 업계 용어. 나쁜 소식은 순화됩니다. 예: "this is a blocker bug"(이건 출시를 막는 버그다) → "Oh! Looks like your team has the bandwidth to fix this minor issue!"(오! 팀에 이 사소한 문제를 고칠 여력이 있어 보이네요!)

문장 부호만 바꾸거나 다른 줄과 같은 다시 쓰기는 표시되지 않습니다.

### Jargon 용어 목록 (나만의 용어)

Jargon에는 내장 용어 목록이 없습니다. 나만의 목록(예: 팀에서 쓰는 표현)을 준비하면, 모델이 그 용어를 우선해서 씁니다. 후보의 Jargon 줄에는 사용한 용어의 뜻이 함께 적힙니다.

목록은 한 줄에 용어 하나씩 쓰는 텍스트 파일이며, 필요하면 그 뒤에 "=", 콜론, Tab으로 구분해 뜻을 덧붙입니다(스프레드시트에서 두 열을 복사해 붙여 넣을 수 있습니다). `#`로 시작하는 줄은 주석입니다:

```
PRFAQ = a new-feature proposal: the press release and FAQ, written first
COE = an incident review
two-way door = a decision you can undo at any time
```

설정의 "Rewrite Styles → Jargon list"(다시 쓰기 스타일 → Jargon 목록)에서 "New"(새로 만들기)를 클릭하면 `~/.config/allinoneime/jargon.txt`에 빈 목록을 만들고 엽니다. 이미 목록 파일이 있다면 "Choose File…"(파일 선택…)을 클릭해 그 자리에서 그대로 쓸 수 있습니다(설정 파일의 `jargonFile`). 변경 사항은 바로 적용됩니다. 처음 150개 용어만 읽습니다. "Jargon"을 체크하면 목록이 각 요청과 함께 Bedrock으로 전송됩니다.

## 입력하며 번역하기

시험해 볼 수 있는 프로토타입입니다. Shift만 1초 동안 누르고 있으면 입력하며 번역하기(Translate as You Type)가 켜집니다(또는 꺼집니다). Shift를 가볍게 누르면 전처럼 입력 언어가 바뀝니다. 0.5초가 되면 커서 근처에 "Keep holding → Translate as You Type"(계속 누르면 → 입력하며 번역) 안내가 나오고, 1초가 되면 "Translate as You Type on: Chinese → English · hold Shift again to turn off"(번역할 언어를 표시)가 약 1.5초 동안 켜졌음을 알려 줍니다(끌 때는 "Keep holding → Translate as You Type off", 그다음 "Translate as You Type off"). 그 전에 손을 떼면 아무것도 바뀌지 않습니다. Shift를 글자(대문자)나 다른 키와 함께 누르면 켜지지 않습니다. 켜져 있는 동안 메뉴 막대 아이콘에 작은 점이 붙습니다. 이 기능을 위한 명령어는 없습니다.

켜져 있는 동안 입력하는 내용은 초안으로 모이고, 그 옆의 칩에 언어가 표시됩니다("ZH → EN". 중국어 인터페이스에서는 「中 → 英」). 번역할 언어는 칩에서 마지막으로 고른 언어이며(아래 참고), 모든 앱에서, 재시작한 뒤에도 유지됩니다. 하나를 고르기 전까지는 설정의 첫 번째 번역 언어로 번역합니다(고른 언어가 번역 언어에서 빠지면 다시 그 언어로 돌아갑니다). 입력 언어가 하나뿐이면 그 언어는 건너뜁니다(영어만 입력하고 번역 언어가 영어, 프랑스어 순이면 프랑스어). 켤 때 입력 중이던 언어는 영향을 주지 않습니다. ⏎를 누르면 초안을 번역해 고를 후보 없이 바로 넣습니다. 그동안 초안에 "Translating…"(번역 중…)이 표시되며, 메시지가 전송되지는 않습니다(⏎를 한 번 더 누르면 앱의 ⏎로 동작합니다). ⇧⏎는 초안을 입력한 그대로 넣습니다. 번역 중에 Esc를 누르면 번역을 멈추고 초안을 유지합니다(⌫도 번역을 멈추며, 초안에서처럼 글자 하나를 지웁니다). 실패하면(네트워크, 거부, 보안 입력) 초안이 한 줄짜리 알림과 함께 남고, ⏎로 다시 시도합니다. 번역할 언어로 입력한 텍스트(Shift를 가볍게 눌러 영어로 바꿈)는 입력한 그대로 들어갑니다.

켜져 있는 동안 입력 중인 줄 아래에 작은 칩 "ZH → EN"(중국어 인터페이스에서는 「中 → 英」)이 입력기 자체의 패널(후보 패널. 병음을 입력하는 동안에는 후보 위)에 표시되므로, 앱의 포커스를 빼앗지 않습니다. "ZH"를 클릭하면 Shift를 가볍게 누른 것처럼 입력 언어가 바뀝니다. "EN"을 클릭하면 번역 언어의 짧은 목록이 현재 언어에 체크된 채 나오고, 하나를 클릭하면 바로(칩과 다음 번역이 따라 바뀜) 그리고 그 뒤로도 그 언어로 번역합니다. 키는 전처럼 동작하며, 키를 누르면 목록이 닫힙니다.

- **어조**: 앱을 따릅니다. Settings → Apps에서 그 앱의 첫 번째 다시 쓰기 스타일, 없으면 채팅 앱(WeChat, Slack, Messages, Telegram, Discord, Teams)에서는 편하게, 메일 앱(Mail, Outlook, Spark)에서는 격식 있게, 그 밖에서는 자연스럽게 씁니다.
- **앱**: 다른 앱으로 전환하면(텍스트 필드가 없는 앱이라도) 알림 없이 꺼지고, 돌아와도 꺼진 채입니다. 단, Settings → Apps에서 그 앱에 "Always Translate as You Type"(항상 입력하며 번역)을 켰다면(프로필의 `translateAlways`) 그 앱에서는 저절로 켜집니다. No AI로 설정한 앱에서는 아무것도 하지 않습니다. 텍스트는 알림과 함께 입력한 그대로 들어가며, 보안 입력 중(암호 필드)에 입력하는 것도 마찬가지입니다.
- **개인정보 보호**: `@translate`와 같습니다. ⏎를 눌렀을 때만 여러분의 AI 제공업체로 보내며, 민감한 정보 숨기기가 켜져 있으면 그 정보를 숨긴 뒤 보냅니다.

## 음성 입력

<img src="../en/voice.png" width="340" alt="오른쪽 ⌥를 누른 채 말하기">

오른쪽 ⌥를 누른 채 말하고, 떼면 텍스트가 삽입됩니다. 입력 중인 언어(영어, 중국어, 프랑스어, 한국어, 힌디어)로 인식합니다. 먼저 명령어를 입력하고(예: `@improve `, `@question `) 말하면 텍스트가 명령어 뒤에 들어가고 ⏎로 실행합니다. 오른쪽 ⌥를 떼지 않고 ⏎를 눌러 말이 끝나자마자 실행할 수도 있습니다. 음성은 macOS 내장 음성 인식(SpeechAnalyzer)이 Mac에서 인식하며, 오디오는 업로드되지 않습니다. macOS 26 이상이 필요합니다.

처음에는:

- macOS가 AllInOneIME가 마이크를 사용하도록 허용할지 묻습니다. 설정에서 미리 "Allow Microphone"(마이크 허용)을 클릭해 둘 수도 있습니다.
- 이 Mac에 해당 언어의 음성 모델이 아직 없으면 한 번 자동으로 다운로드됩니다. 설정에서 다운로드할 수도 있습니다.

녹음은 키를 약 0.2초 누르고 있어야 시작되므로, 오른쪽 ⌥를 가볍게 누르기만 해서는 마이크가 켜지지 않습니다(실행 키가 "Tap ⌥"로 설정되어 있으면 가볍게 누르기가 동작을 실행합니다). 누르고 있는 동안 다른 키를 누르면(⌥ 단축키, ⌥←) 단축키로 간주되어 역시 녹음되지 않습니다. 녹음 중에 다른 키를 누르면 녹음이 취소됩니다.

## 설치

실행하려면 macOS 14 이상, 음성 입력에는 macOS 26 이상이 필요합니다. 설치 프로그램은 유니버설이라 Apple 실리콘과 Intel Mac 모두에서 작동합니다. 지금까지는 Apple 실리콘의 macOS 27에서만 테스트했습니다(Intel 빌드는 Rosetta에서 자체 테스트만 거쳤습니다).

1. [Releases](https://github.com/MicroZ-LLC/AllInOneIME/releases/latest)에서 `AllInOneIME-<version>.dmg`를 다운로드해(반드시 이곳에서만) 엽니다.
2. 그 안의 "Install AllInOneIME"을 더블 클릭하고 "Install"(설치)을 클릭합니다. 입력기는 `~/Library/Input Methods`에, "AllInOneIME Settings"는 `~/Applications`에 설치됩니다. 현재 사용자 전용이며 관리자 암호는 필요 없습니다.
3. 설치 프로그램은 Developer ID로 서명되고 Apple의 공증을 받았기 때문에, 처음 열 때 macOS는 인터넷에서 내려받은 앱을 열지 여부만 묻습니다. "열기"를 클릭하세요. (0.6.3 이전 버전은 공증을 받지 않아, 버전마다 시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기에서 한 번씩 허용해야 했습니다.)

그러면 AllInOneIME가 활성화되어 입력 소스에 추가됩니다. Ctrl+Space로 전환하세요(🌐 키는 System Settings → Keyboard(시스템 설정 → 키보드)에서 "Press 🌐 key to"가 "Change Input Source"로 설정된 경우에만 전환합니다). 설치 프로그램이 직접 추가하라고 하면, 이 Mac은 프로그램이 입력기를 활성화하도록 허용하지 않는 것이므로 한 번 직접 추가하세요: System Settings → Keyboard → Text Input → Input Sources → Edit… → +(왼쪽 아래) → English → AllInOneIME(설정의 "Input"에서 중국어를 추가하면 병음도 입력합니다).

Ctrl+Space로 AllInOneIME에 가지 않거나, 얼마 후 U.S.로 되돌아간다면 설치 프로그램을 다시 실행하세요. AllInOneIME를 입력 소스에 다시 추가합니다.

업데이트: Settings → About → Check for Updates(업데이트 확인). 새 버전이 있으면 About에 새로운 내용과 함께 표시되고(메뉴 막대 패널에도 한 줄 나타납니다), "Update to <version>"(<버전>으로 업데이트)을 누르면 내려받아 AllInOneIME의 릴리스 키로 서명된 업데이트 정보와 대조하고, 설치한 뒤 입력기를 다시 시작합니다. 설정, 언어 팩, 학습한 단어, 확장은 그대로 남고, 도중에 문제가 생기면 쓰던 버전으로 되돌립니다. AllInOneIME는 하루에 한 번 백그라운드에서 스스로 확인합니다(About의 "Check for updates automatically"로 끌 수 있습니다). 클릭하기 전에는 아무것도 설치하지 않습니다. 이 기능은 0.6.3부터 동작합니다. 더 오래된 버전을 업데이트하거나 원한다면, 제거하지 말고 새 버전의 디스크 이미지를 그 위에 설치하세요. 업그레이드하기 전에 [변경 기록](../../CHANGELOG.md)을 읽어 보세요. 버전별 변경 사항과 업그레이드 참고 사항이 있습니다.

이전 버전에서 0.6.3으로 업데이트하는 경우: 0.6.3은 Developer ID로 서명된 첫 버전이라, 키체인은 아직 이 앱을 키를 저장한 앱으로 알아보지 못합니다. 저장된 각 키(API 키, AllInOneIME Cloud 로그인, 확장의 암호)가 처음 필요할 때 macOS가 로그인 암호를 묻습니다. 암호를 입력하고 "Always Allow"(항상 허용)를 클릭하세요. 그 뒤로는 이후 업데이트 후에도 다시 묻지 않습니다. Amazon Bedrock의 키는 `~/.aws/credentials`에 있어서 영향을 받지 않습니다. 터미널에 붙여 넣기와 선택 영역 읽기에 쓰이는 손쉬운 사용(시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용)도 한 단계가 필요합니다. AllInOneIME가 목록에 있으면 제거한 뒤, 요청이 나올 때 다시 켜세요.

AIPinyin(AllInOneIME의 이전 이름)을 설치했었다면 그냥 설치하세요. 이전 AIPinyin.app과 그 설정 실행기는 제거되고, 입력 소스의 항목은 새 이름으로 바뀌므로 다시 추가할 필요가 없습니다. 설정, Jargon 목록, 학습한 단어는 처음 실행할 때 새 폴더(`~/.config/allinoneime` 등)로 옮겨지며, 이전 폴더는 각각 새 폴더를 가리키는 링크로 남습니다.

제거하려면 "Install AllInOneIME"을 열고 "Uninstall…"(제거…)을 클릭하세요. 설정과 학습한 단어는 유지됩니다.

### 소스에서 빌드하기

음성 입력이 macOS 26 SDK를 사용하므로 빌드하려면 Xcode 26 이상이 필요합니다.

```sh
git clone https://github.com/MicroZ-LLC/AllInOneIME.git
cd AllInOneIME
make install
```

`make install`은 librime과 rime-ice 사전을 다운로드해 검증하고, 빌드한 뒤 같은 위치에 설치하며, 같은 방식으로 입력 소스에 추가합니다. 설치되는 앱에는 중국어 사전이 없습니다(사전은 중국어 언어 팩입니다). 사전이 있던 설치에서는 그것을 팩으로 유지하고, 그렇지 않으면 `make install-pack`이 체크아웃의 사전에서 다운로드 없이 팩을 설치합니다. `make status`는 설치된 버전(`version:`)과 입력 소스에 있는지(`listed:`)를 보여 줍니다. 제거: `make uninstall`.

## AI 설정

번역과 다시 쓰기는 Settings → AI Provider에서 고른 AI 제공업체로 갑니다. 새로 설치하면 AllInOneIME Cloud로 시작합니다. 로그인하면 하루 20번의 무료 요청을 쓸 수 있습니다. Apple Intelligence를 지원하는 Mac에서는 대신 이 Mac에서, 계정 없이 실행할 수도 있습니다(아래 "이 Mac의 Apple Intelligence" 참고). 또는 비용을 여러분의 계정으로 내고 자신의 제공업체를 쓸 수 있습니다: AWS 계정의 Amazon Bedrock, Claude API, Gemini, OpenAI 호환 서비스(아래 "기타 AI 제공업체" 참고).

### Amazon Bedrock

1. AWS 콘솔에서 Bedrock을 활성화하고, 선택한 모델을 쓸 수 있는지 확인하세요. 기본값은 Claude Haiku 4.5입니다. Anthropic 모델을 처음 쓸 때는 사용 사례 양식을 한 번 작성합니다.
2. `bedrock:InvokeModelWithResponseStream`이 허용된 AWS 프로필을 쓰세요. `~/.aws/credentials`의 정적 키, 또는 임시 자격 증명을 받아 오는 프로필(`credential_process`, 역할, SSO. 아래 "AWS 프로필" 참고)입니다.
3. "AllInOneIME Settings"를 여세요. Spotlight나 응용 프로그램 폴더에서 찾거나, 메뉴 막대의 입력기 아이콘 → "Settings…"(설정…)에서 열 수 있습니다. 프로필, 리전, 모델을 고르고 "Test Connection"(연결 테스트)을 클릭하세요. 인터페이스는 English, 简体中文(중국어 간체), 繁體中文(중국어 번체), 日本語, 한국어, Deutsch, Français, Español, Português (Brasil)로 제공됩니다. 기본값(Settings → General → "Interface language"(인터페이스 언어)의 "Follow the system"(시스템 따르기))은 시스템의 선호하는 언어(시스템 설정 → 일반 → 언어 및 지역)를 따릅니다. 그중 앱에 있는 첫 번째 언어를 쓰며, 같은 언어의 지역 변형도 그 언어로(de-AT는 Deutsch, es-MX는 Español, fr-CA는 Français), zh-Hant, zh-TW, zh-HK는 중국어 번체로, 그 밖의 중국어는 간체로, 포르투갈의 포르투갈어도 브라질 포르투갈어로(영어보다 읽기 편하므로) 표시하고, 해당하는 언어가 없으면 영어로 표시합니다. 또는 거기서 언어를 직접 고를 수 있으며, 각 언어는 그 언어 자체로 표시됩니다. 설정 창, 후보 패널의 힌트, 입력 메뉴가 모두 이를 따릅니다. 설정 창은 Assistant 페이지로 열립니다. 말로 설정을 바꾸고, 문제를 점검해 항목마다 Fix로 고칠 수 있습니다([Settings → Assistant](#settings--assistant-신규) 참고).

#### AWS 프로필

AWS CLI가 아무것도 묻지 않고 쓸 수 있는 프로필이면 무엇이든 됩니다. `~/.aws/config`와 `~/.aws/credentials`(또는 셸의 `AWS_CONFIG_FILE`과 `AWS_SHARED_CREDENTIALS_FILE`이 가리키는 파일)에서 읽습니다. 한 프로필 안에서는 AWS CLI와 같은 순서로, 그 프로필에 있는 첫 번째 것을 씁니다(`role_arn`과 키가 둘 다 있는 프로필은 역할로 봅니다).

| 종류 | 프로필 내용 | 갱신 |
| --- | --- | --- |
| 역할 | `role_arn`과 `source_profile`(여기에는 어떤 종류든 올 수 있고 연쇄도 가능하며, 자기 자신을 가리키는 프로필은 자기 키를 씀) 또는 `credential_source = Environment`. `role_session_name`, `external_id`, `duration_seconds` | 만료 5분 전에 STS `AssumeRole`로 다시 받음(프로필의 `region`, 없으면 us-east-1) |
| SSO | `sso_account_id`, `sso_role_name`과 `sso_session` 및 그 `[sso-session …]` 섹션(또는 예전 방식의 `sso_start_url`, `sso_region`) | 만료 5분 전에 캐시된 로그인으로 다시 받음 |
| 정적 키 | `~/.aws/credentials`의 `aws_access_key_id`, `aws_secret_access_key`(와 `aws_session_token`) | 요청할 때마다 다시 읽음 |
| `credential_process` | `credential_process = /usr/local/bin/my-creds --profile dev`(셸 명령처럼 나누되 셸 없이 실행, 로그인 셸의 PATH로, 홈 폴더에서, 최대 60초) | `Expiration` 5분 전에 다시 실행. 없으면 AWS가 자격 증명을 거부할 때 |
| 정적 키 | `~/.aws/config`에 있는 같은 키 | 요청할 때마다 다시 읽음 |

프로필이 "default"이면(또는 고르지 않았으면) AWS CLI처럼 셸의 키가 먼저 쓰입니다: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`. 이름을 지정한 프로필은 이것들과 절대 섞이지 않습니다. 셸의 `AWS_REGION`(또는 `AWS_DEFAULT_REGION`)은 AWS CLI처럼 프로필의 `region`보다 우선하고, 설정의 Region 칸은 둘보다 우선합니다.

- **자동:** 만료되는 자격 증명은 메모리에만 두고(디스크에는 절대 쓰지 않음) 만료 5분 전에 다시 받아 옵니다. 10분이 채 안 남았으면 요청은 기존 자격 증명을 쓰면서 백그라운드에서 새것을 받아 오므로, 타이핑이 기다리지 않습니다. 동시에 들어온 요청은 한 번의 받아 오기를 기다립니다. Bedrock이 자격 증명이 만료되었다고 답하면(`ExpiredTokenException` …) 다시 받아 와서 요청을 한 번 더 보냅니다.
- **SSO:** AllInOneIME는 AWS CLI가 `~/.aws/sso/cache`에 보관하는 로그인을 쓰며(읽기만 함), 브라우저가 필요하기 때문에 대신 로그인할 수는 없습니다. 로그인이 끝나면 후보 패널에 "SSO sign-in expired: run aws sso login --profile X"(SSO 로그인 만료: aws sso login --profile X를 실행하세요)가 표시됩니다. Terminal에서 그 명령을 실행하면(설정에 "Copy Command"와 "Open in Terminal"이 있고, Settings → Assistant도 복사할 명령을 제공합니다) AllInOneIME가 새 로그인을 알아서 사용합니다.
- **지원하지 않음:** `mfa_serial`(입력기는 MFA 코드를 물어볼 수 없습니다. `credential_process`나 SSO를 쓰거나, CLI가 자격 증명을 캐시하게 하세요), `credential_source = Ec2InstanceMetadata`나 `EcsContainer`(Mac에는 없음), 그리고 web identity.
- **알려진 제한:** 로그인 셸에서 가져오는 것은 PATH와 AWS 파일 변수(`AWS_CONFIG_FILE`, `AWS_SHARED_CREDENTIALS_FILE`)뿐이며, `credential_process`에도 마찬가지입니다(나머지 환경 변수는 가져오지 않음). AllInOneIME는 `sso_session` 토큰을 갱신하지 않으므로(CLI의 갱신 토큰은 쓰지 않고, SSO 캐시는 읽기만 함), 캐시된 토큰이 만료되면 `aws sso login`을 실행하세요(AWS CLI를 쓸 때마다 갱신되기도 합니다).
- **Settings → AI Provider**는 모든 프로필을 종류와 함께 나열하고("dev — Role via base"), 선택한 프로필에 대해 자격 증명이 언제 만료되는지("Role via base: credentials expire at 15:30", "SSO (signed in until 18:00)") 또는 무엇을 해야 하는지 알려 줍니다. Test Connection은 체인 전체를 거쳐 새 자격 증명을 받아 오고, Settings → Assistant도 같은 내용을 보고합니다.
- 프로그램을 실행하고 AWS에 자격 증명을 요청하는 것(`sts.<region>.amazonaws.com`, `portal.sso.<region>.amazonaws.com`)은 요청이나 Test Connection에 필요할 때뿐입니다. 프로필 목록을 보여 줄 때도, Settings → Assistant를 위해서도 절대 하지 않습니다.

### 기타 AI 제공업체: Claude API, Gemini, OpenAI 호환 서비스

AWS가 없어도 됩니다. 설정의 "AI Provider"(AI 제공업체)에서 하나를 고르고, API 키를 붙여 넣은 뒤 "Save"(저장), 이어서 "Test Connection"을 클릭하세요.

| 제공업체 | 기본 모델 | API 키 |
|---|---|---|
| Claude API | `claude-haiku-5-5`(가장 빠르고 저렴함. Sonnet 5.5와 Opus 5.5는 더 신중하지만 느리고 비쌈) | [Claude Console](https://platform.claude.com) |
| Gemini API | `gemini-3.8-flash` | Google AI Studio |
| OpenAI 호환 | OpenAI의 `gpt-6-luna`(또는 `gpt-5.4-mini`). "Common Services…"(자주 쓰는 서비스…)에는 DeepSeek, Qwen, Kimi, Zhipu GLM, SiliconFlow, OpenRouter, 이 Mac의 Ollama가 있으며, 하나를 고르면 Base URL이 채워지므로 이어서 모델을 입력합니다 | 해당 서비스의 키. Base URL을 그 주소로 설정합니다(예: `https://api.deepseek.com/v1`, 이 Mac의 Ollama는 `http://localhost:11434/v1`) |

- API 키는 로그인 키체인에 보관되며, 설정 파일에는 절대 저장되지 않습니다. Sync through iCloud(iCloud로 동기화)에서 "API keys and passwords"를 켜면 대신 iCloud 키체인에 보관되며, 그곳의 키는 `allinoneime-cli`와 0.6.5 이전 버전이 보지 못합니다. 키체인에 키가 없으면 셸의 `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`(또는 `GOOGLE_API_KEY`), `OPENAI_API_KEY`를 사용합니다.
- API 키 행에는 키가 설정되어 있는지 표시됩니다: "✓ Saved · ends in a1b2"(저장됨 · 끝자리 a1b2: 마지막 4자를 키와 함께 저장해 두어, 표시할 때 키 자체를 읽지 않음)와 "Replace…"(교체), "Remove…"(제거), 셸에서 온 키라면 "✓ From $OPENAI_API_KEY"($OPENAI_API_KEY에서), 없으면 "No API key yet"(아직 API 키 없음)과 붙여 넣을 칸이 표시됩니다.
- "Thinking"(사고)은 기본값이 낮음입니다. 입력기는 문장마다 기다리므로, 사고가 적을수록 빠릅니다. 이를 지원하지 않는 모델에는 "Not set"(설정 안 함)을 고르세요.
- Claude Opus 5.5나 Sonnet 5.5를 고르면 요청에 Claude API의 거부 시 대체(`fallbacks: "default"`)가 포함됩니다. 안전 분류기가 거부하면 서버가 다른 모델로 다시 시도합니다.
- 설정 파일에서: `provider`(`"bedrock"`, `"anthropic"`, `"gemini"`, `"openai"`), 그리고 `anthropic`, `gemini`, `openai` 아래의 `model`, `baseURL`, `effort`, `temperature`(설정하지 않은 것은 기본값 사용).

### 이 Mac의 Apple Intelligence (macOS 26)

Apple Intelligence를 쓸 수 있는 Mac(Apple 실리콘, macOS 26 이상, 시스템 설정 → Apple Intelligence 및 Siri에서 켜짐)에서는 "AI Provider"에서 "Apple Intelligence (on this Mac)"를 고르세요. 키도 비용도 필요 없고, 입력한 내용이 Mac 밖으로 나가지 않습니다. macOS에 내장된 모델(Foundation Models 프레임워크)을 사용하며, 지시와 답의 형식은 다른 제공업체와 같지만 예시는 문장 자체의 언어로 쓰인 것만 넣습니다(작은 모델은 예시의 언어를 너무 쉽게 따라 합니다).

- 작은 모델입니다. 컨텍스트가 약 4K 토큰(macOS 27에서는 8K)이라 긴 단락은 너무 길 수 있고, 지원하는 언어도 더 적습니다(영어, 중국어, 일본어, 한국어, 프랑스어, 독일어, 스페인어와 몇 가지 더. 힌디어는 지원하지 않음). 두 경우 모두 그렇다고 알려 줍니다. 결과는 클라우드 모델에 못 미치며, 사실이나 코드에 대한 `@question` 답은 자주 틀립니다.
- 쓸 수 없는 곳에서는 이유(이 Mac에서 지원하지 않음, 꺼져 있음, 모델이 준비되지 않음)와 함께 회색으로 표시되고, 설정에서 시스템 설정 → Apple Intelligence 및 Siri로 연결됩니다. macOS 26 이전에는 목록에 나오지 않습니다.
- "Model Settings"의 "Output tokens", temperature, 시간 제한이 적용됩니다. 설정 파일에서는 `"provider": "apple"`입니다.

### 민감한 정보 숨기기 (신규)

Settings → AI Provider → Privacy → "Hide sensitive information before sending"(보내기 전에 민감한 정보 숨기기, 기본값은 끔): 요청이 AI로 가기 전에, 텍스트에서 찾은 내용을 Mac에서 `[EMAIL_1]` 같은 자리 표시자로 바꾸고(같은 값에는 같은 자리 표시자), 결과는 표시하거나 삽입하기 전에 실제 값을 되돌려 받습니다. 패널에는 "2 items hidden from the AI"(AI에게 2개 항목을 숨김)라고 표시됩니다. 종류마다 끌 수 있습니다.

## 개인정보 보호

- 타이핑(영어와 병음)과 `@calculator` 플러그인의 계산은 전적으로 로컬에서 이루어집니다. `@improve`, `@translate`, `@question`에서 실행 키를 눌렀을 때만 그 문장이 여러분이 고른 AI 제공업체(여러분의 Bedrock, 또는 키를 추가한 서비스)로 전송됩니다. "Jargon"을 체크하고 Jargon 목록을 설정했다면 목록도 함께 전송됩니다. 결과 다듬기(결과 뒤에 입력한 지시와 ⇧⏎)는 표시된 결과와 지시를 붙여 같은 요청을 다시 보냅니다. 후속 질문(⇧⏎)은 지금까지의 대화를 함께 보냅니다.
- Settings → Assistant는 Preview를 누르거나, 질문을 쓰고 Check를 누를 때만 모델에 텍스트를 보냅니다. 이 Mac에서 Apple Intelligence를 쓸 수 있으면 항상 그것으로(아무것도 Mac 밖으로 나가지 않음), 아니면 선택한 제공자로 보냅니다. 요청은 문장(그 안에 입력한 키는 먼저 제거됨)과 바꿀 수 있는 설정의 현재 값을 보냅니다. 키나 AI에게 숨기는 단어는 절대 보내지 않으며(개수만 보냄), AWS 프로필 이름은 문장이 AWS나 Bedrock에 관한 것일 때만 보냅니다. 질문은 가린 점검 결과와 함께 보냅니다. `~` 너머의 경로나 키는 없고, 로그 줄은 정해진 문구로 바뀝니다. 민감한 정보 숨기기는 둘 다에 적용됩니다. 점검만으로는 아무것도 보내지 않으며, Check는 Test Connection 요청도 보내는데, 그것도 제공자에게 시험할 키나 자격 증명이 있을 때뿐입니다.
- `@question` 대화를 다른 곳에서 이어 가면(마지막 회차 뒤의 ⌘1 …, 또는 ⌘⏎) 대화가 입력한 내용과 함께, 고른 서비스로 웹 주소나 클립보드를 통해 전송됩니다: 이 Mac의 코딩 에이전트(Claude Code, Gemini CLI, Kiro CLI 또는 직접 만든 것, 각자 자신의 계정과 서비스를 씀), claude.ai, chatgpt.com, gemini.google.com. 대화는 보이던 그대로 전송됩니다. AI 요청에서 숨겼던 값(아래 참고)도 그대로 들어 있는데, 그곳으로 보내기로 한 것이 사용자이기 때문입니다. 하나를 고르기 전까지는 아무 데로도 전송되지 않습니다. "Copy the conversation"은 클립보드에 넣기만 합니다.
- AllInOneIME Cloud를 쓰면 문장은 개발자의 서버를 거쳐 모델 제공업체로 갑니다(현재는 OpenRouter를 거침). 서버는 횟수만 보관하며, 텍스트는 절대 보관하지 않습니다. 로그인 시에는 이메일 주소만 보관합니다.
- 민감한 정보 숨기기(Settings → AI Provider → Privacy, 기본값은 끔): 어떤 요청이든 나가기 전에(`@improve`, `@translate`, `@question`, 사용자의 프롬프트 명령어와 프롬프트 플러그인, AllInOneIME Cloud를 포함한 모든 제공업체), 이메일 주소, 전화번호, 결제 카드 번호(Luhn 검사), API 키와 토큰(`sk-`, `sk-ant-`, `AKIA…`, `ghp_`, `xox…`, 긴 무작위 문자열), IP 주소, 직접 등록한 단어(코드명, 이름)를 Mac에서 `[EMAIL_1]`, `[PHONE_1]`, `[ITEM_1]` 같은 자리 표시자로 바꿉니다. 같은 값에는 같은 자리 표시자가 붙습니다. 모델의 결과는 표시하거나 삽입하기 전에 실제 값을 되돌려 받으며, 패널에는 "2 items hidden from the AI"라고 표시됩니다. 모델이 자리 표시자를 알아볼 수 없을 만큼 바꾼 결과는 쓰인 그대로 보여 주고 "⚠ placeholder changed"로 표시합니다. 숨긴 값이 들어 있는 Jargon 용어 목록 항목은 보내지 않습니다. 종류마다 끌 수 있습니다. 전각 형태(`zhang＠example.com`, `１３８…`)도 찾아내며, 값이나 구절이 줄바꿈으로 나뉘어 있어도 됩니다. 이메일, 번호, 키처럼 형식이 있는 값은 알아보지만, 이름이나 주소(직접 등록한 단어로 추가하세요), 다른 문자 체계의 비슷하게 생긴 글자는 알아보지 못합니다. 사용자의 AI 서비스로 가는 요청에 적용됩니다. `@agent`(함께 가져가는 Chrome 페이지 포함), 웹사이트에서 데이터를 가져오거나(`@stock`) 웹사이트를 여는(`@x`) 플러그인, 스크립트 확장은 입력한 그대로 텍스트를 보냅니다. 설정 파일에서는 `redaction`(`enabled`, `emails`, `phones`, `cards`, `keys`, `ips`, `customWords`)입니다.
- 음성은 오른쪽 ⌥를 누르고 있는 동안에만 녹음되며 Mac에서 인식됩니다. 인식된 텍스트는 위의 명령어에서 실행 키를 눌렀을 때만 전송됩니다.
- 입력기는 명령어 안에서 ⌃V나 ⌘V를 누를 때만 클립보드 텍스트를 한 번 읽습니다. 암호 관리자가 숨김으로 표시한 내용은 읽지 않습니다. 텍스트는 먼저 명령어 안에 표시되며, 역시 실행 키를 눌렀을 때만 전송됩니다. 최근 macOS 버전은 AllInOneIME가 클립보드를 읽도록 허용할지 묻습니다. 허용하세요. 매번 묻지 않게 하려면 System Settings → Privacy & Security에서 AllInOneIME의 붙여넣기 권한을 항상 허용으로 설정하세요.
- 암호 필드에서는 macOS가 자체 키보드(U.S. 또는 ABC)로 전환하고, 필드를 벗어나면 되돌립니다. 입력 중인 앱이 보안 입력을 유지하는 동안 AllInOneIME는 글자를 조합하지 않고 녹음도 할 수 없으며, 키는 입력한 그대로 들어갑니다. 또한 시스템이 보안 입력 상태인 동안(암호 필드, Terminal의 Secure Keyboard Entry(보안 키보드 입력) 등)에는 아무것도 AI로 전송되지 않습니다.
- `@note`와 `@reminder`는 AI로 가지 않습니다. AllInOneIME는 텍스트를 이 Mac의 Notes와 Reminders에만 넘기며, 미리 알림의 시간도 Mac에서 해석합니다(그 앱들이 다른 기기로 동기화하는지는 iCloud 같은 계정에 달려 있습니다). 그래서 보안 입력 중에도 작동합니다. 폴더로 저장하는 `@note`는 이 Mac에 파일을 씁니다(iCloud Drive나 Obsidian Sync 폴더처럼 그 폴더가 동기화된다면 파일도 동기화됩니다). Notion으로 저장하는 `@note`는 메모를 Notion(api.notion.com)에 통합의 토큰(키체인에 보관)으로 보내며, 그때만 보냅니다. 보안 입력 중에는 보내지 않습니다.
- `@reportissue`(와 "Report an Issue…")는 스스로 아무것도 보내지 않습니다. 브라우저에서 GitHub의 새 issue 페이지를 열고, 입력한 제목과 위에 나열한 버전, 언어, 제공업체 종류, 개수를 붙이며, 이 내용은 먼저 후보 패널에 표시됩니다. 거기서 Submit을 클릭하지 않으면 GitHub에는 아무것도 전달되지 않습니다.
- `@open`은 이 Mac에서만 검색합니다. 그것으로 연 항목(최근 200개)을 입력기 자체의 환경설정(config.json이 아님)에 기억해 두었다가 먼저 나열합니다.
- Settings → Apps의 "Add App…"을 위해 입력기는 최근 입력한 앱 12개의 번들 ID를 자체 환경설정에 보관합니다. 그 앱에 관한 다른 정보는 보관하지 않습니다.
- `@question`은 최근 질문 5개를 답과 질문한 시각과 함께 이 Mac에만(iCloud로 동기화하기로 한 경우는 예외. 위 참고) `~/Library/Application Support/AllInOneIME/recent-questions.json`(사용자 계정만 읽을 수 있음)에 기억해 두고 `@question` 아래에 보여 줍니다. 저장된 답은 온라인에 접속하지 않고 거기서 표시됩니다. 보안 입력 중에는 아무것도 보관하지 않으며, 선택한 텍스트에 대한 질문은 아예 보관하지 않습니다(그 답은 선택 영역에 관한 것이라, 보관하면 선택 영역이 디스크에 남게 됩니다). Settings → General에서 "Remember recent questions"를 끄면 질문도 삭제되고, Settings → Assistant로 끄면(설정 파일의 `rememberQuestions`) 질문이 남아 있어 정확히 되돌릴 수 있습니다. "Clear"는 질문을 삭제합니다.
- 메모를 나열하기 위해, 메뉴 막대 패널은 `@note`로 저장한 최근 30개 메모의 ID(Notes의 메모 ID, 파일의 경로, 또는 Notion 페이지의 주소)와 첫 줄(최대 80자)을 입력기 자체의 환경설정에 보관합니다. 패널이 꺼져 있을 때도 마찬가지입니다. 패널을 열 때 Notion에 무언가를 요청하는 일은 없습니다.
- `@py`와 `@js`는 실행 키를 눌렀을 때만, 그리고 여러분이 직접 입력하거나 붙여 넣은 코드만 실행합니다. AI의 답이나 다른 명령어의 출력은 절대 코드로 실행되지 않습니다. `@py`는 Mac의 `python3`를 사용하므로 Terminal에서처럼 파일을 읽고 쓰고 온라인에 접속할 수 있습니다. `@js`는 별도 프로세스에서 실행되어 파일을 읽거나, 네트워크에 접근하거나, 다른 프로그램을 실행할 수 없습니다. 둘 다 보안 입력 중에는 실행되지 않습니다.
- 업데이트 확인: 하루에 한 번("Check for updates automatically"가 꺼져 있지 않다면) AllInOneIME는 https://allinoneime.com/update.json과 그 서명을 내려받습니다. 요청에는 식별자도, 입력한 내용도 들어 있지 않습니다. 업데이트는 Update를 클릭했을 때만 GitHub 릴리스에서 내려받습니다.
- 확장 소스: git은 사용자가 추가한 소스에 대해서만, 사용자의 Mac에서 사용자 권한으로 실행됩니다. 스스로 확인하는 소스에 대해 하루 한 번 가져오기(fetch)(고정한 소스는 없음), 그리고 Check Now, Update, Re-clone을 클릭할 때입니다. 통신하는 상대는 저장소의 호스트뿐이며, 사용자 자신의 git과 SSH 설정으로 로그인합니다. 입력한 내용은 함께 가지 않습니다.
- iCloud로 동기화(기본값은 끔): 여러분 자신의 iCloud Drive, `~/Library/Mobile Documents/com~apple~CloudDocs/AllInOneIME/`에만 저장하며, Apple이 이것을 다른 Mac으로 동기화합니다. 개발자의 서버로는 아무것도 가지 않습니다. 저장되는 것: `settings.json`(동기화되는 설정과 각각이 바뀐 시각, Mac마다의 무작위 ID. 사용자 지정 명령어도 들어가며, 프로그램을 실행하는 명령어도 포함되지만 여전히 고를 때만 실행됩니다), `jargon.txt`(Jargon 목록), `rime/`(각 Mac에서 병음이 학습한 것의 스냅숏. Rime 폴더의 다른 것은 없으며, 사용자 정의 문구와 Rime 설정은 Mac에 남습니다), 그리고 켰을 때만 AI에게 숨기는 단어(`settings.json` 안)와 `questions.json`(최근 질문과 답, 사용자 계정만 읽을 수 있음). 이 둘은 꺼도 제거하기 전까지 iCloud에 남습니다(각 스위치 아래의 "Remove from iCloud…"). 절대 저장하지 않는 것: API 키, 토큰, 암호, 확장 소스, 확장 폴더와 플러그인, 오타를 내지 않는 앱, 최근 앱, 창 상태, 동기화 스위치. iCloud Drive는 고급 데이터 보호를 켠 경우에만 종단 간 암호화됩니다. 이 Mac이 무엇을 동기화했는지에 대한 자체 기록은 `~/Library/Application Support/AllInOneIME/iCloudSync/state.json`에 있습니다.
- 로그에는 입력 내용이 기록되지 않습니다. macOS는 모든 타사 입력기에 대해 "The developer can access anything you type with this input source"(개발자가 이 입력 소스로 입력하는 모든 내용에 접근할 수 있습니다)라고 경고하는데, 이는 시스템의 일반적인 경고입니다.

## 개발

```sh
make test         # unit tests, plus tests that run the real Rime engine (and make strings-check)
make strings      # adds new interface text to Resources/Localizable.xcstrings, marks what's unused stale
make pack         # the Chinese language pack: build/packs/zh-pinyin-<version>.tar.xz, its sha256, its packs.json entry
make packs        # all the language packs: Chinese, and Korean and Hindi from Core/LanguagePacks/ (ko-hangul, hi-phonetic)
make selftest     # drives the input method through a simulated text field: real Bedrock calls, plus on-device recognition tested with synthesized speech
make realtest     # types into a real app's text field (needs the screen unlocked; takes over the foreground for about 1 minute)
make screenshots  # regenerates the screenshots in docs/
make cli && .build/release/allinoneime-cli --styles concise,jargon "this is a blocker bug your team need fix it asap"   # try polishing and rewrites in the terminal
make icon         # regenerates the app icon and the menu bar icon from Resources/AppIcon.png
make dmg          # the release installer, build/AllInOneIME-<version>.dmg (universal; needs the Developer ID certificate it's signed with and DIST_PROFILE, the provisioning profile; optionally notarized), and the in-app update, build/AllInOneIME-<version>-update.zip
make app PROFILE=<profile> SIGN_IDENTITY=<a certificate it lists>   # a build with the keychain entitlements: it can sync keys through iCloud Keychain
make update-test  # the in-app updater end to end: a temporary install, a test server on 127.0.0.1, a test key (never the installed app)
```

`make selftest`와 `make realtest`는 사용자의 설정에 영향을 받지 않습니다. 자체 테스트는 자체 설정 파일을 씁니다(Amazon Bedrock에 AWS 프로필과 리전은 사용자의 설정에서 가져오고, 나머지는 모두 기본값). 실제 앱 테스트는 실행하는 동안 제공업체를 Bedrock으로 바꾸고 끝나면 사용자의 것으로 되돌립니다. 그 순간 확인할 수 없는 것은 실패가 아니라 건너뜀으로 처리됩니다. 그 프로필의 자격 증명이 없을 때의 Bedrock 실시간 확인, 그리고 보안 입력이 켜져 있을 때(화면 잠금, 암호 입력란) 입력하는 모든 것입니다. 마지막 줄은 통과, 실패, 건너뛴 확인 수를 셉니다. 실패만 실행을 실패로 만들며, 건너뛴 것이 있는 실행은 INCOMPLETE로 끝나고, 타이핑하는 것이 하나도 실행되지 않았으면 SKIPPED로 끝납니다(BLOCKED: 실제 앱 테스트가 잠긴 화면에서 시작됨). PASSED로 끝나는 일은 없습니다.

인터페이스 텍스트는 `tr("中文", "English")`로 씁니다. 중국어 간체와 영어는 코드에서, 다른 언어는 String Catalog에서 가져옵니다. 코어의 텍스트는 `Core/Resources/Localizable.xcstrings`, 앱 자체의 텍스트는 `Resources/Localizable.xcstrings`에 있으며(Makefile이 Xcode의 `xcstringstool`로 병합해 각 앱에 컴파일), 키는 영어 텍스트이고 보간마다 `%@`를 씁니다. 텍스트를 추가하거나 바꾼 뒤에는 `make strings`를 실행하세요(그때까지 `make test`가 실패합니다. `*SelfTest.swift`에 있는 자체 테스트의 텍스트는 번역 대상이 아닙니다). 하나의 영어 텍스트가 두 가지 뜻으로 쓰이면(`make strings`가 알려 주고, `make strings-check`는 실패합니다) 그중 하나에, 어디서 어떻게 쓰이는지를 나타내는 짧은 점 구분 이름으로 별도의 키를 주세요: `tr("删除", "Remove", key: "remove.delete")`. 그 영어는 카탈로그에 있는 그 키의 영어 값입니다. 언어를 추가하는 것은 카탈로그에 그 언어의 열을 추가하는 것입니다. 검토된 번역은 언어마다 JSON 파일 하나(`"core\t<key>"` 또는 `"app\t<key>"` → 번역)로, `Scripts/import-translations.py <folder>`로 넣습니다. 이 스크립트는 영어를 절대 건드리지 않으며, 자리 표시자가 키의 것과 다른 번역은 거부합니다. 코어 자체의 텍스트도 인터페이스 언어의 코드로 같은 방식으로 찾습니다(`InterfaceText.lookup`. 각 앱이 설정하며, macOS에서는 `.lproj` 번들, 그 밖에서는 `StringCatalog`가 카탈로그의 표를 읽습니다).

코드 구성: 루트는 macOS 앱이고, `Core/`는 모든 플랫폼이 공유하는 코어로 그 자체가 하나의 Swift 패키지입니다(macOS, Linux, Windows에서 따로 빌드하고 테스트합니다). `Windows/`는 Windows 앱의 시작입니다.

- `Core/Sources/AllInOneIMECore`: Bedrock 클라이언트, SigV4, 프롬프트, 2단계 입력 상태 머신(@ 명령어와 음성 제스처 포함). AppKit 의존성 없음
- `Core/Sources/AllInOneIMEText`: 인터페이스 텍스트와 그 언어(`UIString`, `InterfaceText`, `InterfaceLanguage`, 그리고 `.lproj` 번들이 없는 곳에서 카탈로그를 읽는 `StringCatalog`). 설정 실행기는 이 모듈만 링크합니다(`AllInOneIMECore`가 이것을 다시 내보냄)
- `Core/Sources/AllInOneIMEQuickJS`: QuickJS-ng(C 소스는 `Core/Sources/CQuickJS`에 있음). JavaScriptCore가 없는 곳(Windows, Linux, Android)에서 플러그인과 `@js`의 JavaScript를 실행
- `Core/Sources/AllInOneIMERime`: librime 래퍼
- `Core/Sources/AllInOneIMECLI`: 명령줄 도구 `allinoneime-cli`(`make cli`). 각 플랫폼 자체의 `main`이 실행
- `Sources/AllInOneIMEMac`: Mac에만 있는 것(키 배열, 코드 서명, Spotlight, AppleScript, 업데이트 설치)과 `Platform.mac`
- `Sources/AllInOneIME`: InputMethodKit 입력기, 후보 패널, 설정 창, 음성 인식
- `Sources/AllInOneIMESettings`: "AllInOneIME Settings" 실행기
- `Sources/AllInOneIMEInstaller`: 디스크 이미지의 "Install AllInOneIME". 설치, 업데이트, 제거를 담당

언어 팩은 플러그인과 별도로 자체 라이브러리가 있습니다. 저장소 [MicroZ-LLC/AllInOneIME-languages](https://github.com/MicroZ-LLC/AllInOneIME-languages)이며, https://languages.allinoneime.com/ 에서 제공되고 자체 키로 서명됩니다. `make pack`이 아카이브를 빌드하면 그곳에 릴리스 애셋으로 게시되며(릴리스 `zh-pinyin-<version>`, `ko-hangul-<version>`, `hi-phonetic-<version>`), `swift Scripts/build-packs-index.swift <languages repo> build/packs/*.tar.xz.json`이 그곳에 `packs.json`을 쓰고, 키체인에 있는 언어 팩 키(`allinoneime-languages-signing`)로 서명해 `packs.json.sig`를 만듭니다. 앱은 https://languages.allinoneime.com/packs.json 을 읽고 서명을 확인한 다음, 아카이브의 크기와 SHA-256을 확인합니다. 로컬 서버에서 팩을 시험하려면: `--test-key`로 테스트 키로 서명하고, `AllInOneIME --install-pack zh-pinyin --library http://127.0.0.1:8765/ --key <its public key> --packs-dir <folder>`를 실행합니다.

버전 출시하기 (앱 내 업데이트는 릴리스 전용 키로 서명된 https://allinoneime.com/update.json을 읽습니다):

1. 버전을 올리고(`AppVersion.swift`와 Info.plist 세 개. `AppVersionTests`가 서로 일치하는지 확인합니다) 변경 기록을 갱신합니다.
2. `make dmg NOTARY_PROFILE=<profile>`: `build/AllInOneIME-<version>.dmg`와 그 `.sha256`, 그리고 `build/AllInOneIME-<version>-update.zip`(디스크 이미지의 설치 프로그램에 든 것과 같은 두 앱)을 만듭니다. 앱과 이미지는 키체인에 있는 Developer ID Application 인증서로 서명되고, 이미지는 그 `xcrun notarytool` 키체인 프로필로 공증된 뒤 스테이플(staple)됩니다. 입력기에는 키체인 인타이틀먼트(entitlement)를 부여하는 Developer ID 프로비저닝 프로파일(`Resources/Signing/AllInOneIME-DeveloperID.provisionprofile`, `DIST_PROFILE`)이 들어갑니다. 프로파일에 서명 인증서가 없거나, 모든 기기를 프로비저닝하지 않거나, 남은 기간이 30일 미만이면(`Scripts/profile-entitlements.sh`), 또는 서명에 키체인 인타이틀먼트가 빠져 있으면 빌드가 멈춥니다. 빌드는 서명된 입력기를 한 번 실행해 봅니다(프로파일이 맞지 않으면 macOS가 입력기를 종료시킵니다). `DIST_PROFILE`이 비어 있어도 멈춥니다. 인타이틀먼트가 없는 릴리스는 iCloud 키체인으로 옮겨진 키를 모두 보지 못하게 되기 때문입니다. 이 프로파일에는 Developer ID G1 인증서 두 개만 들어 있으므로, 다른 인증서(G2)로 서명하기 전에 개발자 포털에서 그 인증서가 들어간 새 프로파일을 만들어(직접 만들어야 합니다. 이 App ID의 서명은 Xcode에 맡기지 않습니다) 커밋하세요.
3. 두 파일을 GitHub 릴리스 `v<version>`에 올리고 게시합니다.
4. `make update-manifest UPDATE_SUMMARY_EN="…" UPDATE_SUMMARY_ZH="…"`(각각 한두 문장): `site/public/update.json`(앱에서 읽은 버전, 빌드, 최소 macOS, 파일의 주소, 크기, SHA-256, 릴리스 노트 주소와 요약)을 쓰고, 로그인 키체인의 키(`allinoneime-releases-signing`. macOS가 접근 허용을 물을 수 있습니다)로 서명해 `update.json.sig`를 만듭니다. 둘 다 커밋합니다.
5. 릴리스 파일을 내려받을 수 있게 된 뒤에만 사이트를 배포합니다(`cd site && npx wrangler@4 deploy`). 앱은 하루에 한 번 확인하며, `AllInOneIME --check-update`로 앱이 보는 내용을 확인할 수 있습니다.

앱은 매니페스트를 읽기 전에 내장된 공개 키로 서명을 확인하고, 더 새롭지 않은 버전은 절대 설치하지 않으며, https로 allinoneime.com 또는 이 저장소의 GitHub 릴리스 파일에서만 내려받고, 아카이브의 크기와 SHA-256이 매니페스트와 일치하고 두 앱의 번들 ID, 버전, 코드 서명이 확인되며 새 입력기가 시작될 때에만 설치합니다. 그런 다음 입력기는 자신의 실행 파일을 도우미로 넘겨(`--apply-update`) 작업을 맡깁니다. 도우미는 입력기가 종료되기를 기다렸다가 설치 프로그램과 같은 방식으로 앱을 바꾸고(이전 앱은 옆으로 옮겨 두고, 실패하면 되돌림) 새 앱을 등록합니다. 로컬 서버로 시험하려면: `make update-test`, 또는 `Scripts/build-update-manifest.swift`의 `--test-key`와 `AllInOneIME --install-update --manifest-url http://127.0.0.1:<port>/update.json --key <its public key> --target-dir <folder>`를 사용합니다.

번들 ID는 여전히 `com.aipinyin.inputmethod.AIPinyin`입니다. macOS가 이것으로 추가된 입력 소스와 마이크 권한을 기억하므로, 바꾸면 입력기를 다시 추가하고 권한을 다시 허용해야 합니다.
